# Skill 质量标准与验收规范

> 定义专业级 Skill 的质量标准，作为优化和验收的依据。

---

## 🎯 质量等级定义

### S 级（专业级）- 总分 95-100

**特征**：
- 可发布到官方市场
- 零已知 Bug
- 文档极其完善
- 社区活跃
- 持续维护

**验收标准**：
- audit 总分 ≥95
- 测试覆盖率 ≥90%
- 文档数量 ≥20
- 所有 P0/P1/P2 项完成
- 跨平台测试通过

---

### A 级（优秀）- 总分 85-94

**特征**：
- 可公开分享
- 极少 Bug
- 文档完善
- 有用户反馈机制

**验收标准**：
- audit 总分 ≥85
- 测试覆盖率 ≥80%
- 文档数量 ≥15
- 所有 P0/P1 项完成
- P2 项完成 ≥80%

---

### B 级（良好）- 总分 70-84

**特征**：
- 可自用
- 有少量已知问题
- 基础文档齐全
- 需要优化

**验收标准**：
- audit 总分 ≥70
- 测试覆盖率 ≥60%
- 文档数量 ≥8
- 所有 P0 项完成
- P1 项完成 ≥70%

---

### C 级（一般）- 总分 50-69

**特征**：
- 基本能用
- 有较多问题
- 文档缺失
- 需要大幅优化

---

### D 级（较差）- 总分 <50

**特征**：
- 无法正常使用
- 严重缺陷
- 建议重构

---

## 📐 八大维度质量标准

### 1. 元数据完整性（权重 15%）

| 检查项 | S 级 | A 级 | B 级 |
|--------|------|------|------|
| frontmatter | 完整且规范 | 完整 | 有 name |
| description | 200+ 字，含触发场景 | 100+ 字 | 有描述 |
| 版本号 | 语义化，有发布记录 | 语义化 | 有版本号 |
| 许可证 | 有，且文件完整 | 有 | 有声明 |
| 作者信息 | 完整（名字/邮箱/链接） | 有名字 | 有 |

**评分公式**：每项 20 分，总分 100

---

### 2. 文档完整性（权重 20%）

| 检查项 | S 级 | A 级 | B 级 |
|--------|------|------|------|
| 文档数量 | ≥20 | ≥15 | ≥8 |
| README | 完整，有徽章和示例 | 完整 | 基本完整 |
| QUICKSTART | 5 分钟可上手，有截图 | 5 分钟可上手 | 有基本步骤 |
| API 文档 | 所有函数，有示例 | 核心函数 | 有部分 |
| FAQ | 20+ 问题 | 10+ 问题 | 5+ 问题 |
| 文档更新 | 与代码同步 | 基本同步 | 有滞后 |

**评分公式**：文档数量占 40%，质量占 60%

---

## ✅ 验收流程

### 提交验收

1. **自检**：运行 `python skill-opt.py audit --path .`
2. **修复**：根据报告修复问题
3. **测试**：运行所有测试
4. **文档**：更新 CHANGELOG 和版本号
5. **提交**：创建 Pull Request

### 验收检查项

```bash
# 1. 健康检查
python skill-opt.py audit --path .
# 要求：总分 ≥ 目标等级分数

# 2. 代码质量
flake8 scripts/
mypy scripts/
black --check scripts/
# 要求：0 错误

# 3. 测试
python -m pytest tests/ -v --cov=.
# 要求：全部通过，覆盖率达标

# 4. 文档检查
# 检查所有文档链接有效
# 检查文档与代码同步

# 5. 跨平台测试
# 在 Windows/macOS/Linux 上运行
```

### 验收结论

| 结论 | 条件 | 后续动作 |
|------|------|---------|
| ✅ 通过 | 所有检查项达标 | 可以发布 |
| ⚠️ 有条件通过 |  minor 问题，不影响使用 | 修复后发布 |
| ❌ 不通过 | 有 major 问题 | 修复后重新验收 |

## 🎓 质量文化

### 核心原则

1. **质量是每个人的责任**
2. **预防胜于修复**
3. **自动化一切可以自动化的**
4. **数据驱动决策**
5. **持续改进**

### 最佳实践

- 测试驱动开发（TDD）
- 代码审查（Code Review）
- 持续集成（CI）
- 小步提交，频繁发布
- 简洁代码，避免过度设计
