# 项目流程化：把 AI 搭好的项目，变成"零基础可学、可动手、可验收"的指南

## 一、这个 Skill 解决什么问题

AI 现在能一键生成"能跑、功能齐全"的全栈项目（如 RAG + Agent 平台、前后端分离系统）。
但学习者直接拿到会陷入两个陷阱：

- **抄完就交**：项目能跑，但一行没写、一问就露馅，面试与工作都用不上；
- **无从下手**：上万行代码、几十个模块，不知道先读什么、什么必须自己重写、怎么验收。

本 Skill 的产物是**两份文档，而不是一份**：

| 产物 | 受众 | 内容 | 位置 |
|---|---|---|---|
| **README 增强** | 面试官 / 使用者 | 能力、用法、架构、限制、测试与 CI；原 README 零删减 | 项目仓库 |
| **《从零到专家 · AI 协作学习指南》** | 你自己 | 代码怎么来的、AI 已完成部分如何"利用而非抄"、哪些必须亲手做、按什么路线从零基础到专家级并通过验收 | **仓库外**（如项目仓外的 `../private-notes/`） |

> 两者内容不同、受众不同、安全级别不同。把指南写进 README 等于把"哪些是 AI 写的"摊给面试官——
> 这是本 Skill 最容易犯、后果最重的一个错误。详见 `references/05-文档一致性与防漂移.md` 第 7 节。

> 核心理念一句话：**跑起来 → 读得懂 → 复现出 → 改得动**，AI 负责"骨架 + 体力"，学习者负责"灵魂 + 验证"。

## 二、五条核心原则（不可违背的设计原则）

1. **零删减原则**：原始 README 一个字都不删，只允许"插入 / 增强"。唯一例外是**显式标注的事实修正**（如测试数写错），且必须用 `verify_zero_cut.py` 输出差异、在正文说明，禁止静默改写。
2. **事实可追溯原则**：文档里每一个数字（文件行数、测试用例数、组件数、配置开关、服务名、依赖、脚本参数）都必须来自 `scan_project_facts.py` 的同一次扫描或直接读源码，禁止凭印象编造；统计口径要写清（物理行、排除 `__init__.py`/缓存/依赖目录）。
3. **分工显式原则**：每个模块都要标明"AI 已完成 / 你需验证 / 你必须亲手写"，并给"让 AI 讲代码"的 Prompt；凡是面试会问、工作能复用的（核心算法、流程、架构决策），必须学习者亲手白板默写或重写。
4. **循序渐进原则**：路线必须分阶段（如阶段 0-5），每阶段给出**学习周期、验收目标、项目练习、知识点优先级、学习技巧**；前置基础不牢时给"补到什么程度即可"的对照，不要求系统补完课再动手。
5. **可执行可验收原则**：所有命令必须来自项目真实脚本、可直接照抄（含路径、参数、鉴权、报错排查）；每章/每阶段配可勾选的验收清单，指南结尾有"从零基础到专家"的终极 checklist。
6. **公开/私密分离原则**：README 只放能给面试官看的内容；分工说明、AI 协作比例、逐章练习一律进仓库外的私密指南。私有文档写进 `.gitignore`，并用 `check_docs.py` 的私有文件检查做 CI 守卫。**禁止用 `git add -A` 盲加**。

## 三、五轮迭代工作流程（标准工作流程）

按顺序执行，每轮都有明确产出与校验动作。**先用脚本拿到事实，再动笔**，不要边想边编数字。

### 第 0 步：探查项目、备份原文

- 读项目根的 `README`、`docker-compose`、依赖清单、配置文件、目录结构、`docs/`、`tests/`，判断技术栈与"AI 已做到哪一步"。
- 把原始 README 复制一份为 `*_original.md`（或临时路径），作为零删减比对基准。
- **确认边界**：项目是否公开仓库？私密指南必须放在仓库外（如 `../private-notes/`），并写入 `.gitignore`；已存在的私有文档要确认没被 git 跟踪。

### 第 1 轮：扫描事实（数字全部来自这里）

```bash
python scripts/scan_project_facts.py --path <项目根> --group-depth 2 \
  --components "app/routers,app/models,app/schemas,src/views" --json --output facts.json
```

- 记录：代码总规模与分层行数、测试文件/用例数（含每个测试文件分布）、组件目录业务文件数（已自动排除 `__init__.py`）、Docker 服务、`.env` 键名（脱敏）、依赖清单。
- 对扫描器未覆盖的关键事实（golden 用例条数、配置常量、评测脚本参数、接口数），**直接打开对应源码逐个核对**，方法见 `references/02-事实核查清单.md`。

### 第 2 轮：套模板生成指南初稿

- **产物 A（公开 README）**：原 H2 一个不删，只插入四块——能力矩阵 / 快速开始 / 架构（含未接线标注）/ 已知限制与验收命令。**不写分工、不写 AI 协作比例。**
- **产物 B（私密指南）**：复制 `templates/learning-guide-template.md` 生成仓库外的《学习指南》，必写八章：①代码怎么来的与分工 ②AI 已完成清单与"如何利用" ③必须亲手做的部分 ④五阶段路线 ⑤手把手操作手册 ⑥AI 协作规范（红线） ⑦代码地图 + 文档导航 ⑧终极验收清单。
- 写法、Frontmatter、callout、Mermaid、表格规范见 `references/03-写作规范.md`；Prompt 模板见 `references/04-AI协作Prompt库.md`。

### 第 3 轮：事实校准（逐数字回源码核对）

- 用 `scan_project_facts.py` 与 `grep`/读文件逐项核对表格里的行数、组件数、用例数、开关名、脚本参数；宁可不写，也不留错误数字。
- 模型名/版本号等易变内容写"系列"不写死具体小版本。

### 第 4 轮：补可执行性与全面性

- 操作手册前置环境清单（什么不用装、什么必须装、如何验证）、Git 安全网（无 git 时如何 init 基线）、调试/接口测试/前端构建工具箱、成本控制、基础补课对照表。
- 检查清单见 `references/01-五轮迭代方法论.md` 第 4 轮。

### 第 5 轮：导航、回归校验与交付

- 生成折叠目录并写回：
  ```bash
  python scripts/make_toc.py --path README.md --start "学习指南" --end "License" \
    --levels 3-4 --details --title "学习指南目录（点击展开）" --insert-after "学习指南（AI 协作版）" --write
  ```
- 三连校验（见下方"四、五个脚本"）：
  ```bash
  python scripts/validate_md.py --path README.md --require-frontmatter
  python scripts/verify_zero_cut.py --original README_original.md --new README.md
  python scripts/check_docs.py --root . --tests backend/tests
  ```
- **把 `check_docs.py` 接进 CI**（lint job 里加一步即可）。生成时校验只能保证"此刻对"，只有 CI 才能保证"以后还对"。

## 四、五个脚本（确定性工作交给脚本，不要手写正则）

所有脚本在 `scripts/`，纯标准库、跨平台、带 `--help`：

| 脚本 | 解决什么 | 典型命令 |
|------|---------|---------|
| `scan_project_facts.py` | 扫描可信事实：分层行数、测试数、组件数、服务、依赖、`.env` 键 | `--path 项目根 --group-depth 2 --components "..."` |
| `validate_md.py` | 围栏状态机校验：H1 唯一、层级不跳、围栏闭合、表格列数、双链 | `--path README.md --require-frontmatter` |
| `verify_zero_cut.py` | 原文零删减比对：精确/宽松/疑似删减三级，差异逐行列出 | `--original 原.md --new 新.md --allow-note "..."` |
| `make_toc.py` | 生成 GitHub slug 折叠目录（与 GitHub/Obsidian 一致），可写回 | `--path README.md --start .. --end .. --details --write` |
| `check_docs.py` | 文档与代码一致性：测试数、路径、废弃表述、私有文件、接口清单（兼容 `POST /api/x` 写法，支持 `--json`） | `--root . --tests backend/tests --openapi openapi.json` |

> 落地到具体项目时**不要 fork 逻辑**：把本文件复制到 `<项目>/backend/scripts/check_docs.py`，
> 只在顶部保留一段「项目本地配置」（废弃表述、私有文件、默认根目录），其余函数与上游保持一致。
> 这样上游修的问题能靠一次 diff 回灌到所有项目；逻辑各改各的，两份脚本就会悄悄分叉。

> 关键易错点：校验标题**必须用代码围栏状态机**——代码块里的 `#` 是 bash 注释，朴素正则会误判出假 H1。这几个脚本已内置状态机，直接调用即可。

## 五、输出规范与质量标准

最终产物（**公开 README** 与 **私密指南** 各自校验）必须满足：

1. **Frontmatter 合规**：以 `---` 开头，含 `title/category/tags/difficulty/created/updated/status/version/tech_stack/source` 等字段；全文恰好 1 个 H1。
2. **结构完整**（两份分别校验）：
   - 公开 README：原文 H2 全部在前且零删减，只插入"能力/用法/架构/限制"四块；
   - 私密指南：独立成文、恰好 1 个 H1；八章 H3 + 小节 H4，层级不跳跃（无 H5/H6）；交叉引用与锚点存在。
3. **导航可用**：开头有"今天就做这 3 件事"快速入口，指南标题下有折叠 TOC，结尾有代码地图 + 文档导航。
4. **事实零错误**：所有数字可追溯到扫描结果或源码；配置开关、脚本参数、路径与项目一致；敏感信息（API Key、密码）脱敏。
5. **分工与验收清晰**：六大亲手任务 + 白板算法清单 + 阶段周期/验收 + 终极 checkbox 清单齐备；命令可照抄、报错有排查。

交付前自检清单：

- [ ] `scan_project_facts.py` 输出的行数/用例数/组件数/服务/依赖与文档一致
- [ ] 关键事实（用例条数、配置常量、脚本参数）已逐个打开源码核对
- [ ] `validate_md.py` 通过（H1=1、围栏偶数、无层级跳跃、表格列数一致）
- [ ] `verify_zero_cut.py` 仅有的差异都属于已 `--allow-note` 声明的有意修正
- [ ] `make_toc.py` 生成的锚点与正文标题一致，快速入口链接可跳转
- [ ] 八章齐全；每阶段含周期/验收/练习/优先级；终极验收清单可勾选
- [ ] 无 API Key/密码等敏感信息；模型版本等易变内容未写死
- [ ] `check_docs.py` 全绿，且做过一次反向验证（故意写错一个数字/路径，确认会红）
- [ ] 私密指南不在仓库内；`.gitignore` 已含；仓库 `git ls-files` 中无私有文档
- [ ] 架构图每层能指到具体文件/函数；未接线能力用虚线标注（见 references/05 第 5 节）

## 六、使用场景

### 场景一：AI 刚生成一个全栈项目，要做学习指南

输入：一个能 `docker compose up` 跑起来的项目（如 RAG + Agent 平台）。
执行：备份原 README → 第 1 轮扫事实 → 第 2 轮产出两份（README 四块 + 私密八章）→ 第 3-5 轮校准/补全/校验 → 交付。
输出：① 零删减、可公开的 README 增强；② 仓库外、带折叠目录与验收清单的《从零到专家 AI 协作学习指南》。

### 场景二：已有项目 README，只想补"从零到专家"学习路线

执行：先 `verify_zero_cut.py` 建立基准，在 README 里只插入"能力/用法/架构/限制"四块；路线、精读顺序、白板清单与验收写入仓库外的私密指南（按 `references/01-五轮迭代方法论.md` 的五轮法）。

### 场景三：指南多轮迭代后的回归校验

每次新增/修改后，依次跑 `validate_md.py`、`verify_zero_cut.py`、`make_toc.py`、`check_docs.py`（输出到 stdout 对比），确保没有引入层级错误、误删原文、断链锚点、数字漂移。

## 七、参考文档与模板导航（按需读取）

- `templates/learning-guide-template.md`：**生成指南时的主骨架**，含 Frontmatter、折叠 TOC 占位、八章结构、callout 与表格范例。
- `references/01-五轮迭代方法论.md`：每轮检查点、常见缺口、"AI/你"分工判定规则。
- `references/02-事实核查清单.md`：哪些数字必须实测、用什么命令、如何核对 golden 用例/配置/脚本参数。
- `references/03-写作规范.md`：Frontmatter 字段、标题层级、Obsidian callout、Mermaid、表格与代码围栏规范。
- `references/04-AI协作Prompt库.md`：让 AI 讲代码、拆任务、出评测题的可复制 Prompt，以及"红线"。
- `references/05-文档一致性与防漂移.md`：单一事实源、四类断言、CI 接入、架构图规范、假完备清单、公开/私密分离。
- `examples/`：以一个真实企业级 RAG+Agent 项目为例，展示扫描事实到八章的映射关系。

## 八、边界与禁忌

- 不替用户完成"必须亲手做"的实操（白板默写、跑通系统、补 golden QA、跑评测）——指南只给方法和命令，产出由学习者完成。
- 不在文档里粘贴真实密钥/密码；`.env` 只列键名。
- 不硬凑内容：经五轮后若文档已完备，应明确建议用户"转入动手实践"，避免无限加章节。
- 不混用多个统计脚本的数字；同一文档的规模数字以同一次扫描为准。
- **不把学习指南写进项目 README**：它含"AI 已完成 / 你必须亲手做"的分工，只进仓库外的私密文档。
- 不用 `git add -A` 盲加；提交前先看 `git status`，并用 `check_docs.py` 确认无私有文件被跟踪。
