# 人生指导手册生成器（Career & Life Guidance）

> 把"普通背景个体如何靠能力而非标签改变命运"这件事，做成一份**有温度、可执行、按优先级组织、贴合真实身份**的全周期指导手册。核心理念：不做空泛的宏观环境分析，只写"这个人明天起床后具体该做什么"。
>
> 成品标杆是一份**书籍级手册**：完整版 10-20 万字、六篇数十章、上百张表格与数十张流程图，从"写在前面"到"文档信息"有一整套固定部件；用户不是在读报告，而是在听一个走过这条路的前辈，坐在对面跟他说实在话。

---

## 核心原则与设计理念

### 1. 身份锚定原则
所有内容必须以用户真实身份为锚，不写通用内容。每个建议都要回答"对这个人具体意味着什么"。8个身份字段未锁定前，不开始写正文。

### 2. 可执行密度原则
每1000字至少1个可执行动作。拒绝空泛的宏观分析，每个建议必须包含"为什么重要 + 具体怎么做 + 不做的后果"三要素。多用表格和流程图，少用大段文字。

### 3. 项目为王原则
项目实战篇占全书25%-35%篇幅，是重中之重。至少3个从易到难的完整项目，每个项目包含需求分析→技术选型→实现指南→工程化→部署→简历包装全流程。项目是普通背景者最好的简历。

### 4. 前辈语气原则
像一个走过这条路的前辈，坐在对面说实在话。有温度但不鸡汤，有建议但不说教。用"我见过..."、"以我的经验..."代替"你必须..."。承认困难，但给出出路。

### 5. 六篇时间线原则
按人生时间线组织：决策→学习→项目→求职→发展→支撑。每篇解决一个阶段的核心问题，篇与篇之间有逻辑递进。每篇结束必须有行动清单和检查点。

### 6. 风险兜底原则
不只讲成功路径，还要讲失败预案。第六篇支撑与风险必须包含失业、生病、行业衰退、个人危机等风险场景的应对方案。给用户安全感，比给用户焦虑更重要。

### 7. 多轮迭代原则
手册通常迭代3-5版。第1版搭骨架，第2版深化项目，第3版补求职和支撑，第4版做长期发展和风险，第5版整体润色。不追求一次完美，每轮聚焦一个方向做深做透。

### 8. 标准化输出原则
输出必须符合Obsidian标准：双链格式正确、Frontmatter完整、流程图可渲染。成品必须包含固定套件：写在前面、能力总览、篇小结、收尾套件、文档信息，缺一件都不算完整手册。

## 一、这个 Skill 解决什么问题

普通背景用户（普通一本/二本、零基础、跨专业、转行、在校学生）在做职业决策时，面对的真实困境是：

- 信息过载且互相矛盾，不知道该信哪个、先做哪个
- 学校教的落后、教程只教跟敲，**没人教"怎么从知识点走到能赚钱的能力"**
- 容易陷入"无限准备"（总觉得没学完，不敢行动）和"身份焦虑"（学历/经验/年龄）
- 宏观分析看了很多，却没有一份贴合自己身份、能照着执行的完整路线

本 Skill 的产出不是"行业研究报告"，而是一份**人生指导手册**：以用户真实身份为锚，按人生时间线组织，每个建议都回答三件事——**为什么重要 + 具体怎么做 + 不做的后果**。

## 二、先认标杆：一份合格成品长什么样

动手前先建立成品标准。详细部件模板见 `references/12-document-anatomy.md`，此处是必须记住的总纲。

### 2.1 量级标准：按版本递进，不允许"半成品式完整"

手册通常迭代 3-5 版才成型，每一版都要有明确量级，禁止用"提纲+几句解释"冒充成品：

| 版本 | 内容范围 | 参考量级 | 合格线 |
|------|---------|---------|--------|
| v1 决策骨架 | 写在前面 + 能力总览 + 第一篇 + 六篇目录 | 1-2 万字 | 方向结论有据可查、硬截止已设 |
| v2 补支撑维度 | 加学习期主干 + 身体/社保/理财/心态 | 3-6 万字 | 每条建议三位一体、P0/P1/P2 标注齐全 |
| v3 深化职业能力 | 加求职篇 + 长期发展篇 | 8-12 万字 | 数字具体、模板可复制、每章有小结和行动清单 |
| v4 完整版 | 项目实战独立成篇、全书补齐 | 10-20 万字+ | 部件齐全（见 2.2）、可当工具书随时查阅 |

### 2.2 成品固定套件（缺一件都不算完整手册）

```
① Frontmatter（12 字段，含 version/summary/pre/next）
② 写在前面：给正在犹豫的你（情绪接住→能力背书→数据定锚→出发召唤）
③ 能力体系总览（导航地图四件套：5阶段总表 + 维度优先级矩阵 + 核心增量表 + 按状态阅读导航图）
④ 六篇正文（每篇：篇首导言 → 若干章 → 篇小结）
   每章固定微结构：开场问题 → 表格/数据（带来源行）→ 核心结论/关键认知
                 → ❌误区+真相 → 📌本章小结 → 📋本章行动清单
⑤ 风险提示（8 条贯穿性风险，每条含应对）
⑥ 结语：掏心窝子的 N 句话 + 金句引用块
⑦ 参考文献（[n] 编号，标题—机构—时间—链接，正文数字逐一对应）
⑧ 尾部导航（相关笔记 / 前置知识 / 延伸阅读 三段式 Obsidian 双链）
⑨ 免责声明（理财/法律/医疗/数据时效边界）
⑩ 文档信息块（版本、日期、字数、结构、本版变更、适用人群、核心判断）
```

### 2.3 密度指标（完整版的下限，用来防止"写薄了"）

- **表格**：每章至少 1-3 张对比/决策表；表格下方给"资料来源：……"行
- **Mermaid 图**：全书 20 张以上（阶段地图、9 步流程、架构图、状态流转、路径图），一图一主题、图前引导图后解读
- **📌本章小结**：每章结尾一段浓缩，覆盖本章全部关键结论，让用户不回看正文也能抓住要点
- **📋行动清单**：每章结尾 5-8 条 `- [ ]` 可勾选项，并提示复制到任务工具
- **具体数字**：时间（每天几分钟/共几个月）、数量（刷多少题/投多少家/存多少月钱）、区间（薪资带/占比）——禁止"多学习、多努力"式零信息句子
- **代码/配置**：涉及技术处给**完整可运行**内容，不给残缺片段

## 三、铁律：动手前先完成"用户身份校准"

**身份没校准，不许开始写正文。** 错误的身份假设会让整份文档作废（例如把"已毕业全职转行"错写成"在校学年规划"）。

### 3.1 必须锁定的 8 个身份字段

| 字段 | 说明 | 典型取值 |
|------|------|---------|
| 学历层次 | 决定哪些赛道卡学历、哪些看能力 | 985/211、普通一本、二本、专科、硕士 |
| 毕业/在校状态 | 决定用"学年时间线"还是"转行时间线" | 在校大几、毕业几年、在职、裸辞全职 |
| 现有基础 | 决定从哪里起步，禁止臆测经验 | 完全零基础、有旧背景但已忘、有相关经验 |
| 可投入时间 | 决定学习周期与每日安排 | 全职8-10h、在职2-3h、在校课余 |
| 目标定位 | 决定赛道高度与节奏 | 进大厂、进中小公司、自由职业、站稳中产 |
| 硬约束/排除项 | 用户明确不做的，绝对不写 | 不做算法、不回老家、不考虑某方向 |
| 家庭/经济约束 | 决定能否裸辞、学习期多长 | 存款月数、是否需顾家、有无房贷 |
| 地域倾向 | 决定技术栈与城市建议 | 目标城市、是否接受异地/远程 |

### 3.2 校准规则

1. **多轮校准，以最新指令为准**：用户可能连续推翻前设（在校→已毕业→无旧背景→全职），每轮都要更新锁定字段，并主动说明"本版已按你的最新情况调整"。
2. **信息缺失时一次性问清关键字段**，不要把互斥分支丢给用户选；不会改变结论的细节可自行假设并显式标注。
3. **用户明确排除的内容绝不展开**（如用户说家庭/恋人已处理好，就不再写婚恋家庭章节，后续迭代也不加回）。
4. 校准完成先产出一句话"用户画像"，后续每一篇、每一条建议都必须回答："这对画像里的这个人，为什么适用？"
5. 完整校准方法、追问话术与 5 类身份画像库见 `references/01-user-profiling.md`。

## 四、核心产出结构：六篇人生时间线

一份完整手册默认按**人生推进顺序**组织成六篇（可按用户情况裁剪，但顺序逻辑不变）：

```
第一篇  决策与准备期   —— 选赛道、破焦虑、做准备（身体/钱/社保/法律）
第二篇  系统学习期     —— 从零到能做东西的学习路线、方法、工具、心态
第三篇  项目实战期     —— 把知识点变成能上线、能写进简历的项目（核心差异化）
第四篇  求职冲刺期     —— 作品集、简历、投递、面试、谈薪、签约
第五篇  长期发展期     —— 入职后晋升、深度/广度、跳槽、地区定居、35岁危机
第六篇  风险应对期     —— 每个阶段的 Plan B 与兜底预案
```

六篇不是固定章节数，而是**思考顺序**：先决定、再学习、再做项目、再求职、再发展、全程有兜底。

**篇级固定动作（篇篇都要做，详见 references/12）：**
- 篇首放引用块导言：本篇解决什么问题 → 什么状态的人该认真读 → 为什么不能跳过
- 篇尾放"篇小结"：编号回顾本篇要点 → "X 时间后你会发生什么转变" → 一句承上启下引出下一篇

每篇的详细章节模板见 `references/03-six-phase-structure.md`，可直接套用的完整骨架见 `assets/document-template.md`。

## 五、标准工作流程（8 步）

### 第 1 步：身份校准
按第三节锁定 8 个字段；缺失则先问。产出一句话"用户画像"，后续所有内容都对它负责。

### 第 2 步：赛道选择与取证
- 当用户面临"A 还是 B"时，**不要简单二选一，先找交叉融合地带**（例：纯全栈初级岗被 AI 压缩、纯调 API 缺工程底座，交叉的"AI 全栈"才是最优解），并给出主辅关系与先后顺序。
- 用统一维度横向对比候选赛道：需求增速、学历门槛、薪资带、竞争烈度、年龄危机、抗替代性、与用户身份的匹配度。
- 所有关键数字必须可溯源（标注来源与时间），区分"已查证数据"与"经验判断"；预测给乐观/中性/悲观三情景 + 可验证跟踪信号。取证框架见 `references/02-track-selection.md`。

### 第 3 步：搭建全书固定套件与六篇骨架
- 先立 Frontmatter、写在前面、能力体系总览四件套（references/12 有模板），让手册一上来就有"全局地图"。
- 按六篇结构列章，给每条建议/每个知识点打优先级：
  - **P0（立即做/必须掌握，🔴）**：不做会直接失败
  - **P1（重要，🟡）**：显著拉开差距
  - **P2（长期建设，🟢）**：锦上添花、持续积累
- 优先级是这份手册的灵魂：普通背景用户资源有限，必须先做回报率最高的事，并显式写明"资源不够时先砍什么"。

### 第 4 步：填充学习路线（第二篇）
- 分阶段、标知识点优先级（重点学什么 / 可以跳过什么 / 先后顺序），每阶段给**可验证的验收标准**和配套项目，禁止用"看完了某教程"当成果。
- 区分全职/在职/在校的时间方案，含每日时间分配、经济准备、心态管理、效率陷阱。方法见 `references/04-learning-roadmap.md`。

### 第 5 步：填充项目实战（第三篇，重中之重，篇幅占全书 25%-35%）
这是普通背景者**最大的加分项和最缺的能力**，必须写到"照着做就能做出来"：
- 项目认知误区 → 项目规划（灵感来源/难度分级/求职项目组合）→ 从 0 到 1 的开发流程（需求→选型→架构→拆解→开发→测试→部署→文档→迭代，每步给产出物）
- 给 2-3 个完整项目实现指南（背景/功能/选型理由/架构图/分阶段任务/难点完整代码/工程化配置/部署/面试讲法/15-20 个高频问题）
- 工程化实践、AI 辅助开发（含红线）、独立解决问题能力、项目包装求职、从教程到独立的进阶路径
- 完整方法见 `references/05-project-playbook.md`。

### 第 6 步：填充求职与长期发展（第四、五篇）
- 求职：渠道优先级、对其友好的公司类型、作品集标准、简历 STAR-R（学历放底部）、面试权重与项目讲法（3 分钟+10 分钟两版）、薪资谈判、合同社保、gap 话术。见 `references/06-job-hunting.md`。
- 长期：能力体系阶段模型、系统设计、深度 vs 广度、细分领域选择、跳槽节奏、向上管理与晋升、地区选择、35 岁危机根本解法、被动收入。见 `references/07-longterm-development.md`。

### 第 7 步：补齐支撑维度、风险预案与收尾套件
- 支撑维度按用户需要裁剪：身体健康、心理韧性、理财、社保保险法律、个人品牌、人脉导师、信息获取体系、英语、远程工作。清单见 `references/08-support-dimensions.md`。
- 每个阶段都写 Plan B：进度慢怎么办、找不到工作怎么办、风口过去怎么办、经济断了怎么办，并先给"不要做的事"（如别借消费贷、别考研逃避）。
- 最后统一完成收尾套件：风险提示 8 条、结语、参考文献、三段式尾部导航、免责声明、文档信息块（模板见 references/12）。

### 第 8 步：标准化输出与校验
- 按 `references/10-obsidian-output.md` 做 Obsidian 标准化（Frontmatter、`[[]]` 双链、Mermaid、表格、尾部导航、文档信息）。
- 写作语气必须通过 `references/09-writing-style.md` 的检查清单。
- 交付前做完整性校验（见第八节），大文件分段回读验证，不凭字数假设完整。

## 六、写作风格与"前辈语气"配方（详细规范见 references/09）

1. **第二人称"你"**，像走过这条路的前辈在跟你说话，有温度、不端着，可适度直言现实；允许有明确立场和推荐，不做"各有优劣你自己看着办"的甩手掌柜。
2. **三位一体**：每个建议都写清「为什么重要（含后果）→ 具体怎么做（可执行步骤/模板/数字）→ 常见误区与避坑」。
3. **语气四件套**（本书的辨识度来源，详细句式库见 references/09、部件模板见 references/12）：
   - **掏心窝子开场**：写在前面先用三句话接住情绪——"你不晚 / 你能学会 / 这条路走得通（用数据证明）"
   - **关键认知/核心结论**：每节用加粗句一锤定音（"**关键认知：……**""**核心结论：……**"），不把判断藏在数据里让用户自己悟
   - **误区+真相对**：每个坑写成"❌误区：…… → 真相：……"，先复述新手的真实想法再纠正
   - **小结+行动清单收尾**：📌本章小结浓缩全章，📋行动清单给出明天就能打勾的动作
4. **贴合身份、拒绝空谈**：不堆砌宏观数据和正确的废话；每个结论都要落到"这个身份的你明天做什么"。宏观数据只作论据、点到为止。
5. **细节到可执行**：给数字、给模板、给清单、给时间周期、给资源；举例必须具体（具体技术、具体公司类型、具体场景）。
6. **优先级前置**：章节内先讲 P0，明确告诉用户"资源不够时先砍什么"，主动替用户做减法。
7. **多用表格做对比和决策，多用 Mermaid 画流程/架构/路径图**（Obsidian 原生渲染）；段落不超过约 5 行。
8. **诚实标注不确定性**：数据标来源与时点，预测给乐观/中性/悲观三情景，不打包票、不灌鸡汤；理财/法律/医疗只给常识框架并建议咨询专业人士。

## 七、多轮迭代协议（这份手册通常要迭代 3-5 版）

用户往往会持续追加"还缺什么、再深化某块、按优先级补充"。遵循 `references/11-iteration-protocol.md`：

1. **增量不推翻**：保留已确认内容，新增维度按人生时间线落位到对应篇，不另起炉灶、不在文末堆"补充章节"。
2. **版本递进**：v1 决策骨架 → v2 补支撑维度 → v3 深化职业能力 → v4 补项目实战，每版更新版本号、`date` 日期、字数、结构、变更说明（Frontmatter 的 summary 与文末文档信息块同步，四处一致）。
3. **每次迭代都做三件事**：去重（新内容与旧内容重叠则合并并加交叉双链）、消歧（前后矛盾以最新为准并显式说明）、理顺序（章节重新编号，目录/正文/导航三处同步）。
4. **用户说"还缺什么"时**：主动从方法论清单中找出其尚未覆盖的高价值维度，按优先级推荐并说明"为什么你现在需要它"，而不是等用户点名。
5. 本地文件固定路径覆盖 + 同步在线文档（如飞书），两个交付物都要验证；最终回复给出：版本、字数/章节、本次新增清单、交付入口、下一步可继续方向。

## 十、使用场景

### 场景一：普通一本学生选择职业方向

**用户输入**："我是普通一本计算机专业大三学生，成绩中等，不知道该走前端、后端还是AI方向，帮我做一份完整的职业规划"

**执行流程**：
1. **身份校准**：锁定8个身份字段（普通一本/计算机/大三/成绩中等/无实习/一线城市/目标月薪15k/无明确偏好）
2. **赛道选择**：读取`references/02-track-selection.md`，对前端/后端/AI三个方向做对比取证，结合用户身份给出推荐
3. **搭建骨架**：读取`assets/document-template.md`，搭建六篇结构
4. **填充内容**：按8步工作流程填充学习路线、项目实战、求职策略、长期发展
5. **重点突出**：项目实战篇占25%-35%篇幅，给出3个可落地的项目
6. **校验交付**：按交付前校验清单检查，输出完整手册

**输出**：一份10-20万字的六篇人生指导手册，从"写在前面"到"文档信息"完整套件

### 场景二：零基础转行到互联网

**用户输入**："我是机械专业毕业2年，在工厂上班，想转行做程序员，零基础，帮我规划一条从入门到入职的完整路线"

**执行流程**：
1. **身份校准**：锁定8个身份字段（机械专业/毕业2年/工厂工作/零基础/26岁/新一线城市/目标月薪12k/有存款可支撑6个月）
2. **赛道选择**：读取`references/02-track-selection.md`，对比前端/后端/测试/运维，推荐最适合零基础转行的方向
3. **时间规划**：6个月全职学习或12个月在职学习的详细时间表
4. **项目实战**：读取`references/05-project-playbook.md`，设计3个从易到难的转行项目，重点是能写进简历的作品
5. **求职策略**：读取`references/06-job-hunting.md`，针对转行求职者的简历包装、面试话术、薪资谈判
6. **风险预案**：转行失败的退路、经济压力应对、心态调整
7. **校验交付**

**输出**：一份针对零基础转行者的完整指导手册，包含每日学习计划、项目实现指南、简历模板、面试题库

### 场景三：35岁危机应对与中长期发展

**用户输入**："我35岁，在中小公司做后端开发5年，感觉遇到瓶颈，担心35岁危机，帮我规划未来5-10年的职业发展"

**执行流程**：
1. **身份校准**：锁定8个身份字段（35岁/后端5年/中小公司/本科/已婚有孩/二线城市/年薪25万/焦虑晋升和裁员）
2. **现状诊断**：分析当前能力短板、行业趋势、年龄优势与劣势
3. **方向选择**：技术专家/技术管理/架构师/独立开发/转行产品，五个方向对比
4. **能力提升**：读取`references/07-longterm-development.md`，制定3年能力提升计划
5. **风险对冲**：副业、理财、社保、人脉、个人品牌，读取`references/08-support-dimensions.md`
6. **35岁危机应对**：如何避免被裁员、如何在面试中解释年龄、如何转型
7. **长期规划**：5年、10年、15年的职业里程碑
8. **校验交付**

**输出**：一份针对35岁程序员的中长期发展手册，包含能力提升路线、风险对冲方案、转型路径、财务规划
