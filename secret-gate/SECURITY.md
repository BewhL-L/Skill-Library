# 安全策略

## 报告问题

发现绕过闸门的漏洞（例如某类密钥匹配不到、钩子在某种环境下不生效），**不要**在公开 Issue 里贴真实密钥或复现样本；直接联系维护者，或用假数据（运行时拼接的 `sk-` + 30 个字符）构造样本提交 Issue。

## 能力边界（请如实理解，不要高估）

| 本技能**不做** | 替代方案 |
|---|---|
| 扫描 git 历史 | `gitleaks`、`git log -S` |
| 熵检测（高随机串） | `gitleaks`、`truffleHog` |
| 二进制内容检查 | 只按文件名与体积拦 |
| 阻止 `git commit --no-verify` | 钩子可被绕过是 git 的设计；CI 里再放一道 |

正则匹配的规则是**已知模式**的防线，不是"检测一切密钥"的承诺。

## fail-closed

钩子找不到 `gate.py`、或扫描器异常时，**拒绝提交**而不是放行。这是刻意的：静默放行会让防线失效而无人察觉。

## 支持版本

| 版本 | 状态 |
|---|---|
| 0.x | 仅安全修复；规则与退出码语义保持向后兼容 |
