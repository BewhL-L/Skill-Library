# 常见问题

## 误报与白名单

**Q: 一个明明没问题的文件被拦了，怎么办？**
A: 先确认内容真的可以公开（示例值、测试假数据）。然后按优先级：

1. 把那行改成明显的占位符（`your-key-here`）——比加规则更安全；
2. 确实要保留 → 在 `rules.json` 的 `allow` 里加**路径**白名单，不要加内容白名单。

**Q: 为什么不提供"内容白名单"？**
A: 内容白名单会永久放过某个模式，而真正的密钥往往和误报长得一样。按路径放行是可控的（只影响一个文件），按内容放行是发散的。

**Q: 测试文件里的假密钥为什么不会拦住自己？**
A: 假密钥在测试里**运行时拼接**（`"sk-" + "a1b2c3d4e5" * 3`），源码里没有完整字面量。见 `tests/test_gate.py` 顶部注释。写死假密钥会让测试文件被自己的闸门拦下——这正是"技能必须能通过自己的检查"。

## 钩子不生效

**Q: 装了钩子但 commit 还是放行了？**
A: 按顺序查：

1. `.git/hooks/pre-commit` 是否存在、是否可执行；
2. 直接跑 `bash .git/hooks/pre-commit`，看输出是 `gate: 通过` 还是报错；
3. 钩子里的 `gate.py` 路径是否是**绝对路径**、技能目录是否被移动过；
4. 是否用了 `git commit --no-verify`（会跳过钩子，这是故意的逃生门）。

**Q: 钩子找不到 gate.py 时会怎样？**
A: **拒绝提交**（fail-closed），并打印原因。宁可卡住让你看见，也不要静默放行。

## 覆盖范围

**Q: 为什么不扫 git 历史？**
A: 本技能只检查**当前即将入库的文件**。已被提交的密钥要靠 `git log -S` 或 `gitleaks` 做全历史扫描——那属于事后清理，不是提交前拦截。

**Q: 为什么文件名规则不拦 `.md`？**
A: 文档名里含 `secret` 很常见（`secrets.md` 讲的是密钥管理），所以文件名规则只针对数据/配置类扩展名（`.json/.yaml/.env/.py/.key…`）；`.md` 里的敏感内容由内容规则兜住。

**Q: 高熵随机串会漏吗？**
A: 会。本技能是**正则前缀匹配**，不做熵检测。需要更强覆盖时换 `gitleaks`，把本技能当"轻量前置"。
