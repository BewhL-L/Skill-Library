# 常见问题（FAQ）

## 1. 这个 Skill 和普通的"写 README"有什么区别？

普通写法容易凭印象编数字、覆盖原文、缺少可执行步骤。本 Skill 强制：先扫事实、
零删减增补、明确 AI 与学习者分工、每步可验收，并用脚本做回归校验。

## 2. 为什么组件数要排除 `__init__.py`？

`__init__.py` 是 Python 包标记，不是业务组件。把它算进去会让"路由数"虚高 1。
`scan_project_facts.py` 已默认排除并单独统计为 `init_files`。

## 3. 为什么不能用普通正则统计 Markdown 标题？

代码围栏里的 `#` 是 bash / Python 注释，不是标题。朴素正则会把它们误判成 H1，
导致"多个 H1"的假错误。`validate_md.py` 和 `make_toc.py` 都用围栏状态机规避。

## 4. `verify_zero_cut.py` 报"疑似删减"，但那是我有意修正的数字，怎么办？

这正是设计目的：**强制你确认每一处与原文的差异**。用 `--allow-note "修正测试用例数 47→79"`
说明原因，确认这些差异都属于已声明的有意修正即可。脚本仍会列出差异，便于复核。

## 5. 生成的锚点为什么和我手算的不一样？

GitHub 锚点规则：转小写、移除标点（保留字母/数字/中文/空格/连字符）、每个空白转一个连字符。
连续空格会变成多个连字符（如 `编排 + 生产化` 含双连字符）。直接用 `make_toc.py`，不要手算。

## 6. 我的项目不是 Python / RAG，能用吗？

能。流程与技术栈无关：扫描"规模 / 测试 / 组件 / 服务 / 依赖"五类事实，再套八章。
前端、Node、Java 项目同样适用；`scan_project_facts.py` 已覆盖常见前端后缀。

## 7. 项目没有 golden QA、没有评测脚本怎么办？

不要假装它存在。在指南第三章把它列为"必须亲手从 0 建立"的任务，第五章给出建立步骤
（字段设计、用例模板、JSON 校验、跑第一轮评测）。

## 8. Windows 控制台中文乱码是脚本出错了吗？

不是。PowerShell 默认 GBK 控制台显示 UTF-8 文本会乱码，文件本身正确。
用 `chcp 65001` 切换，或用 Python 读取输出文件查看。

## 9. 脚本会修改我的项目文件吗？

默认只读取、把报告写到你指定的 `--output`。只有 `make_toc.py --write` 会写回 README，
且会先生成 `.bak` 备份；不放心可先不加 `--write`，输出到 stdout 预览。

## 10. 一定要写满八章吗？

八章是"学习指南"的完整骨架，用于 AI 生成的完整项目。若只是给小项目补学习路线，
可按场景二精简，但"事实可追溯、零删减、分工、验收"四条铁律不可省。
