# 零基础精讲版规范（第三产物）

> 面向"完全新手"的配套文档规范。主指南回答"做什么、做到什么程度算过"；本产物回答"这是什么、为什么、我现在该看到什么"。

## 1. 何时产出

满足任意两条，就应产出：

- 学习者自评"没写过代码 / 没碰过命令行 / 看不懂术语"；
- 主指南里出现大量未解释的名词（RAG、向量、切片、SSE、JWT、容器）；
- 学习者反馈"每个字都认识，连起来不知道在干什么"；
- 项目规模超过 5000 行，或模块数超过 20。

不产出的情况：学习者已能独立读代码、只缺项目路线；此时主指南 + 精读路线足够。

## 2. 与主指南的分工

| 文档 | 回答的问题 | 类比 |
|---|---|---|
| 主指南（私密） | 做什么、先做哪个、做到什么程度算过、哪里有坑 | 施工图 + 验收单 |
| 本产物（零基础） | 这是什么、为什么要有、我现在应该看到什么、报错在说什么 | 师傅带你认工具、讲原理 |

铁律：

1. **不要把精讲版写进 README**，也不要把主指南的分工表搬进精讲版；
2. 精讲版可以引用主指南的章节号，但不复制其事故复盘与商务措辞；
3. 两份文档同时更新时，先改代码事实，再改主指南，最后改精讲版。

## 3. 章节结构（第 0 章 + 第 1-10 章，共 11 章；可按项目裁剪，不要按知识体系排）

| 章 | 目标 | 必须有的内容 |
|---|---|---|
| 0 全景 | 用一句话说清项目是什么 | 生活化比喻 + "点一次发送，系统里发生 N 件事"的链路表（每步标文件） |
| 1 名词地图 | 混个脸熟，不要求记住 | 核心词表（定义 + 比喻 + 在本项目哪里）+ 易混词对比 + 查词方法 |
| 2 前置知识 | 只补项目用得到的那一点 | HTTP/JSON、前后端分离、数据库、容器、`.env`；每节 3 道自测 |
| 3 核心原理 | 讲透项目灵魂（如 RAG） | 五步流程 + 手算例子 + 20 行可运行的最小实验 + 项目比教科书多了什么 |
| 4 第二核心 | 如 Agent / 编排 | 机制时序图 + "谁在执行" + 终止条件 + 工具清单 |
| 5 环境 | 从零到能打开页面 | 每条命令：直译 / 真正做了什么 / 预期输出 / 报错怎么办；终端差异小抄 |
| 6 第一次跑通 | 看懂刚才发生了什么 | 后台 N 步 + 日志逐行翻译 + 亲眼看数据 + 抓包/流式 |
| 7 读代码 | 不是"读"，是"拆" | 四个坏习惯 + 四个方法（入口/断点/改一行/画图）+ 核心文件带读 + 其余模块"知道存在即可" |
| 8 手动部分 | 六件事逐项拆解 | 在干什么 / 为什么不能外包 / 动作 / 完成证据 / 常见卡点；白板算法只写"三样东西" |
| 9 评测 | 为什么"感觉变好了"不算数 | 考卷字段表 + 手算 Hit@K/MRR + 报告解读 + 一轮对照实验 |
| 10 节奏 | 每周干什么 | 最小闭环周表 + 每日模板 + 三个自欺欺人信号 + 求助模板 |

裁剪规则：

- 小型项目可合并 0-2 章、7-8 章；
- 非 AI 项目把第 3-4 章换成对应核心原理；
- 没有评测体系的项目，第 9 章改为"验收与回归"。

## 4. 写作规则（七条）

1. **术语首次出现必须解释**：一句话定义 + 生活比喻 + 在本项目哪里。解释不了，说明作者也没懂。
2. **每个操作必须给"可观察证据"**：命令敲完应该看到什么；没有预期，就无法判断对错。
3. **每条命令必须标工作目录**：仓库根 / `backend/` / `frontend/` / 容器内，四者不能混。
4. **日志要逐行翻译**：不要只说"看日志"，要给一段示意日志并逐行解释；同时标注"示意，不是逐字匹配"。
5. **代码带读只讲"五块"**：一个 300 行文件，先拆成 5 个职责块，再逐块讲；不要从第 1 行 import 读到尾。
6. **范围分三档**：精读 8 个 / 知道存在 16 个 / 暂时不看其余。新手最怕"还有一百个文件没读"。
7. **绝对化表述要收敛**："一定会 / 所有 / 永远"改成"很可能 / 大部分 / 暂时"；示例数字必须标"示意值"。

## 5. 动手卡片模板（每章末尾一张）

```markdown
### 动手卡片 · 第 N 章

**目标**：一句话，可检验。

**命令**（在哪执行，可复制）

| # | 命令 | 用途 | 成功标志 |
|---|---|---|---|
| 1 | `...` | ... | ... |

（无命令的章节写：**没有命令**：这一章只建概念。）

**验收清单**
- [ ] 可观察的事实，不是"理解了"
- [ ] ...

**卡住了**：指向本章某一节或某个报错翻译表。
```

卡片规则：

- 命令必须能直接复制，不能有 `<占位符>` 以外的省略；
- 每条命令必须有"成功标志"；没有标志的命令不要放；
- 验收项必须可观察（"能打开 /docs"、"日志出现 X"），禁止"掌握 / 理解 / 熟悉"；
- 卡片不得引入正文没解释过的新概念；
- 卡片顺序统一：目标 → 命令/无命令 → 验收清单 → 卡住了。

## 6. 命令审查清单（写完逐条过）

- [ ] 工作目录明确：`ruff check app tests scripts` 必须在 `backend/`，不是仓库根；
- [ ] 解释器上下文明确：宿主机 WSL 用 `python3`，容器/venv 用 `python`；
- [ ] 无覆盖式命令：`cp .env.example .env` 必须先判断文件是否存在，否则清空真实 Key；
- [ ] 危险命令有标注：`down -v`、`git checkout -- .`、删库/删卷必须写"危险"；
- [ ] 路径含中文/空格时加引号；
- [ ] 容器状态口径正确：没有 healthcheck 的服务只能写 `Up`，不能写 `healthy`；
- [ ] `grep` 模式不会命中注释：用 `^ *from ...` 之类锚定，避免把说明文字当隐患；
- [ ] 脚本参数真实存在（打开 `--help` 或源码核对），不凭印象写 `--dataset` / `--top-k`；
- [ ] 指标口径真实：`hit@k` 的 k 取 `TOP_K`，不是固定 3/5；报告里没有的字段不要编；
- [ ] 命令实际执行过，记录真实输出；示例输出标"示意"；
- [ ] 失败路径有排查：至少给"最后一行看根因 + 你自己代码的最后一层"两步；
- [ ] 长命令有替代方案（Docker / 本地二选一），并说明前提。

## 7. 多轮审核清单（至少四轮）

**第 1 轮：结构**
- [ ] 章节数 = 卡片数；卡片在每章末尾、下一章之前；
- [ ] 围栏偶数、表格列数一致、全角括号/引号平衡；
- [ ] 无 TODO / 占位符 / 残留标记；标题层级不跳。

**第 2 轮：事实**
- [ ] 每个数字能指到源码或同一次扫描；
- [ ] 函数签名、CLI 参数、字段名与当前代码一致；
- [ ] 配置默认值与 `.env` / `config.py` 一致；
- [ ] 命令能跑通（至少跑主链路三条：启动、测试、评测）。

**第 3 轮：一致性**
- [ ] 同一概念的大小写/译名统一（Hit@K、Rerank、golden QA）；
- [ ] 数量词与实际条目数一致（"四个证据"就真的是四个）；
- [ ] 正文与卡片不矛盾（healthy 口径、容器数、测试数）；
- [ ] 交叉引用的小节号真实存在。

**第 4 轮：可用性**
- [ ] 每条命令有工作目录 + 预期输出；
- [ ] 每个验收项可观察；
- [ ] 危险命令有警示；
- [ ] 示例数字标"示意值"。

> 四轮全过还不算完：**最后一轮只看"读者照着做会不会卡"**，而不是"文字对不对"。

## 8. 高频坑（来自真实项目）

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | 无条件 `cp .env.example .env` | 清空真实 Key，服务 401 | 加 `if [ ! -f ... ]`，并提示后果 |
| 2 | venv 激活顺序反了 | `source .venv/bin/activate` 找不到文件 | 先进 `backend/`，再激活 |
| 3 | `python` / `python3` 混用 | WSL 报 command not found | 宿主机 `python3`，容器/venv `python` |
| 4 | "五个容器都 healthy" | frontend 没有 healthcheck，实际只有 Up | 写"5 个 Up，其中 4 个 healthy" |
| 5 | `grep` 命中注释 | 误判为"绕过统一入口" | 用 `^ *from ...` 锚定 |
| 6 | 文档写 `run_eval --dataset` | 实际 CLI 只有 `--kb-id` / `--no-judge` | 打开源码核对参数 |
| 7 | 把 `hit@k` 固定当 Hit@5 | k 实际取 `TOP_K`，改配置就变 | 写清 k 的来源 |
| 8 | 示例指标冒充实测 | 读者以为 0.911 是真实分数 | 标"示意值"，给"换成你自己的数字" |
| 9 | 文档说 `_execute_tool` 是同步 | 代码已改 async，读者按旧文档改错 | 以代码为准，标注"文档可能过期" |
| 10 | 只给命令不给预期 | 敲完不知道算不算成功 | 每条命令加"成功标志" |

## 9. 交付判定

- [ ] 第 0-10 章（或裁剪后）齐全，每章有可观察的验收点；
- [ ] 每章末尾有动手卡片，卡片命令可复制、有成功标志；
- [ ] 命令审查清单 12 项全过；
- [ ] 四轮审核全过，最后一轮"照着做"没有卡点；
- [ ] 与主指南的分工写清，没有把私密内容写进 README。

> 一句话：**精讲版的价值不在"写完"，在"新手照着做能不卡"。**
