# 项目类型与需求模板

> 供 project-based-learning 生成项目方案时参考，确保需求合理、技术选型恰当、覆盖核心知识点。

## 一、项目类型总览

| 类型 | 难度 | 周期 | 涉及技术栈 | 适合阶段 |
|------|------|------|-----------|---------|
| 全栈 CRUD 应用 | ⭐⭐ | 2-3 周 | 前端+后端+数据库 | 初期→中期 |
| 全栈业务系统 | ⭐⭐⭐ | 4-6 周 | 前端+后端+缓存+消息队列 | 中期→后期 |
| 微服务系统 | ⭐⭐⭐⭐ | 6-8 周 | 微服务+注册中心+网关+分布式事务 | 后期→专家 |
| AI RAG 应用 | ⭐⭐⭐ | 3-4 周 | LLM API+向量数据库+检索+前端 | 中期→后期 |
| AI Agent 应用 | ⭐⭐⭐⭐ | 4-6 周 | Agent框架+工具调用+多Agent+前端 | 后期→专家 |
| 前端工程化项目 | ⭐⭐⭐ | 3-4 周 | 组件库+脚手架+Monorepo+CI/CD | 中期→后期 |
| 高并发系统 | ⭐⭐⭐⭐ | 6-8 周 | 缓存+消息队列+分库分表+限流 | 后期→专家 |
| 全栈+AI 融合 | ⭐⭐⭐⭐ | 6-8 周 | 全栈+AI能力+用户系统+部署 | 后期→专家 |

## 二、各类型项目需求模板

### 类型1：全栈 CRUD 应用

**典型项目**：博客系统、任务管理、图书管理、员工管理

**核心功能模块**：
- 用户认证（注册/登录/JWT）
- 数据 CRUD（列表/详情/新增/编辑/删除）
- 搜索与筛选
- 分页
- 文件上传（可选）

**技术栈**：
- 前端：Vue3 + TypeScript + Element Plus + Axios
- 后端：Spring Boot + MyBatis + MySQL
- 部署：Docker + Nginx

**对应知识点**：
- Vue3：组件设计、路由、状态管理、表单处理
- Spring Boot：RESTful API、参数校验、异常处理、统一返回
- MyBatis：动态 SQL、分页、关联查询
- MySQL：表设计、索引、事务

**验收标准**：
- 完整的用户认证流程
- 所有 CRUD 操作正常
- 前端表单校验 + 后端参数校验
- 统一异常处理和错误返回
- 响应式布局，支持移动端

---

### 类型2：全栈业务系统

**典型项目**：电商平台、在线教育、OA 系统、内容管理系统

**核心功能模块**：
- 用户系统（注册/登录/权限/角色）
- 业务核心模块（商品/订单/课程/内容）
- 搜索与筛选（高级搜索）
- 缓存（热点数据缓存）
- 消息通知（站内信/邮件）
- 文件管理（上传/下载/预览）
- 后台管理（数据统计/管理操作）

**技术栈**：
- 前端：Vue3 + TypeScript + Pinia + Vue Router + ECharts
- 后端：Spring Boot + MyBatis-Plus + Redis + RabbitMQ
- 数据库：MySQL + Redis
- 部署：Docker Compose + Nginx

**对应知识点**：
- 前端：复杂组件设计、状态管理、权限控制、数据可视化
- 后端：缓存策略、消息队列、权限设计（RBAC）、接口限流
- Redis：缓存穿透/击穿/雪崩、分布式锁、热点数据
- RabbitMQ：消息可靠性、死信队列、延迟队列、消费幂等

**验收标准**：
- 基于 RBAC 的权限系统
- 热点数据缓存，缓存命中率 > 80%
- 异步消息处理（订单超时、通知发送）
- 后台数据统计与可视化
- 接口限流与防刷
- 完整的错误处理和日志

---

### 类型3：微服务系统

**典型项目**：微服务电商、在线支付平台、分布式调度系统

**核心功能模块**：
- 多个微服务（用户服务、商品服务、订单服务、支付服务）
- 服务注册与发现
- API 网关
- 配置中心
- 服务间通信（OpenFeign）
- 分布式事务
- 链路追踪
- 统一认证（SSO）

**技术栈**：
- 微服务框架：Spring Cloud Alibaba（Nacos + Sentinel + Seata）
- 网关：Spring Cloud Gateway
- 服务通信：OpenFeign + LoadBalancer
- 消息队列：RocketMQ / RabbitMQ
- 数据库：MySQL（分库分表可选）
- 可观测性：Sentinel + SkyWalking / Zipkin

**对应知识点**：
- 微服务：服务拆分、注册发现、配置中心、网关
- 分布式：分布式事务（Seata AT/TCC）、分布式锁、分布式 ID
- 服务治理：限流、熔断、降级、负载均衡
- 可观测性：链路追踪、日志聚合、监控告警

**验收标准**：
- 至少 4 个微服务，服务间通信正常
- Nacos 服务注册与配置中心
- Gateway 统一路由与鉴权
- Seata 分布式事务（订单+库存+支付）
- Sentinel 限流熔断
- SkyWalking 链路追踪
- 统一异常处理和错误码

---

### 类型4：AI RAG 应用

**典型项目**：知识库问答系统、文档智能助手、客服机器人、代码问答

**核心功能模块**：
- 文档上传与解析（PDF/Word/Markdown）
- 文档切分（Chunking）
- 向量化与存储
- 检索（向量检索 + 关键词检索）
- 重排序（Reranker）
- LLM 生成（带引用）
- 对话历史管理
- 反馈机制（点赞/点踩）

**技术栈**：
- AI 框架：LangChain / LlamaIndex
- LLM：OpenAI API / 国内大模型 API
- Embedding：text-embedding-ada-002 / bge-large-zh
- 向量数据库：Chroma / Milvus / Pinecone
- 后端：FastAPI / Flask
- 前端：Vue3 + TypeScript（聊天界面）

**对应知识点**：
- RAG：文档切分策略、检索优化、重排序、查询改写
- LLM：Prompt 工程、Function Calling、流式输出
- 向量数据库：索引类型、相似度计算、检索性能
- LangChain：Chain、Retriever、Memory、Output Parser

**验收标准**：
- 支持 PDF/Word/Markdown 文档上传
- 文档自动切分、向量化、存储
- 混合检索（向量 + BM25）+ 重排序
- 回答带引用来源
- 多轮对话，上下文管理
- 流式输出
- 回答准确率 > 80%（人工评估）
- 检索召回率 > 90%

---

### 类型5：AI Agent 应用

**典型项目**：智能研究助手、自动化办公 Agent、多 Agent 协作系统、代码助手

**核心功能模块**：
- Agent 核心（ReAct / Plan-and-Execute）
- 工具系统（搜索/计算/文件/API 调用）
- 记忆系统（短期/长期）
- 规划与执行（任务分解、步骤执行）
- 多 Agent 协作（角色分工、通信、协调）
- 人机协作（人工确认、干预）
- 错误恢复（重试、回退、人工介入）

**技术栈**：
- Agent 框架：LangGraph / AutoGen / CrewAI
- LLM：GPT-4 / Claude / 国内大模型
- 工具：Tavily 搜索、Python REPL、文件操作、自定义工具
- 后端：FastAPI
- 前端：Vue3 + TypeScript（Agent 执行过程可视化）

**对应知识点**：
- Agent：ReAct 模式、工具调用、规划、记忆
- 多 Agent：角色设计、通信协议、协作模式、冲突解决
- LangGraph：状态管理、节点/边、循环、条件分支
- 错误处理：重试机制、超时、降级、人工介入

**验收标准**：
- Agent 能自主规划并执行复杂任务（至少 5 步）
- 支持至少 5 种工具调用
- 多 Agent 协作（至少 3 个角色）
- 执行过程可视化（思考/行动/观察）
- 错误自动恢复（重试至少 3 次）
- 人工确认机制（高风险操作）
- 任务完成率 > 80%

---

### 类型6：前端工程化项目

**典型项目**：UI 组件库、脚手架工具、Monorepo 管理系统、低代码平台

**核心功能模块**：
- 组件开发（基础组件 + 业务组件）
- 组件文档（Storybook / 自建文档站）
- 组件测试（单元测试 + 视觉回归）
- 构建与发布（构建配置、版本管理、npm 发布）
- Monorepo 管理（pnpm workspace + Turborepo）
- CI/CD（自动化测试、构建、发布）
- 代码规范（ESLint + Prettier + Stylelint + Husky）

**技术栈**：
- 框架：Vue3 + TypeScript
- 构建：Vite + Rollup
- 测试：Vitest + Vue Test Utils + Playwright
- 文档：VitePress / Storybook
- Monorepo：pnpm workspace + Changesets
- CI/CD：GitHub Actions

**对应知识点**：
- 组件设计：组件封装原则、Props 设计、事件设计、插槽、v-model
- 工程化：构建配置、代码分割、Tree Shaking、按需引入
- 测试：单元测试、组件测试、E2E 测试、测试覆盖率
- 发布：语义化版本、变更日志、npm 发布、CDN 部署

**验收标准**：
- 至少 10 个高质量组件
- 完整的组件文档和示例
- 单元测试覆盖率 > 80%
- 支持按需引入和全量引入
- npm 包发布流程
- CI/CD 自动化
- 完整的代码规范和提交规范

---

### 类型7：高并发系统

**典型项目**：秒杀系统、票务抢购、弹幕/IM、短链服务、热点榜单

**核心功能模块**：
- 热点隔离（缓存预热 + 本地缓存 + 布隆过滤器）
- 异步削峰（消息队列排队、结果异步通知）
- 库存扣减（防超卖、幂等、预扣与回补）
- 限流熔断（网关层 + 服务层双层）
- 分布式锁（锁粒度、续期、惊群）
- 压测与容量评估（基线、瓶颈定位、扩容方案）

**技术栈**：
- 服务：Spring Boot / Go（选一个，别混）
- 缓存：Redis（String/Hash + Lua 原子扣减）
- 消息：RocketMQ / Kafka（顺序消息、事务消息按需）
- 存储：MySQL + ShardingSphere（分库分表可选）
- 治理：Sentinel（限流熔断）+ Prometheus + Grafana
- 压测：wrk / JMeter

**对应知识点**：
- 缓存：穿透 / 击穿 / 雪崩、一致性、过期策略
- 并发：乐观锁 vs 悲观锁、CAS、库存扣减的原子性
- 消息：幂等消费、顺序性、堆积处理、死信
- 稳定性：限流算法（令牌桶/漏桶/滑动窗口）、降级预案

**验收标准**：
- 1000 并发抢 100 件库存，**超卖 0 件**（脚本断言最终库存 = 0、订单数 = 100）
- 缓存命中率 ≥ 90%（`redis-cli info stats` 取 keyspace_hits/misses）
- 限流触发可观测：压测超出阈值时返回 429 且指标有记录
- 单机 QPS 有基线数字（如 `wrk -t4 -c200 -d60s` → 3k QPS，P99 < 300ms）
- 故障演练：手动停 Redis，服务降级而非雪崩（有日志与兜底返回）

### 类型8：全栈 + AI 融合

**典型项目**：AI 笔记助手、智能客服工作台、AI 简历优化平台、AI 数据分析台

**核心功能模块**：
- 用户体系与鉴权（注册登录、角色、会话）
- 业务 CRUD（笔记/工单/简历等主数据）
- AI 能力接入（对话、摘要、改写，全部流式）
- 配额与成本（按用户计量、超限拒绝、成本看板）
- 内容安全（输入过滤、输出审核、敏感词）
- 异步长任务（长文生成、批量处理）
- 可观测性（首 token 延迟、token 消耗、失败率）

**技术栈**：
- 前端：Vue3 + TypeScript + SSE 流式渲染
- 后端：FastAPI / Spring Boot（二选一）
- 存储：PostgreSQL（业务）+ Redis（会话/配额）+ 向量库（如需要 RAG）
- AI：LLM SDK（OpenAI 兼容）+ Prompt 版本管理
- 异步：Celery / BullMQ（长任务）
- 部署：Docker Compose（先跑通再谈 K8s）

**对应知识点**：
- 流式：SSE vs WebSocket、断线重连、增量渲染
- AI 工程：Prompt 版本化、上下文裁剪、重试与降级模型
- 成本：token 计量、按用户配额、缓存命中降本
- 安全：提示注入防护、输出过滤、越权访问

**验收标准**：
- 未登录访问受保护接口返回 401；越权访问他人资源返回 403
- 首 token < 1.5s，整段 P95 < 3s（取 SSE 首帧与服务端日志）
- 配额耗尽返回明确错误码（如 429 `quota_exceeded`），不静默失败
- 单次问答的 token 成本可在日志/看板查到
- 客户端中途断开，服务端捕获取消异常，无栈溢出刷屏
- 长任务走异步：接口立即返回 task_id，可查询进度

> 类型7、8 都是 6–8 周量级。若用户只给 4 周，须降级：类型7 → "单机版秒杀（不做分库分表）"，类型8 → "AI 功能单点接入（不做配额与看板）"。

## 四、项目方案生成检查清单

- [ ] 项目类型明确，难度与用户目标匹配
- [ ] 需求文档有功能需求表和非功能需求
- [ ] 技术选型有理由，不堆砌技术
- [ ] 架构设计有系统架构图、目录结构、数据库设计
- [ ] 分步实现分阶段，每阶段有独立可运行产物
- [ ] 每个实现步骤标注对应知识库笔记
- [ ] 验收标准可量化、可检查
- [ ] 扩展方向有具体的技术升级路径
- [ ] 项目周期合理（与难度匹配）
- [ ] 涉及的知识点在用户学习路线范围内
