# project-based-learning 常见问题解答

> 使用项目驱动学习生成器时的常见问题和解答。

---

## Q1：项目方案生成后，我需要自己写代码吗？还是会生成完整代码？

**A**：项目方案包含**分步实现教程**，每一步有：
- 具体的实现步骤（做什么）
- 核心代码片段（关键部分的代码，带注释）
- 对应知识库笔记（`[[]]` 双链）
- 本阶段验收点（怎么确认这步完成了）

但不会生成完整的项目代码，需要你跟着教程一步步实现。这是刻意的设计：
- **跟着写**比**直接复制**学习效果好 10 倍
- 遇到问题自己排查，是项目学习的重要部分
- 每阶段有验收点，可以确认自己理解了

如果你在某一步卡住了，可以用 `bug-troubleshooter` Skill 排查问题，或者用 `code-practice-generator` 生成该步骤的完整代码参考。

## Q2：一个项目方案需要多长时间完成？难度怎么选？

**A**：根据项目类型和难度：
- **全栈 CRUD 应用（⭐⭐）**：2-3 周，适合入门级学习者
- **全栈业务系统（⭐⭐⭐）**：4-6 周，适合进阶级学习者
- **微服务系统（⭐⭐⭐⭐）**：6-8 周，适合高级学习者
- **AI RAG 应用（⭐⭐⭐）**：3-4 周，适合有 Python 基础的学习者
- **AI Agent 应用（⭐⭐⭐⭐）**：4-6 周，适合有 AI 基础的学习者
- **高并发系统（⭐⭐⭐⭐）**：6-8 周，适合有后端基础的学习者

建议从比自己当前水平高半级的项目开始，既有挑战又不会完全做不出来。如果项目太难，可以先做 `code-practice-generator` 的练习项目打基础。

## Q3：项目方案中的技术选型可以改吗？我想用其他技术栈

**A**：当然可以。有两种方式：
1. **生成前指定**：在需求描述中明确技术栈，如"用 Next.js + Go + PostgreSQL 做一个博客系统"
2. **生成后修改**：生成方案后，替换技术选型部分，调整架构设计和实现教程

技术选型的核心原则是：
- 选择你**想学**的技术，而不是你已经熟练的技术
- 技术之间要**兼容**（如 Vue3 配 Spring Boot，React 配 Node.js）
- 考虑**学习曲线**（不要同时学 3 个新技术）

如果你不确定选什么技术，可以描述项目需求，让 Skill 推荐技术栈并说明理由。

## Q4：项目做到一半发现方案有问题怎么办？

**A**：项目方案是指导，不是圣旨。遇到问题可以调整：
1. **需求变更**：如果发现某个功能太复杂或不需要，可以简化或砍掉
2. **技术问题**：如果某个技术太难或不适合，可以替换（如把微服务改回单体）
3. **时间不足**：如果时间不够，可以先完成核心功能，扩展功能后续再做
4. **架构调整**：如果发现架构设计有问题，可以重构（这是宝贵的学习经验）

调整后建议更新项目方案文档，记录变更原因和决策过程。项目学习的价值不仅在于完成项目，更在于过程中的决策和思考。

---

## Q5：项目完成后怎么检验学习效果？

**A**：通过以下方式检验：
1. **验收标准**：项目方案中有明确的验收清单（功能/性能/代码质量/部署），逐项核对
2. **演示能力**：能向别人演示项目功能，解释技术选型和架构设计
3. **问题排查**：能独立排查项目中的常见问题，理解错误原因
4. **扩展能力**：能在项目基础上添加新功能，或替换某个技术组件
5. **知识输出**：能写出项目总结文章，或给别人讲解项目中的技术点

也可以用 `interview-prep-coach` Skill 模拟面试，检验项目经验的表达能力。

## Q6：可以基于我现有的项目扩展吗？还是必须从零开始？

**A**：两种方式都支持：
1. **从零开始**：生成完整的项目方案，从需求到部署
2. **基于现有项目扩展**：描述现有项目的技术栈和已实现功能，生成扩展方案
   - 扩展需求说明
   - 对现有架构的影响分析
   - 具体实现步骤（修改哪些文件、新增哪些文件）
   - 兼容性和迁移说明
   - 扩展后的验收标准

基于现有项目扩展的优势是可以复用已有代码，专注于学习新技术点。建议有一定基础后尝试这种方式。

## Q7：项目方案中的「分步实现教程」每步都对应知识库笔记，这个联动是怎么工作的？

**A**：联动机制是：
1. **生成时标注**：生成项目方案时，每一步实现教程中标注对应的知识库笔记，如"对应 [[Spring Boot 入门]]、[[JPA 基础]]"
2. **学习时查阅**：做项目时，遇到不熟悉的概念，点击双链直接跳转到知识库笔记学习
3. **完成后更新**：项目完成后，在知识库笔记中添加项目引用，形成"理论→实践→理论"的闭环
4. **复习时关联**：用 `knowledge-review-spaced` 复习笔记时，可以关联项目实践，加深记忆

这样做项目的过程也是系统复习知识库的过程，项目完成后，相关知识点也都复习了一遍。
