## 1. 六篇的内在逻辑

六篇按"一个人真实改变命运的行动顺序"排列，形成闭环：

```
决定方向 → 学会能力 → 做出作品 → 拿到工作 → 长期向上 → 全程兜底
（决策）  （学习）   （项目）   （求职）   （发展）    （风控）
```

关键认知：**项目实战独立成篇且置于学习与求职之间**。这是普通背景者最容易缺的一环——学了知识点不等于能交付产品，而能交付产品才是求职硬通货。

## 2. 每篇章节清单与必含要素

### 第一篇 决策与准备期
必含：
- 赛道对比与结论（引用 02-track-selection）
- 结合身份的优劣势分析（手里有几张牌 / 要面对几个现实）
- 破局逻辑（用什么替代学历和工作经验，如"用可验证项目成果同时替代二者"）
- 启动前准备：经济储备（存够几个月）、身体健康基线、社保/保险/合同常识、必要的硬件与预算
- 设硬截止日期（防止无限准备）

### 第二篇 系统学习期
必含（详见 04-learning-roadmap）：
- 分阶段学习路线（每阶段：目标/知识点 P0-P2/重点学什么与可跳过什么/验收标准/配套项目）
- 每日时间分配（区分全职/在职/在校）
- 学习方法与工具（费曼、刻意练习、间隔重复、AI 辅助）
- 计算机基础补课策略（非科班怎么补、编程与基础的时间配比）
- 效率陷阱与心态管理（假学习、只输入不输出、频繁换方向、完美主义、无限准备）

### 第三篇 项目实战期（核心，详见 05-project-playbook）
必含：
- 项目认知误区
- 项目规划（灵感来源、难度分级 L1-L4、求职项目组合）
- 从 0 到 1 的开发 9 步流程
- 2-3 个完整项目实现指南（架构图/分阶段任务/难点/面试讲法）
- 工程化实践、AI 辅助开发、独立解决问题能力
- 项目包装与求职衔接、从教程到独立的四阶段进阶

### 第四篇 求职冲刺期（详见 06-job-hunting）
必含：
- 求职渠道优先级、对其最友好的公司类型与路径
- 作品集与 GitHub、简历（STAR-R、学历放底部）
- 投递节奏与数量、面试结构与权重、项目讲法
- 薪资预期与谈判、offer 评估、合同/社保/试用期注意事项
- gap 期与转行原因的标准解释话术

### 第五篇 长期发展期（详见 07-longterm-development）
必含：
- 能力体系阶段模型、薪资与职位里程碑
- 系统设计能力、技术深度 vs 广度、细分领域选择
- 跳槽节奏与公司评估、向上管理与晋升
- 地区选择与定居、远程工作/数字游民、被动收入
- 35 岁危机的根本解法（30 岁前建非工资收入）

### 第六篇 风险应对（Plan B）
必含：每个阶段的失败情景 + 诊断 + 备选路径：
- 学习期：进度慢/方向不对/学不进去怎么办
- 求职期：长期拿不到 offer 怎么办（先入行再跃迁，不无限期全职学）
- 长期：风口过去/被裁/不喜欢这行/经济断裂怎么办
- 8 条左右贯穿全文的风险提示

## 3. 篇与章的固定外观（篇篇如此、章章如此）

光有章节清单不够，成品手册的"手感"来自统一的篇/章外观，完整模板见 `12-document-anatomy.md`：

### 3.1 每篇三件套

1. **篇首导言（引用块）**：本篇解决什么问题 → 什么状态的人必须认真读 → 为什么不能跳过某关键准备
2. **若干章**，章章带固定微结构（见 3.2）
3. **篇小结**：编号回顾本篇 6-8 条结论 → "X 时间后你会从【旧状态】变成【新状态】"对照 → 承认不容易但值得 → 一句话引出下一篇

### 3.2 每章八零件（缺一补一）

章标题（带🔴P0/🟡P1/🟢P2 与白话副标题）→ 开场大白话问题 → 结构化主体（表格+来源行/完整代码）→ 核心结论或关键认知加粗 → 红线/提示引用块 → ❌误区+真相对（3-4 个）→ 📌本章小结（200-400 字浓缩）→ 📋本章行动清单（5-8 条可勾选项）。

### 3.3 篇前部件不可省

六篇之前必须先有"写在前面"（情绪定调三句话）和"能力体系总览"（阶段总表+维度优先级矩阵+核心增量表+阅读导航图四件套），它们是全书导航地图，不是装饰；六篇之后按固定顺序收尾（风险提示→结语→参考文献→尾部导航→免责声明→文档信息）。

## 4. 裁剪规则（按身份删改，不硬套）

| 身份 | 保留重点 | 可弱化/删除 |
|------|---------|------------|
| 在校学生 | 补基础、实习、长线时间线、竞赛开源 | 裸辞经济准备、gap 解释 |
| 全职转行（主场景） | 六篇全保留，强化硬截止、项目、经济储备、Plan B | 学年规划、实习 |
| 在职转行 | 学习期改为碎片化方案、求职改为骑驴找马 | 裸辞、全职每日安排 |
| 用户明确排除的领域 | —— | 直接删（如用户说家庭已处理好，删婚恋家庭章） |

裁剪后要在开头说明"本版针对你的身份做了哪些取舍"。

---

## 5. 篇间衔接与交叉引用

- 每篇开头写"本篇解决什么、上一篇给了你什么、学完进入下一篇"
- 跨篇相关概念用 Obsidian `[[]]` 双链互链（如学习篇的"配套项目"链到项目篇）
- 同一主题只在一处详述，他处概述 + 链接，避免重复和前后不一致

## 6. 完整目录示例（六篇四十七章版，可增删）

```
Frontmatter（12 字段）
写在前面：给正在犹豫的你
能力体系总览（阶段能力地图 + 维度优先级矩阵 + 增量体系表 + 阅读导航图）
第一篇 决策与准备期（第1-8章，含篇首导言与篇小结）
第二篇 系统学习期（第9-17章）
第三篇 项目实战期（第18-29章，篇幅最重）
第四篇 求职冲刺期（第30-35章）
第五篇 长期发展期（第36-44章）
第六篇 风险应对（第45-47章）
风险提示（8 条）/ 结语 / 参考文献 / 尾部导航（三段式）/ 免责声明 / 文档信息
```

> 章节数不是标准，标准是"每篇必含要素"是否齐全、逻辑是否贴合该用户。可直接填充的骨架见 `../assets/document-template.md`。
