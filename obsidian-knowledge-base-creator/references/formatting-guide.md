# 排版规范

> 统一的排版规范确保知识库视觉整洁、层次清晰、可读性强。所有文档必须遵循本规范。
>
> **v5.0 更新**：基于 171 篇文档实战验证，新增代码块闭合铁律和标题级别严格性规范，解决 Obsidian 渲染中内容被吞、标题混乱等问题。
>
> **v5.1 更新**：基于 14 篇文档、500+ 异常 H2 的标题修复实战，新增 H2 数量阈值规范、标题文本代码模式禁止、标题修复决策流程，明确"代码内容必须包裹进代码块，绝不能降级为标题"的铁律。

---

## 一、标题层级

### 层级规范（严格执行）

| 级别 | 数量 | 用途 | 命名格式 | 示例 |
|------|------|------|---------|------|
| `#` H1 | **恰好 1 个** | 文档主标题 | `# {标题}` | `# FastAPI 路由与依赖注入` |
| `##` H2 | **8-15 个**（>25需排查代码暴露） | 主要模块 | `## {序号}、{模块名}` | `## 一、概述` |
| `###` H3 | 约 15-25 个 | 模块内小节 | `### {序号}.{子序号} {名称}` | `### 1.1 什么是路由` |
| `####` H4 | 少量 | 必要时使用 | `#### {名称}` | `#### 特殊场景` |
| `#####`+ | **禁止** | - | - | - |

> **代码模式禁止**：H2/H3 标题文本中禁止出现代码模式——文件名（`requirements.txt`）、命令行（`pip install`）、参数（`--workers`）、注释（`# 安装依赖`）、ASCII 树字符（`├──`）。如出现，说明代码块标记损坏，需将代码内容包裹进代码块，而非降级标题。

### ⚠️ 标题级别铁律（v5.0 新增，v5.1 扩展）

1. **每篇文档恰好 1 个 H1**——H1 是文档主标题，不能有多个
2. **禁止级别跳跃**——H2 不能直接跳到 H4，必须经过 H3
3. **代码注释不能暴露为标题**——`# 注释` 必须在代码块内，不能出现在正文
4. **标题后不加标点符号**
5. **标题与正文之间空一行**
6. **H2 数量应在合理范围**——标准文档 8-15 个，超过 25 需排查代码暴露，超过 40 几乎确定是代码块标记大面积损坏
7. **H2/H3 标题文本中禁止出现代码模式**——文件名、命令行、参数行、注释、ASCII 树字符不得作为标题文本；如出现，应包裹进代码块而非降级标题
8. **MOC/枢纽/系统梳理类文档不受 H2 数量限制**——emoji 开头的 H2（如 `## 📚 Python 基础`）或 `1. 概述` 格式的 H2 在此类文档中属正常

### 标题命名
- 一级标题：`# {文档标题}`（与 Frontmatter title 一致）
- 二级标题：`## {序号}、{模块名}`（如 `## 一、概述`）
- 三级标题：`### {序号}.{子序号} {小节名}`（如 `### 1.1 什么是 XXX`）

### 示例
```markdown
# Vue3 组合式 API

## 一、概述

### 1.1 什么是组合式 API

组合式 API 是 Vue3 引入的新特性...

## 二、原理

### 2.1 响应式原理

Vue3 使用 Proxy 实现响应式...
```

### 标题修复决策流程

当文档出现标题混乱时，按以下 5 步流程处理。本流程为**诊断决策流程（5步）**，用于判断问题类型；具体**手动执行步骤（4步）**见 `references/quality-assurance-and-repair.md` 第4.8节「手动修复方法」。

**第一步：检查 H2 数量是否异常（>25）**
- H2 ≤ 15：正常，无需处理
- H2 在 15-25：可接受，抽查标题文本
- H2 > 25：进入第二步，大概率存在代码暴露
- H2 > 40：几乎确定是代码块标记大面积损坏

**第二步：检查代码块是否闭合**
- 运行代码块平衡检查，确认 0 个未闭合代码块
- 检查结束标记是否为纯 ```（不带语言名）
- 如代码块有问题，**必须先修复代码块**，再继续后续步骤

**第三步：判断异常标题是代码内容还是子章节标题**
- 标题文本含代码模式（注释/命令/文件名/参数/ASCII树/模板）→ 代码内容
- 标题文本是描述性小节名（如"安装依赖""配置文件"）→ 子章节标题
- 标题是 `=== xxx ===` 格式 → 装饰性分隔线

**第四步：按类型处理**
- 代码内容 → **包裹进代码块**（绝不能降级为标题）
- 子章节标题 → 逐级降级（H2→H3，H3→H4），保持层级连续
- 装饰性分隔线 → 转为加粗普通文本 `**=== xxx ===**` 或删除

**第五步：验证修复结果**
- H2 数量回到 8-15 合理范围
- 标题文本无代码模式
- 无级别跳跃
- Obsidian 大纲面板结构清晰

> **修复时必须遵守5条铁律**（详细说明见 `references/quality-assurance-and-repair.md` 第4.4节）：
> 1. 代码内容必须包裹进代码块，绝不能降级为任何级别标题
> 2. 子章节标题才降级，保持层级连续
> 3. 装饰性分隔线转为加粗普通文本
> 4. 只改格式不改内容
> 5. MOC/枢纽/系统梳理类文档除外

### 常见错误

| 错误 | 正确做法 |
|------|---------|
| 多个 H1 大标题 | 仅保留 1 个 H1，其余降级为 H2 |
| H2 直接跳到 H4 | 插入 H3 中间层级，或将 H4 降级为 H3 |
| 代码注释 `# 注释` 暴露为 H1 | 将注释包裹进代码块 |
| 章节标题用 H1 | 主要模块用 H2（##） |
| **H2 数量异常多（>25）** | **先修复代码块标记，再将暴露的代码内容包裹进代码块** |
| **配置文件名/命令行显示为标题** | **文件名用行内代码，命令行/文件内容包裹进代码块** |
| **装饰性分隔线 `=== xxx ===` 显示为标题** | **转为加粗普通文本 `**=== xxx ===**` 或直接删除** |

## 二、段落与空行

### 段落规范
- 段落之间空一行
- 段落首行不缩进
- 单段不超过 5 行，超过则拆分
- 重要内容用引用块或加粗突出

### 空行规范
- 标题与正文之间：1 行空行
- 段落之间：1 行空行
- 代码块前后：1 行空行
- 表格前后：1 行空行
- 列表前后：1 行空行
- 分割线 `---` 前后：1 行空行

---

## 三、列表

### 无序列表
- 使用 `-` 作为列表标记（不使用 `*` 或 `+`）
- 列表项之间不空行
- 嵌套列表缩进 2 个空格
- 列表项不超过 3 层嵌套
- 列表项末尾不加句号（除非是完整句子）

```markdown
- 核心特性
  - 响应式数据
  - 组件化开发
  - 虚拟 DOM
- 适用场景
  - 单页应用
  - 中后台系统
```

### 有序列表
- 使用 `1.` `2.` `3.` 作为标记
- 用于步骤、流程、优先级排序
- 嵌套列表缩进 2 个空格

```markdown
1. 安装依赖
2. 配置环境
3. 编写代码
4. 测试运行
```

### 任务列表
- 使用 `- [ ]` 和 `- [x]` 标记
- 用于检查清单、待办事项

```markdown
- [x] 环境搭建
- [x] 核心功能
- [ ] 性能优化
- [ ] 文档完善
```

## 四、表格

### 表格规范
- 表头加粗（Obsidian 自动渲染）
- 列对齐：文字左对齐，数字右对齐，操作居中
- 表格内容简洁，单元格不超过 3 行
- 表格前有引导文字，说明表格内容
- 大表格拆分为多个小表格

### 对齐方式
```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|-------:|
| 内容   | 内容 | 内容   |
```

### 常用表格类型

#### 对比表格
```markdown
| 维度 | Vue3 | React |
|------|------|-------|
| 学习曲线 | 平缓 | 陡峭 |
| 响应式 | Proxy | setState |
| 生态 | 完善 | 丰富 |
| 性能 | 优秀 | 优秀 |
```

#### 参数表格
```markdown
| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| name | string | - | 组件名称 |
| age | number | 18 | 年龄 |
| active | boolean | true | 是否激活 |
```

#### 错误排查表格
```markdown
| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| EADDRINUSE | 端口被占用 | 更换端口或杀死进程 |
| ENOENT | 文件不存在 | 检查文件路径 |
| ETIMEDOUT | 连接超时 | 检查网络和防火墙 |
```

## 五、代码块

### ⚠️ 代码块闭合铁律（v5.0 新增，最重要）

基于 171 篇文档实战验证，代码块标记错误是导致 Obsidian 渲染问题（内容被吞、流程图报错）的最主要原因。必须严格遵守：

| 规则 | 说明 | 错误示例 | 正确示例 |
|------|------|---------|---------|
| **开头标记可带语言名** | 用于语法高亮和 Mermaid 渲染 | - | ```python |
| **结束标记必须是纯 ```** | **绝对不能带语言名** | ```python | ``` |
| **Mermaid 必须用 ```mermaid** | 否则不渲染图表 | ``` | ```mermaid |
| **代码内含 ``` 时外层用 4 反引号** | 避免内部标记被误认为结束 | ```python | ````python |
| **禁止连续两个 ```** | 第二个会开启空代码块 | ```<br>``` | ``` |
| **开闭标记反引号数量一致** | 3对3，4对4 | ````python<br>``` | ````python<br>```` |

### 代码块规范
- 必须标注语言类型（```python、```java、```bash、```javascript）
- 代码块前后空一行
- 代码缩进统一（Python 4 空格，其他 2 空格）
- 关键代码配注释
- 长代码分段展示，每段配说明
- 输出结果用 ```text 或 ```bash 标注

### 语言标注
| 语言 | 标注 | 示例 |
|------|------|------|
| JavaScript | ```javascript | ```javascript |
| TypeScript | ```typescript | ```typescript |
| Python | ```python | ```python |
| Java | ```java | ```java |
| Bash | ```bash | ```bash |
| SQL | ```sql | ```sql |
| JSON | ```json | ```json |
| YAML | ```yaml | ```yaml |
| HTML | ```html | ```html |
| CSS | ```css | ```css |
| Vue | ```vue | ```vue |
| Mermaid | ```mermaid | ```mermaid |
| 纯文本 | ```text | ```text |

### 代码示例
```javascript
// 计算数组总和
function sum(arr) {
  return arr.reduce((acc, cur) => acc + cur, 0);
}

const result = sum([1, 2, 3, 4, 5]);
console.log(result); // 15
```

### 嵌套代码块（代码内含 ```）

当 Python/JS 代码中包含 Markdown 模板字符串时，外层必须用 4 反引号：

````python
# 正确：外层用 4 反引号
prompt = """
```markdown
# 分析报告
## 结论
内容
```
"""
print(prompt)
````

```python
# 错误：外层用 3 反引号，内部的 ``` 会被误认为代码块结束
prompt = """
```markdown
# 分析报告
```
"""
```

### 行内代码
- 使用单个反引号 `` ` `` 包裹
- 用于变量名、函数名、命令、文件名
- 行内代码不换行

示例：使用 `useState` Hook 管理状态，运行 `npm install` 安装依赖。

## 六、引用块

### 引用块规范
- 使用 `>` 标记
- 用于重要提示、警告、最佳实践、补充说明
- 引用块前空一行
- 引用块内可以包含列表、代码、加粗

### 引用块类型

#### 提示
```markdown
> 💡 **提示**：这里是实用技巧或补充说明。
```

#### 警告
```markdown
> ⚠️ **注意**：这里是需要特别注意的风险或坑点。
```

#### 最佳实践
```markdown
> ✅ **最佳实践**：这里是推荐的做法或设计模式。
```

#### 禁止
```markdown
> ❌ **禁止**：这里是不推荐或错误的做法。
```

#### 引用
```markdown
> 这里是引用的内容或重要结论。
```

### 多层引用
```markdown
> 第一层引用
> > 第二层引用
> > > 第三层引用
```

## 七、强调与格式

### 加粗
- 使用 `**文字**` 标记
- 用于关键词、重要结论、术语首次出现
- 一段内不超过 3 处加粗

示例：**响应式**是 Vue3 的核心特性，使用 **Proxy** 实现。

### 斜体
- 使用 `*文字*` 标记
- 用于强调、术语、书名
- 避免与加粗混用

### 删除线
- 使用 `~~文字~~` 标记
- 用于已废弃的内容、错误的做法
- 必须配合说明为什么废弃

### 高亮
- 使用 `==文字==` 标记（需 Obsidian 插件支持）
- 用于特别重要的内容
- 谨慎使用，一篇不超过 5 处

## 八、链接与引用

### 内部链接（双链）
- 使用 `[[文档名]]` 格式
- 可加别名：`[[文档名|显示文字]]`
- 可加锚点：`[[文档名#标题]]`
- 链接到当前文档的标题：`[[#标题]]`

示例：详见 [[Vue3 知识点系统梳理_优化版|Vue3 核心笔记]] 的 [[Vue3 知识点系统梳理_优化版#响应式原理|响应式原理]] 章节。

### 外部链接
- 使用 `[显示文字](URL)` 格式
- 必须是完整 URL（含 https://）
- 外部链接后加图标说明：`[文档](https://example.com) 🔗`

示例：[Vue3 官方文档](https://vuejs.org) 🔗

### 图片
- 使用 `![alt](图片路径)` 格式
- 图片放在 `assets/` 目录
- 图片前有说明文字
- 图片大小适中，不超过 2MB

## 九、分割线

- 使用 `---` 标记
- 用于大模块之间的分隔
- 分割线前后各空一行
- 一篇文档不超过 10 个分割线

```markdown
## 一、概述

内容...

---

## 二、原理

内容...
```

## 十、特殊符号

### 图标使用
| 图标 | 含义 | 使用场景 |
|------|------|---------|
| 📌 | 重点 | 重要结论、核心概念 |
| 💡 | 提示 | 实用技巧、补充说明 |
| ⚠️ | 警告 | 风险、坑点、注意事项 |
| ✅ | 正确 | 最佳实践、推荐做法 |

| 🔗 | 链接 | 外部链接 |
| 📖 | 参考 | 延伸阅读、参考资料 |
| 🚀 | 进阶 | 高级特性、深入学习 |
| 🎯 | 目标 | 学习目标、验收标准 |

### 箭头符号
- 用于流程、关系、路径：`→` `←` `↑` `↓` `↔`
- 用于递进：`➡️` `⬅️`
- 避免过度使用，保持简洁
