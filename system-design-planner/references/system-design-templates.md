## 典型系统设计模板

### 模板1：电商秒杀系统

**核心难点**：高并发读、高并发写、防超卖、防刷、限流

**架构要点**：
- 前端：按钮置灰、倒计时、静态资源 CDN
- 接入层：Nginx 限流、WAF 防刷、验证码
- 应用层：库存预扣（Redis Lua）、请求削峰（消息队列）、异步下单
- 数据层：Redis（库存/分布式锁）、MySQL（订单/库存最终一致）、Binlog 同步
- 核心流程：秒杀请求 → 限流 → 资格校验 → Redis 库存预扣 → 发送MQ → 消费者创建订单 → 支付 → 库存扣减

**关键技术**：
- Redis Lua 脚本保证库存扣减原子性
- 消息队列异步下单，削峰填谷
- 分布式锁防重复下单
- 令牌桶限流
- 热点数据多级缓存（本地缓存 + Redis）

### 模板2：社交 Feed 流

**核心难点**：Feed 生成、推送 vs 拉取、热点用户、排序、扩展性

**架构要点**：
- 写扩散（推模式）：用户发消息 → 写入所有粉丝的收件箱 → 粉丝直接读
- 读扩散（拉模式）：用户读 Feed → 拉取所有关注者的消息 → 合并排序
- 混合模式：普通用户推模式，大V用户拉模式
- 存储：Feed 内容存数据库，Feed ID 列表存 Redis（ZSet/Timeline）
- 排序：按时间倒序 / 兴趣排序（机器学习）

**关键技术**：
- Redis ZSet 存储 Feed Timeline
- 异步推送（消息队列）
- 大V特殊处理（拉模式）
- 分页（游标分页，不用 offset）
- 缓存热门 Feed

### 模板3：即时通讯系统

**核心难点**：长连接、消息可靠性、消息顺序、群聊、离线消息

**架构要点**：
- 接入层：WebSocket 长连接、连接路由（用户在哪个机器）
- 消息层：消息存储、消息同步（单聊/群聊）、ACK 机制
- 存储：消息存数据库（分库分表）、未读数存 Redis
- 核心流程：发消息 → 写入存储 → 推送给在线用户（WebSocket） → 离线用户存未读 → 上线后同步

**关键技术**：
- WebSocket 长连接（Netty/Socket.IO）
- 消息 ID 生成（雪花算法，保证有序）
- 消息 ACK 机制（至少一次 + 幂等）
- 群聊扩散写（写群成员的收件箱）
- 离线消息同步（增量同步，基于最后同步 ID）

### 模板4：RAG 知识库系统

**核心难点**：文档处理、检索质量、生成质量、评估、扩展性

**架构要点**：
- 文档处理：解析（PDF/Word/Markdown）→ 切分（Chunking）→ 向量化（Embedding）→ 存储（向量数据库）
- 检索：查询改写 → 多路召回（向量 + BM25 + 知识图谱）→ 重排序（Reranker）→ 上下文组装
- 生成：Prompt 组装 → LLM 调用（流式）→ 引用标注 → 结果返回
- 评估：检索评估（召回率/精确率）、生成评估（相关性/准确性/幻觉率）
- 存储：向量数据库（Milvus/Chroma）、关系数据库（文档/用户/反馈）、缓存（Redis）

**关键技术**：
- 混合检索（向量 + 关键词）
- Reranker 重排序（BGE-Reranker/Cohere Rerank）
- 查询改写（HyDE/多查询）
- 上下文窗口管理（动态选择 Chunk 数量）
- 引用溯源（Chunk ID → 文档 → 页码）

## 容量估算公式速查

| 指标 | 公式 | 示例 |
|------|------|------|
| 日均 QPS | DAU × 日均请求数 / 86400 | 100万 × 10 / 86400 ≈ 116 QPS |
| 峰值 QPS | 日均 QPS × 峰值系数（3-5） | 116 × 5 ≈ 580 QPS |
| 日存储增量 | 日新增记录数 × 单条大小 × 副本数 | 100万 × 1KB × 3 = 3GB/天 |
| 总存储 | 日增量 × 保留天数 × 冗余系数（1.5） | 3GB × 365 × 1.5 ≈ 1.6TB |
| 带宽 | 峰值 QPS × 平均响应大小 × 8 | 580 × 2KB × 8 ≈ 9.3 Mbps |
| 应用服务器数 | 峰值 QPS / 单台承载 × 冗余（1.5） | 580 / 200 × 1.5 ≈ 5 台 |
| 缓存大小 | 热点数据量 × 缓存比例 × 副本数 | 100GB × 20% × 3 = 60GB |
| 数据库连接数 | 应用服务器数 × 每台连接数 | 5 × 50 = 250 |

## 系统设计面试答题结构

1. **需求澄清**（5分钟）：需要问面试官的 5 个问题（功能范围、用户规模、性能要求、一致性要求、约束条件）
2. **容量估算**（10分钟）：具体数字（DAU、QPS、存储、带宽、服务器数）
3. **高层设计**（10分钟）：架构图（分层 + 模块 + 数据流）
4. **核心组件详解**（15分钟）：3-5 个核心组件的设计细节
5. **深入讨论**（10分钟）：可能被追问的方向（扩展性、高可用、一致性、性能优化）
6. **瓶颈与优化**（5分钟）：识别瓶颈，给出优化方案
7. **总结**（2分钟）：方案要点回顾
