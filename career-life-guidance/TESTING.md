# 测试指南

> 本文档描述 career-life-guidance Skill 的测试方法。由于本Skill为纯文档型（doc-only），测试以验证输出质量、文档完整性和工作流程有效性为主。

## 测试概述

本Skill不包含可执行代码，测试分为以下几个层面：

1. **文档完整性测试** - 验证所有必需文档存在且内容完整
2. **工作流程测试** - 验证8步工作流程可执行且产出符合标准
3. **输出质量测试** - 验证生成的手册符合成品级标准
4. **参考文档有效性测试** - 验证12个参考文档内容准确、可操作
5. **迭代协议测试** - 验证多轮迭代流程可产出逐步深化的结果

## 工作流程测试

### 8步工作流程验证

| 步骤 | 测试方法 | 预期结果 |
|------|---------|---------|
| 1. 身份校准 | 给定模糊用户输入，检查是否主动询问8个字段 | 字段不完整时主动追问，不猜测 |
| 2. 赛道选择 | 给定2-3个方向，检查是否做对比取证 | 输出多维度对比表，给出推荐和理由 |
| 3. 搭建骨架 | 检查是否使用document-template.md | 六篇结构完整，固定套件齐全 |
| 4. 学习路线 | 检查是否有时间线和可执行计划 | 每日/每周/每月计划，资源推荐 |
| 5. 项目实战 | 检查项目数量和完整度 | 至少3个项目，每个包含完整实现指南 |
| 6. 求职发展 | 检查是否覆盖求职全流程 | 简历、面试、谈薪、入职、长期发展 |
| 7. 支撑维度 | 检查是否补齐7大维度 | 身体/心理/理财/社保/品牌/人脉/英语 |
| 8. 输出校验 | 检查是否按校验清单逐项检查 | 输出前完成所有校验项 |

### 测试用例

#### 用例1：普通一本学生职业规划

**输入**："我是普通一本计算机专业大三学生，帮我做职业规划"

**预期输出**：
- 主动询问：目标城市、目标薪资、技术偏好、实习经历、经济状况
- 身份校准完成后输出六篇手册
- 项目篇包含3个适合学生的项目
- 求职篇包含实习和校招策略

#### 用例2：零基础转行

**输入**："我是机械专业毕业2年，想转行程序员，零基础"

**预期输出**：
- 主动询问：年龄、城市、经济储备、可投入时间、目标方向
- 推荐适合零基础的方向（前端/测试/运维）
- 学习路线包含6个月全职或12个月在职计划
- 项目篇重点是能写进简历的转行项目
- 求职篇包含转行简历包装和面试话术

#### 用例3：35岁危机

**输入**："我35岁，做后端5年，担心35岁危机"

**预期输出**：
- 主动询问：城市、薪资、家庭状况、技术栈、晋升情况
- 第五篇重点深化35岁危机应对
- 第六篇重点深化风险预案和理财
- 包含技术专家/管理/架构师/独立开发/转行产品五个方向对比

## 输出质量测试

### 成品级标准检查（12项）

- [ ] **身份校准** - 8个身份字段已锁定，无猜测
- [ ] **六篇结构** - 决策/学习/项目/求职/发展/支撑，六篇齐全
- [ ] **项目篇幅** - 项目篇占全书25%-35%
- [ ] **项目数量** - 至少3个从易到难的完整项目
- [ ] **建议完整度** - 每个建议包含"为什么+怎么做+不做后果"
- [ ] **可执行密度** - 每1000字至少1个可执行动作
- [ ] **表格流程图** - 每章至少1张表格或流程图
- [ ] **写作风格** - 符合"前辈语气"配方，有温度不空洞
- [ ] **支撑维度** - 7大支撑维度齐全（身体/心理/理财/社保/品牌/人脉/英语）
- [ ] **风险预案** - 包含至少3种风险场景的应对方案
- [ ] **固定套件** - 写在前面/能力总览/篇小结/收尾套件/文档信息齐全
- [ ] **格式标准** - Obsidian双链、Frontmatter、流程图格式正确

### 量级标准检查

| 版本 | 字数 | 章节 | 表格 | 流程图 | 验收 |
|------|------|------|------|--------|------|
| 简版 | ≥2万字 | ≥15章 | ≥20 | ≥5 | 快速决策参考 |
| 标准版 | ≥5万字 | ≥30章 | ≥50 | ≥15 | 完整执行手册 |
| 完整版 | ≥10万字 | ≥50章 | ≥100 | ≥30 | 书籍级人生指南 |

## 参考文档有效性测试

### 内容准确性检查

| 检查项 | 方法 | 标准 |
|--------|------|------|
| 技术栈时效性 | 检查推荐的技术是否过时 | 主流技术，不推荐已淘汰技术 |
| 薪资数据合理性 | 检查薪资范围是否符合市场 | 基于真实市场行情，不夸大 |
| 学习时间可行性 | 检查学习计划是否可执行 | 符合正常人的学习节奏，不激进 |
| 项目难度梯度 | 检查项目从易到难是否合理 | 入门→进阶→高级，梯度清晰 |
| 求职策略实用性 | 检查简历/面试建议是否可操作 | 具体模板和话术，非空泛建议 |

### 交叉一致性检查

- SKILL.md中的工作流程与API.md中的工作流接口一致
- README.md中的文件结构与实际文件一致
- 各参考文档之间无矛盾内容
- CHANGELOG.md记录的变更与实际文件一致

## 迭代协议测试

### 多轮迭代验证

| 轮次 | 深化方向 | 验收标准 |
|------|---------|---------|
| 第1版 | 骨架完整 + 核心内容 | 六篇结构齐全，每篇有核心内容 |
| 第2版 | 项目实战深化 | 项目篇达到25%-35%篇幅，每个项目有完整实现指南 |

| 第4版 | 长期发展 + 风险预案 | 第五篇包含5年/10年规划，第六篇包含3+风险场景 |
| 第5版 | 整体润色 + 密度提升 | 每1000字≥1个可执行动作，格式标准化 |

## 回归测试

每次修改后必须运行：

1. 文档完整性检查（所有必需文档存在）
2. skill-optimizer审计（确保分数不下降）
3. 工作流程测试（用至少1个测试用例验证8步流程）
