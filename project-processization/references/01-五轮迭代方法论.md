# 五轮迭代方法论（从"能跑的项目"到"能学的指南"）

> 本文件是 SKILL.md 的深入参考，记录每一轮的目标、检查点、最容易漏掉的缺口，以及
> 判定"这块该 AI 做还是该学习者亲手做"的规则。所有数字类结论必须先用脚本取得。

## 第 0 步：探查与备份

目标：在不改动项目的前提下，搞清楚"AI 已经把项目做到哪一步"。

检查点：

1. 项目能否一键启动：是否有 `docker-compose.yml`、`.env.example`、`Dockerfile`。
2. 技术栈：后端语言/框架、前端框架、数据库/向量库/中间件、LLM 与 Embedding 来源。
3. 文档资产：`docs/`、开发指导、部署文档、架构图是否已存在。
4. 测试资产：`tests/` 下有多少文件、用例数、覆盖了哪些能力。
5. 备份原始 README：`cp README.md README_original.md`，作为零删减基准。

> 经验：很多项目"看起来全"，但**没有初始化 Git**。第 4 轮要补 Git 安全网。

## 第 1 轮：事实扫描

目标：让文档里所有规模数字都有同一个可信来源。

- 跑 `scan_project_facts.py --group-depth 2`，拿到：总量、`app/` 与 `tests/` 分层行数、
  每个测试文件的用例数、组件目录业务文件数、Docker 服务、依赖、`.env` 键名。
- 扫描器口径：**物理行数**（`splitlines`，空行计入）、自动排除依赖/缓存目录、
  组件数自动排除 `__init__.py`（包标记不是业务组件）。
- 扫描器不覆盖的（用例数据条数、配置常量、CLI 参数、接口路径），记入第 3 轮"待核对"。

## 第 2 轮：八章初稿

目标：产出两份文档——公开 README 增强（零删减、只补能力/用法/架构/限制）+ 仓库外的《从零到专家 AI 协作学习指南》。

八章固定结构：

1. **先搞懂代码怎么来的**：现状、"四步闭环"学习法（跑起来→读得懂→复现出→改得动）、AI vs 学习者分工图（Mermaid）。
2. **AI 已完成什么、如何利用**：能力清单表（文件/行数/验证方式/精读优先级）、"四步利用法"、可放心委托的场景、"讲代码" Prompt、三条红线。
3. **你必须亲手做的部分**：六大任务总览 + 详解 + 必须白板手写的核心算法清单。
4. **五阶段路线**：能力分层、阶段 0-5（每阶段周期/验收/练习/优先级）、基础补课对照表。
5. **手把手操作手册**：启动、上传文档、精读、补 golden QA、跑评测、复现算法、配置开关、部署、日常工具箱。
6. **AI 协作规范**：红线对照表、各阶段 AI 辅助比例。
7. **代码地图 + 文档导航**：目录树 + 模块职责、已有文档怎么用。
8. **终极验收清单**：从零基础到专家的可勾选 checklist。

## 第 3 轮：事实校准（最容易翻车的一轮）

目标：逐数字回源码核对，不留错误事实。

高频出错点（真实案例）：

- **测试用例数**：README 写"47 个"，实际用 `def test_` 数到 79 个。
- **golden QA 条数**：写"10 条"，实际 JSON 里 20 条，且字段有 7 个。
- **文件行数系统性偏小**：凭印象写的行数普遍比实际少 10%-20%。
- **组件计数**：把 `__init__.py` 算进去导致"路由 13 个"（实际业务 12 个）。
- **脚本参数漏写**：`run_eval` 支持 `--kb-id`、`--no-judge`，文档完全没提。
- **模型写死小版本**：写死 `DeepSeek-V3.2`，应写"V3 系列"避免过期。

规则：**宁可不写，也不写错**；易变内容写"系列/约数"。

## 第 4 轮：可执行性与全面性

补齐"零基础照着做会卡住"的环节（都有真实案例支撑）：

1. **前置环境清单**：Docker / WSL2 / Git / Python / Node 版本、验证命令、"何时才需要"；
   点明 Docker 方式不用单装语言运行时。
2. **Git 安全网**：项目无 `.git` 时，给 `init → commit 基线 → 每里程碑提交 → 回滚` 命令。
3. **评测真实参数与成本控制**：`--no-judge` 省 token、`--kb-id` 统一知识库、Embedding 缓存、调试期 3-5 条用例。
4. **日常工具箱**：VS Code 断点、Swagger 在线测接口（含 Bearer 鉴权）、F12 看 SSE、
   `npm run build` 的 `vue-tsc` 类型检查坑与 `build:no-check`。
5. **基础补课对照表**：Python/FastAPI/Vue3/工程基础"不会就补到什么程度"，强调边做边补。

## 第 5 轮：导航与回归校验

- 长文档（>800 行）**必须有折叠目录**，否则难以定位；用 `make_toc.py` 生成，不要手算锚点。
- 交叉引用（"见 X.Y 节"）与锚点用脚本/检索核对，确保目标真实存在。
- 跑三连校验：`validate_md.py`（结构）、`verify_zero_cut.py`（零删减）、
  `make_toc.py`（输出到 stdout 与现有目录对比）。

## "AI 做 / 学习者做"分工判定规则

判定标准一句话：**面试会不会考、工作中能不能复用。**

| 内容 | 可让 AI 做 | 学习者必须亲手做 |
|------|-----------|-----------------|
| 脚手架、CRUD、接线、配置 | 可以 | 读懂并能讲清数据流 |
| 核心算法（RRF/BM25/ReAct/切片） | 可读参考 | 白板手写、能手算小例子 |
| 评测用例 golden QA | 可起草 | 亲手补到 40-50 条、跑 ≥2 轮单变量实验 |
| 文档/博客 | 可润色 | 自己讲清"为什么这么选型" |
| 调试报错 | 可给方向 | 自己复现、定位堆栈、验证修复 |

各阶段 AI 辅助比例建议：初期约 60%（搭环境、读代码），中期降到 40%（自己写核心），
后期 20%（仅润色与查漏）。

## 常见缺口速查表

- [ ] 没有目录（TOC），长文档无法导航
- [ ] 规模数字没有统一来源，前后不一致
- [ ] 把 `__init__.py` 计作业务组件
- [ ] golden QA 字段/条数与实际不符
- [ ] 评测脚本真实参数缺失，命令跑不通
- [ ] 没有前置环境清单与"何时才需要"
- [ ] 项目无 Git 却没有提醒建基线
- [ ] 没有调试/接口测试/前端构建工具箱
- [ ] 没有白板算法清单与验收 checkbox
- [ ] 模型写死小版本、密钥未脱敏
- [ ] 章节交叉引用或锚点断链
