# english-for-developers 常见问题解答

> 使用开发者技术英语训练时的常见问题和解答。

---

## Q1：我英语基础很差（四级都吃力），能直接练技术英语吗？

**A**：能，而且开发者技术英语恰恰是最容易突破的，因为它范围窄、重复度高、你本来就在学技术：
1. **不补通用语法大课**，直接从你每天都在看的报错和文档入手，即学即用、正反馈最强
2. 技术材料里高频词就几百个、句式高度重复，掌握套路后阅读速度提升很快
3. 先只攻"读"（E1–E2），不急于说；能独立读文档后再补写和说
4. 配合翻译做"脚手架"：整段翻译 → 只查词 → 关键词提示 → 裸读，逐步撤掉

每天稳定 30 分钟，1–3 个月阅读就能基本独立，比回头补应试英语见效快得多。

## Q2：要不要专门背单词、学语法？

**A**：不背大词表、不系统啃语法，按场景最小化学习：
1. **词汇**：只记在真实报错/文档/协作里反复遇到的词，每个词带"技术例句"而不是中文释义堆砌
2. **语法**：够用原则——能读懂长句主干（主谓宾）、认识被动语态和从句即可，遇到卡住的语法点再查，不通学
3. **专业术语不算英语负担**：dependency、middleware、deployment 这些本来就是你要学的技术知识点，中英一起记
4. 用间隔复习巩固场景词汇（联动 `knowledge-review-spaced`），比一次性背 500 个记得牢

判断标准很简单：这个词/语法能不能帮你读懂下一段文档或写下一条 commit，能就学，否则先跳过。

## Q3：看英文文档很慢，是不是词汇量不够？要不要先全翻译成中文读？

**A**：慢主要是"套路不熟"，不全是词汇问题。建议：
1. 第一遍别逐词查，先抓段落结构（是什么/怎么用/注意什么），容忍少量生词
2. 只查"反复出现且影响理解"的词，专业词顺手记，生僻词跳过
3. 翻译工具当**对照**而非依赖：先自己读一遍，再用翻译核对，找出理解偏差
4. 固定读同一套官方文档（你正在学的技术），同一作者/项目的用词重复，会越读越快
5. 用"三遍法 + 复述"训练（见 playbook），两周即可感到提速

长期目标是裸读，一直全翻译成中文会让你永远建立不起英文阅读直觉。

## Q4：怎么用英文搜索问题？我翻译出来的关键词搜不到答案。

**A**：检索不靠整句翻译，靠"技术关键词 + 错误名 + 框架/版本"组合：
1. 直接用**报错原文里的英文异常名/错误码**搜，不要翻成中文再翻回英文
2. 公式：`框架名 版本 关键错误 "完整报错片段"`，例：`spring boot 3 "Failed to configure a DataSource"`
3. 用双引号锁完整报错、用 `site:stackoverflow.com` 限定站点
4. 去掉"为什么/怎么办/请问"这类口语词，英文检索习惯用名词短语
5. 优先看官方文档、官方 Issue、高票 SO 答案，并核对时间与版本是否匹配

建一个"英文报错关键词 → 根因"对照笔记，搜过一次的套路沉淀下来，后面越来越快。

## Q5：写作（Commit / PR / Issue）语法老错，怕闹笑话怎么办？

**A**：开发者协作写作高度模板化，套路固定，门槛比日常英语低：
1. 先从最固定的 **Commit Message** 起步（feat/fix/docs + 祈使句短语），几乎不需要完整语法
2. Issue/PR 直接套 playbook 里的填空骨架，按条目写、多用短句和列表，避免长难句
3. 写完用 AI 改写：要求"保留技术含义、改成地道简洁的技术英文、并解释改动"，对照学习（联动 `ai-assisted-coding`）
4. 技术社区里非母语开发者很多，**清晰 > 华丽**，只要信息结构完整、能复现，语法小错完全可接受
5. 多写多改，10 篇之后常见表达就固化了

## Q6：口语和听力怎么练？没有外国同事、也不敢开口。

**A**：从零社交压力的路径起步：
1. **听力先行**：配英文字幕看技术视频 → 关字幕 → 加速；精听 1–2 分钟片段到能复述
2. **固定套路开口**：Daily Standup 就三句话（昨天/今天/阻塞），先对自己说、录音回听
3. **AI 陪练零压力**：让 AI 扮演海外同事开 standup/技术面试，说错不尴尬，可无限重来
4. 积累会议固定句型（没听清、确认、表达意见、求助、总结），真实会议里 80% 是这些套路
5. 准备英文面试就把 `interview-prep-coach` 的 STAR 项目稿翻成英文反复演练

口语目标是"准确传达、推进协作"，不是口音完美；先流利、后准确、再优雅。

## Q7：技术英语和考雅思/托福、看英文论文是一回事吗？

**A**：相关但目标不同，本 Skill 只服务"开发职业场景"，不做应试：
1. **开发者技术英语**：读文档报错、检索、写协作内容、开技术会议——重实用、范围窄、见效快
2. **应试英语（雅思/托福）**：有固定题型和评分标准，需要额外的通用听说读写与应试技巧，不在本 Skill 范围
3. **英文论文阅读**：句子更长、学术词汇多，属于进阶；本 Skill 打好技术阅读底子后，用 `paper-reader` 的方法专门攻克
4. 顺序建议：先 E1–E3 搞定职业刚需，有余力再向论文/学术或标准化考试延伸
