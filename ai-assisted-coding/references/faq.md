# ai-assisted-coding 常见问题解答

> 使用 AI 辅助编程与学习工作流时的常见问题和解答。

---

## Q1：AI 写代码这么快，我还需要自己打基础吗？会不会反而学不到东西？

**A**：会学不到——前提是你"只复制不理解"。AI 放大的是你已有的判断力，替代不了基础。正确用法分场景：
1. **学习新知识**：让 AI 引导（类比、提问、小测），先自己写再对照，不要直接要成品
2. **做项目**：先自己想方案，让 AI 补样板、补测试、做 review；核心逻辑关掉 AI 能默写
3. **检验标准**：每段 AI 代码你都能逐行讲清、能脱稿重写核心部分，就没白学

把 AI 当"随时在岗的资深同事"，而不是"替你考试的人"。基础越牢，AI 提效越明显；基础为零，AI 给错你也看不出来。

## Q2：为什么我问 AI，它给的代码总是跑不通？

**A**：九成是上下文不足或版本不符。按下面排查：
1. **五要素是否齐全**：角色、技术栈+**确切版本**、相关代码、单一任务、输出格式与约束
2. **给最小可复现**：只贴与问题相关的精简代码，而不是整个项目
3. **版本对齐**：明确告诉它框架大版本（如 Spring Boot 3.x 与 2.x、Vue3 与 Vue2 写法不同）
4. **让它先出计划**：先确认思路再要代码，方向错了写再多也白搭
5. **报错回喂要完整**：完整堆栈 + 你改过什么 + 期望/实际，用 AI Debug 黄金模板

连续两次跑不通，就别再叠加补丁，回到 `bug-troubleshooter` 的"假设→验证"找根因。

## Q3：AI 给了好几个方案，我怎么判断该用哪个？

**A**：不要让它只给一个答案，主动要对比，再用工程标准决策：
1. 让它按"实现复杂度 / 性能 / 可维护性 / 扩展性 / 风险"出对比表并给推荐
2. 追问"推荐方案在什么场景会失败"，让它自我质疑（也可换个模型互审）
3. 用你的约束做最终裁决：当前团队水平、上线时间、是否好维护，比"技术上最优"更重要
4. 选定后让它说明**为什么不选另外两个**，确保是权衡而非随手一选

决策权在你：AI 提供候选和理由，你为结果负责。

## Q4：怎么判断 AI 是不是在"一本正经地胡说"（幻觉）？

**A**：重点核查这四类高危内容：
1. **不存在的 API/参数/依赖**：让它给官方文档链接，点进去核对
2. **版本不符的用法**：对照你锁定版本的官方文档或源码
3. **确定的数字与"官方推荐"**：要来源，给不出来就是经验判断而非事实
4. **自洽但跑不通的代码**：调用了你项目里根本不存在的方法——实际运行见真章

原则：**原理可参考、事实必核验**。涉及安全、钱、数据一致性的，一律人工逐行复核，绝不为了省事直接信。

## Q5：在 Cursor / Copilot 这类工具里，怎样避免它乱改一堆文件？

**A**：控制改动范围，小步合入：
1. 一次只让它做一个垂直切片，任务描述里写明"不要改动与本功能无关的文件"
2. 用 @ 精确引用需要的文件，而不是让它全库扫描后自由发挥
3. **逐块审查 Diff**，看懂一块接受一块，绝不"全部接受（Accept All）"
4. 改动前保证工作区已 commit，方便随时回滚；大改动开新分支
5. 把项目约定写进规则文件（`.cursorrules` / Copilot Instructions），让它默认守规矩
6. 不要同时开多个会自动改代码的 Agent，防止互相覆盖

## Q6：AI 生成的代码，安全方面我重点看什么？

**A**：以下属于红线区域，AI 写完必须人工逐行过：
1. **注入**：SQL 是否参数化/预编译，命令执行是否拼接用户输入
2. **鉴权与越权**：接口是否校验身份与数据归属，有没有"只查不传用户 ID"的水平越权
3. **敏感信息**：有没有硬编码密钥、把 Token/密码打进日志或返回前端
4. **输入校验**：外部入参是否做类型/长度/范围校验，异常是否吞掉
5. **依赖风险**：是否引入来历不明或有已知漏洞的包
拿不准时用 `code-review-refactor` 的安全清单逐项过，或让 AI 按安全维度专门审一遍再人工复核。

## Q7：怎么把"会用 AI"沉淀成长期优势，而不是每次从零问？

**A**：建三类个人资产并持续迭代：
1. **Prompt 模板库**：验证有效的提问按解释/生成/调试/重构/测试/评审分类存好，复用而非重写
2. **项目规则文件**：把技术栈、目录约定、命名、禁令固化，让每次输出默认合规
3. **踩坑与概念笔记**：解决的难题、讲通的概念写进 Obsidian（联动 `tech-concept-deep-dive`、`knowledge-review-spaced`），用 `[[]]` 连成网

每周复盘一次：哪些提问命中率高、哪类问题 AI 总出错，据此更新模板和规则。这样你的 AI 协作能力会复利增长，而不是停留在"会聊天"。
