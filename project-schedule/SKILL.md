# Project-Schedule · 暖色调排期表生成器

## 〇、设计理念

> **设计是资产，内容是变量**。这个 skill 的全部价值在于把一套经过打磨的暖色玻璃拟态视觉固化成模板，调用方只负责填数据，不需要（也不应该）重写任何 CSS/JS。
>
> 三条底线：
> 1. 视觉一致性高于一切——不同项目用这个 skill 出来的页面长得像同一系列
> 2. 单文件可分发——不依赖 CDN、不构建、双击即开
> 3. 进度是用户自己的——勾选状态只存本地，不上传任何服务器

> 设计是资产，内容是变量。所有视觉固化在 `templates/schedule-template.html`，调用方只替换 `{{...}}` 占位符。

## 一、这个 Skill 能产出什么

一个单文件 HTML（内联 CSS+JS，无外部依赖，双击即开），包含：

- **Hero 卡**：渐变高亮大标题 + 一段说明 + 5 个 chip 标签（起点/终点/每日时长/目标人群/资料）
- **4 格统计卡**：周数 / 阶段数 / 任务项 / 完成度（数字自动计算，4 种 accent 色）
- **工具栏**：深浅色切换 / 全部展开 / 全部折叠 / 重置进度
- **总进度条**：橙→紫→粉渐变填充，随勾选实时变化
- **可折叠阶段卡**：badge（W1–W6 样式）+ 阶段名 + 已完成计数 + 箭头旋转
- **周卡**：周序号 + 日期区间 + 标签（本周高亮为橙色实心）+ 周标题 + checkbox 任务列表（逐条错峰渐入）+ 本周验收条
- **右侧固定周导航**：W1…Wn 竖排，当前周橙色高亮，可折叠，已完成周半透明
- **顶部 3px 滚动进度条**：橙→紫→粉渐变
- **深色/浅色双主题**：`data-theme="dark|light"`，localStorage 记忆
- **进度持久化**：每个 checkbox 勾选状态存 localStorage，刷新不丢
- **入场动画**：IntersectionObserver + `.reveal` 类，周卡内任务项 40ms 错峰渐入；支持 `prefers-reduced-motion` 降级

## 二、六条铁律

1. **复制模板**：直接复制 `templates/schedule-template.html`，只替换 `{{...}}` 占位符，不要重写 CSS/JS。
2. **数据层集中**：所有用户数据都在 `<script>` 开头的 `const stages = {{STAGES_JSON}};`，不要散落到 HTML。
3. **不改设计系统**：CSS 变量（`--accent*`/`--bg*`/`--glass*`/`--sp-*`/`--radius-*`）一行不动。
4. **存储隔离**：不同项目用不同 `STORAGE_KEY` / `THEME_KEY`（如 `ragstudy-v1`、`jobhunt-v1`），避免进度串。
5. **任务即字符串**：每个 task 就是一句中文（可带 `（Xh）`），不要嵌套对象。
6. **响应式保留**：768px / 520px 两个断点已写好，不要删。

## 三、占位符清单

打开模板后，用真实数据替换以下 10 个占位符：

| 占位符 | 位置 | 示例 |
|--------|------|------|
| `{{TITLE}}` | `<title>` | `29 周学习排期表` |
| `{{DESCRIPTION}}` | meta description | `企业级 AI Agent 项目排期` |
| `{{HERO_TITLE_HTML}}` | `<h1>` 内 | `🎯 AI 全栈项目 · <span class="hl">29 周排期</span>`（`.hl` 是渐变高亮） |
| `{{HERO_SUBTITLE}}` | hero 下 `<p>` | 一段说明文字 |
| `{{CHIPS_HTML}}` | `<div class="hero-meta">` 内 | 5 个 chip 拼起来，示例：`<div class="chip">📅 起点 2026-10-16</div><div class="chip">⏱ 每天 8h</div><div class="chip">🎯 终点 2027-04-30</div>` |
| `{{START_JS}}` | `const START = ...;` | `new Date(2026,9,16)`（月份从 0 开始） |
| `{{STAGES_JSON}}` | `const stages = ...;` | 见下方数据结构 |
| `{{STORAGE_KEY}}` | localStorage key | `my_project_v1` |
| `{{THEME_KEY}}` | 主题记忆 key | `my_project_theme_v1` |
| `{{FOOTER_TEXT}}` | 页脚 | 一句原则文案，可含 `<b>` 标签 |

## 四、stages 数据结构（必背）

```js
const stages = [
  {
    name: "阶段一 · 环境就绪",        // 阶段名
    badge: "W1",                      // 阶段角标（如 W1、W2–W3、W4–W12）
    goal: "一句话说清这个阶段要达成什么",
    weeks: [
      {
        title: "本周主题标题",         // 周卡 h4
        tag: "后端基础",              // 右上角小标签（本周会自动变成 🔥 本周）
        tasks: [
          "任务一（2h）",
          "任务二（1.5h）",
          // ... 任意条数
        ],
        deliver: "本周 N 项任务，约 Xh"  // 本周验收条
      },
      // ... 本阶段更多周
    ]
  },
  // ... 更多阶段
];
```

**规则**：
- `weeks` 顺序即时间顺序，周号由脚本自动从 1 递增，不要自己写 `w:1`。
- "本周"判定：脚本根据 `START` 和当前日期自动算，落在这周就高亮。
- `tag` 任意字符串，但建议简短（≤6 字）。

## 五、使用流程

1. 复制 `templates/schedule-template.html` 到用户项目目录，重命名为有意义的名字（如 `学习排期表.html`）。
2. 按上面占位符清单逐项替换。**重点**：把用户提供的任务排期组织成 `stages` 数组。
3. `STORAGE_KEY` 和 `THEME_KEY` 用项目英文短名 + 版本号（避免和其他项目冲突）。
4. 浏览器打开自检：
   - 深浅色切换正常
   - 勾选任务后进度条和统计数字变化
   - 刷新页面进度不丢
   - 右侧周导航点击能跳转
   - 今日周有橙色高亮
5. 交付给用户。

## 六、设计要点（不要破坏）

详细见 [references/design-system.md](references/design-system.md)。核心：

- 暖色四色 accent：橙 `#ff9a2e` / 青 `#4fc4b4` / 紫 `#9b8cf0` / 粉 `#e879a0`
- 深色底 `#0f0c09`（暖黑），不是冷黑
- 玻璃卡片：`rgba(32,26,20,.28)` + `blur(24px) saturate(180%)`
- 缓动统一 `cubic-bezier(.22,1,.36,1)`
- 字号 7 档、间距 4 的倍数、圆角 5 档，全部走 CSS 变量

## 七、使用场景

### 场景 1：学习路线排期
用户给了一份分阶段学习计划，要做成网页看板。把每周任务填进 `stages`，设好 `START` 日期即可。

### 场景 2：项目里程碑
把项目里程碑拆成阶段（需求→设计→开发→测试→上线），每个阶段下挂周任务。

### 场景 3：健身/习惯打卡
每周列训练任务，用 checkbox 打卡，进度自动保存。

## 八、输出规范

- 单文件 HTML，UTF-8，无外部 CDN
- 文件名用中文可读名（如 `29周学习排期表.html`）
- 交付前必须在浏览器打开过，确认无 JS 报错
- 不主动加用户没要求的模块（图表、粒子、3D 倾斜等）

### 交付前检查清单

- [ ] 浏览器打开无白屏、无 Console 报错
- [ ] `{{...}}` 占位符全部替换（搜索 `{{` 应为 0 结果）

- [ ] 刷新后勾选状态保留
- [ ] 右侧周导航点击能跳转，当前周橙色高亮
- [ ] 今日周卡有橙色边框高亮
- [ ] STORAGE_KEY / THEME_KEY 与其他项目不冲突
