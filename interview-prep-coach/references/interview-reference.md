# 面试题型答题框架与四大方向面试重点

> 供 interview-prep-coach 准备面试时参考，按对应题型和方向的要点执行。

---

## 面试题型与答题框架

### 题型1：技术概念题

**答题框架（STAR 变体）**：
1. **定义**：一句话说清楚是什么
2. **原理**：核心机制、工作流程（2-3 句话）
3. **特点**：优势、劣势、适用场景
4. **对比**：与相关概念的区别（如被问到）
5. **实践**：项目中的实际应用（1 个例子）

**示例（什么是索引）**：
- 定义：索引是帮助数据库高效获取数据的数据结构
- 原理：B+ 树结构，通过减少磁盘 IO 次数加速查询
- 特点：加速查询但占用空间、降低写入性能
- 对比：聚簇索引 vs 非聚簇索引
- 实践：在电商系统中，给订单表的 user_id 加索引，查询速度从 500ms 降到 10ms

### 题型2：场景设计题

**答题框架（四步法）**：
1. **需求澄清**：问 3-5 个关键问题（规模、性能、约束）
2. **高层设计**：给出整体架构（分层、模块、数据流）
3. **核心细节**：深入 2-3 个核心模块的设计
4. **瓶颈与优化**：识别瓶颈，给出优化方案

**注意事项**：
- 不要一上来就给答案，先问问题澄清需求
- 量化估算（QPS、存储、带宽）
- 说出 trade-off（为什么选 A 不选 B）
- 主动说异常处理和高可用

---

### 题型3：算法编程题

**答题框架（五步解题法）**：
1. **理解题意**：复述题目，确认输入输出、约束条件
2. **思路分析**：
   - 暴力解法（先说，再优化）
   - 优化思路（数据结构、算法技巧）
   - 复杂度分析（时间、空间）
3. **代码实现**：
   - 边写边解释思路
   - 注意边界条件
   - 代码规范（命名、缩进、注释）
4. **测试用例**：
   - 正常用例
   - 边界用例（空、单元素、最大值）
   - 异常用例（非法输入）
5. **优化讨论**：是否有更优解、 follow-up 问题

---

### 题型4：项目经验题

**答题框架（STAR 法则）**：
1. **Situation（背景）**：项目背景、你的角色、团队规模
2. **Task（任务）**：你负责的具体任务、面临的挑战
3. **Action（行动）**：你做了什么、怎么做的、用了什么技术
4. **Result（结果）**：量化结果（性能提升 X%、用户量 X、节省 X 成本）

**注意事项**：
- 重点说"你"做了什么，不是"我们"
- 量化结果（数字比形容词有说服力）
- 说遇到的困难和解决方法
- 说技术选型的理由和 trade-off

---

### 题型5：行为面试题

**答题框架（STAR + 反思）**：
1. **Situation**：具体场景
2. **Task**：你的任务/目标
3. **Action**：你采取的行动
4. **Result**：结果如何
5. **Reflection**：如果重来会怎么做、学到了什么

**常见行为题**：
- 说一个你遇到的最大挑战
- 说一个你和同事意见不合的经历
- 说一个你主动承担额外工作的经历
- 说一个你失败的经历
- 说一个你学习新技术的经历

## 四大方向面试重点

### 方向1：Java 后端

**核心知识点**：
| 模块 | 重点 | 高频考点 |
|------|------|---------|
| Java 基础 | 集合、并发、JVM | HashMap 原理、线程池、GC 算法 |
| Spring | IoC、AOP、事务、Boot | Bean 生命周期、事务传播、自动配置 |
| 微服务 | Spring Cloud、分布式 | 服务发现、配置中心、链路追踪 |
| 数据库 | MySQL、Redis | 索引、事务隔离、缓存穿透/击穿/雪崩 |
| 消息队列 | Kafka、RabbitMQ | 消息可靠性、重复消费、顺序消息 |
| 分布式 | 分布式锁、分布式事务 | Redisson、Seata、CAP 理论 |

**项目面试重点**：
- 系统架构图（能画出并解释每个模块）
- 技术选型理由（为什么用这个，不用那个）
- 性能优化（做了什么优化，效果如何）
- 难点挑战（遇到什么问题，怎么解决的）
- 高可用设计（如何保证系统稳定）

---

### 方向2：前端开发

**核心知识点**：
| 模块 | 重点 | 高频考点 |
|------|------|---------|
| JavaScript | 原型、闭包、异步、ES6+ | 事件循环、Promise、this 指向 |
| TypeScript | 类型系统、泛型、高级类型 | 类型体操、条件类型、映射类型 |
| Vue3 | 响应式、组合式API、性能 | ref/reactive 原理、虚拟DOM、Diff 算法 |
| 工程化 | Vite、Webpack、构建优化 | HMR 原理、Tree Shaking、代码分割 |
| 浏览器 | 渲染流程、性能、安全 | 重排重绘、XSS/CSRF、缓存策略 |
| 网络 | HTTP、HTTPS、TCP | 三次握手、HTTPS 原理、HTTP/2 |

**项目面试重点**：
- 性能优化（首屏加载、运行时性能）
- 工程化实践（构建优化、代码规范、CI/CD）
- 组件设计（通用组件、状态管理）
- 跨端适配（响应式、移动端适配）
- 错误监控和性能监控

---

### 方向3：Python / AI 工程

**核心知识点**：
| 模块 | 重点 | 高频考点 |
|------|------|---------|
| Python 基础 | 数据结构、并发、装饰器 | GIL、生成器、元类 |
| Web 框架 | FastAPI、Django | 异步处理、中间件、ORM |
| 数据库 | SQLAlchemy、Redis、向量库 | 连接池、异步查询、索引 |
| LLM 应用 | Prompt、RAG、Agent | 检索优化、幻觉控制、工具调用 |
| LangChain | Chain、Agent、Memory、Retriever | 自定义 Chain、Agent 规划 |
| 部署 | Docker、API 服务、流式响应 | 并发处理、超时控制、成本优化 |

**项目面试重点**：
- RAG 系统设计（文档处理、检索、生成、评估）
- Agent 系统设计（规划、工具调用、记忆、多 Agent 协作）
- Prompt 工程（少样本、思维链、角色设定）
- 性能优化（LLM 调用延迟、token 成本、并发）
- 评估体系（检索质量、生成质量、用户反馈）

---

### 方向4：全栈 / 系统设计

**核心知识点**：
| 模块 | 重点 | 高频考点 |
|------|------|---------|
| 系统设计 | 架构、容量估算、高可用 | 秒杀系统、Feed 流、短链接 |
| 分布式 | 一致性、容错、扩展性 | CAP、BASE、分布式锁、分布式事务 |
| 中间件 | 消息队列、缓存、搜索引擎 | Kafka、Redis、Elasticsearch |
| 数据库 | 分库分表、读写分离、数据同步 | 分片策略、主从复制、Binlog |
| 运维 | Docker、K8s、CI/CD、监控 | 容器编排、服务发现、可观测性 |
| 安全 | 认证授权、加密、防护 | JWT、OAuth2、XSS/CSRF、SQL 注入 |

**项目面试重点**：
- 整体架构设计（能画出完整架构图）
- 技术选型和 trade-off
- 高并发场景处理（限流、熔断、降级）
- 数据一致性方案（强一致/最终一致）
- 系统演进路径（从单体到微服务到分布式）
