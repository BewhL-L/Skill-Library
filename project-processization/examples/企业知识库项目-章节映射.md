# 示例：企业级 RAG + Agent 平台（扫描事实 → 八章映射）

> 这是一个经过五轮迭代、已达"最终版效果"的真实样例，展示本 Skill 的产物形态：
> 原始事实如何被扫描、核对，并落到学习指南的各章节。数字均来自
> `scan_project_facts.py` 同一次扫描与源码核对（口径：物理行、排除 `__init__.py`/缓存）。

## 三、导航与校验结果（最终版）

- 折叠 TOC：8 章 + 40 小节 = 48 个锚点，`make_toc.py` 生成，与正文逐一对齐。
- 结构：H1=1 / H2=10 / H3=11 / H4=40；代码围栏 34 个成对闭合；无层级跳跃。
- 零删减：126 个原文实质行，125 严格保留，唯一差异是已声明的用例数修正。

## 四、复用本样例的建议

1. 你的项目技术栈不同没关系——**流程不变**：先扫事实、再套八章、逐数字核对、三连校验。
2. 规模数字会变（你项目可能只有几千行），但"分层行数 / 测试数 / 组件数 / 服务 / 依赖"
   这五类事实一定都要扫。
3. 若项目没有 golden QA、没有评测脚本，就在第三章把它列为"必须亲手从 0 建立"的任务，
   并在第五章给出建立步骤，而不是假装它已存在。
