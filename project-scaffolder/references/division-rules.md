# 人机分工判断规则（Division Rules）

> 对项目的每个环节、每个产物，判断属于 A/B/C 哪一类。本文件含通用标准、判断流程、7 类项目具体示例和边界情况。

---

## 一、A/B/C 三类总览

| 类别 | 一句话定义 | 谁来做 |
|---|---|---|
| **A 类** | AI 可独立完成的工作 | AI 直接完成并交付 |
| **B 类** | AI 搭框架，用户填内容/做确认 | AI 做 60%-90%，用户补关键部分 |
| **C 类** | 必须用户亲自完成的工作 | 用户自己做，AI 给指引 |

---

## 二、通用判断三问（按顺序）

对每个动作依次问：

```
第1问：这个动作 AI 能不依赖用户、独立完成吗？
       ├─ 能 → A 类
       └─ 不能 → 进入第2问

第2问：AI 能完成大部分，但需要用户补充个人信息或做最终确认吗？
       ├─ 是 → B 类
       └─ 否 → 进入第3问

第3问：这个动作需要物理世界参与、真实社交、资金/法律操作，
       或必须由用户亲自体验吗？
       └─ 是 → C 类
```

---

## 三、A 类：AI 直接完成

### 核心特征
- 信息搜集、整合、结构化整理
- 模板化、标准化、有明确方法论的工作
- 不依赖用户的私人信息或物理行动
- 产出可以是：初稿、框架、方案、清单、计划、对比、分析

### 典型产物
| 类别 | 示例 |
|---|---|
| 代码 | 程序代码、脚本、配置、测试 |
| 文档 | 大纲、报告框架、模板、说明书 |
| 分析 | 对比表、竞品分析、方案对比 |
| 计划 | 时间规划、路线图、WBS、预算框架 |
| 知识 | 知识点讲解、概念梳理、资料汇编 |
| 内容 | 内容初稿、选题库、话术、文案 |
| 流程 | SOP、流程图、检查清单、验收标准 |

### 质量要求
- 完整、可直接使用，不允许"省略""其余类似"
- 代码可运行、文档可阅读、计划可执行
- 含必要的注释、说明、示例

---

## 四、B 类：AI 框架 + 用户填充

### 核心特征
- 需要用户的个性化输入、私人信息
- 需要用户的专业判断或最终拍板
- AI 能完成 60%-90%，但缺关键的个人内容

### 典型场景
| 场景 | AI 做什么 | 用户填什么 |
|---|---|---|
| 密钥/账号配置 | 配置模板、字段说明 | 真实 API Key、账号信息 |
| 简历/个人陈述 | 模板、范文、结构 | 真实经历、个人数据 |
| 财务模型 | 模型公式、表格框架 | 真实收支数据、投资金额 |
| 商业决策 | 多个方案、利弊分析 | 最终选择、风险偏好 |
| 风格/品牌 | 多套方案、示例 | 风格偏好、品牌定位 |
| 个人计划 | 计划框架、时间模板 | 个人可用时间、特殊情况 |

### 输出要求
每个 B 类产物必须给出：
1. **AI 已做好的框架**（完整结构）
2. **用户需要填的位置**（逐处标注）
3. **填写标准**（填什么格式、什么范围、什么标准）
4. **示例答案**（一个填好的样例，供参考）

**示例**：
```
【需要你填写】年度营销预算
- 位置：预算表 B3 单元格
- 填什么：你能投入的年度营销总金额（数字）
- 标准：建议不超过启动资金的 30%
- 示例：50000
```

## 五、C 类：必须用户自己完成

### 五大特征（满足任一即 C 类）

#### 1. 物理行动
- 安装软件、搭建环境、布置场地
- 出行、制作实体物品、现场操作
- 例：装 Python、布置会场、跑现场

#### 2. 真实社交
- 沟通、谈判、演讲、面试、汇报
- 销售、邀约、主持、团队沟通
- 例：面试、客户谈判、上台汇报

#### 3. 账户/资金/法律操作
- 注册、申请、认证、支付
- 签约、盖章、报税、开户
- 例：申请 API Key、签合同、付定金

#### 4. 个人体验与练习
- 学习、练习、实操、考试
- 创作最终版、习惯养成、技能训练
- 例：做练习题、考试、录最终视频、坚持健身

#### 5. 决策与承诺
- 拍板、取舍、承担后果
- 选择方向、做出承诺、分配资源
- 例：确定创业方向、确认预算、决定 offer

### 输出要求
每个 C 类任务必须给出：
1. **为什么 AI 不能替你做**（说明原因）
2. **你需要做什么**（具体动作）
3. **怎么做**（步骤、方法、话术）
4. **怎么验证做完了**（验收标准）

**示例**：
```
【你需要做】申请火山方舟 API Key
- 为什么 AI 不能替你做：需要你本人注册账号、实名认证，
  Key 与你的账户和计费绑定
- 你需要做什么：注册账号、开通模型服务、复制 API Key
- 怎么做：打开 https://www.volcengine.com/product/ark，
  按页面指引注册，进入"模型推理"创建推理接入点
- 怎么验证：拿到以 sk- 开头的 Key，填入 .env 后能成功调用
```

## 六、7 类项目的分工重点

### 软件/技术项目
- A 多：代码、配置、测试、文档
- B：API Key、个性化配置
- C：装环境、跑项目、部署、面试讲解

### 学习/成长项目
- A：知识体系、讲解、练习题、计划
- B：资料选择确认、时间适配
- C：每天学习、做练习、参加考试（**执行占大头**）

### 内容/创作项目
- A：大纲、选题、模板、初稿、发布日历
- B：风格定位、个人观点
- C：账号注册、最终创作、发布、运营互动

### 商业/创业项目
- A：商业计划框架、市场分析、财务模型框架、SOP
- B：**决策密集**（模式、定价、预算都需拍板）
- C：注册、出资、谈判、签约、真实获客销售

### 研究/调研项目
- A：研究框架、文献整理、数据分析、报告初稿
- B：专业判断、结论确认
- C：一手访谈/实验、专家求证、最终决策

### 活动/组织项目
- A：方案、流程、分工、清单、预算框架
- B：预算确认、方案选择
- C：预订、沟通、邀约、现场执行指挥

### 个人/生活项目
- A：方案对比、计划、清单、预算框架
- B：个人偏好、预算确认
- C：预订付款、出行执行、习惯坚持

## 七、常见边界情况

### 1. AI 能做初稿，但最终质量取决于用户
- 例：演讲稿、面试自述、作品
- 判定：**AI 出初稿（A），用户修改定稿并亲自演讲/提交（C）**
- 不要把"最终上台"也归为 AI

### 2. 可以全程线上完成，但需要用户账号
- 例：发布内容、提交申请、线上报名
- 判定：**AI 准备好材料（A），用户登录账号操作发布（C）**
- 账号操作必须用户自己做

### 3. AI 可以辅助决策，但不能替用户承担后果
- 例：投资、选 offer、辞职
- 判定：**AI 提供分析和方案（A），用户自己决策（C）**
- 重大决策明确标注"风险自担，AI 不代决"

### 4. 简单的创作/修改请求
- 例：写一段文案、改个标题、翻译
- 判定：**直接 A 类完成**，不走完整项目流程

### 5. 涉及他人协作的任务
- 例：团队项目、需要别人配合
- 判定：**AI 给出沟通方案和材料（A），用户去沟通协调（C）**
- AI 无法替用户推动他人

### 6. 重复性执行任务
- 例：每天打卡、长期练习、持续运营
- 判定：**AI 做计划和记录表（A），用户每天执行（C）**
- 坚持无法外包

## 八、分工表输出格式

### 全项目分工表
| 编号 | 环节/产物 | 分类 | AI 交付物 | 用户动作 | 验收方式 |
|---|---|---|---|---|---|
| 1 | 需求文档 | A | 完整 MD | 审阅确认 | 文档完整可读 |
| 2 | 密钥配置 | B | 配置模板 | 填真实 Key | 调用成功 |
| 3 | 环境搭建 | C | 搭建指南 | 亲手安装 | 命令验证通过 |

### 每章分工模块（写入指导文档）
```
### 🤝 本章分工

**🤖 AI 已完成**：
- （具体产物/文件/功能）

**👤 你需要做**：
- （具体任务，标注【必须】/【可选】）
- B 类：附填空指引
- C 类：附验证方法
```

## 九、分工自检清单

- [ ] 每个产物/环节都标注了 A/B/C
- [ ] 没有把"账号/资金/法律/社交/物理动作"错误归为 A
- [ ] 没有把"AI 完全能独立完成的标准化工作"推给用户
- [ ] 所有 B 类都有填空指引和示例
- [ ] 所有 C 类都有原因、做法、验证方法
- [ ] 重大决策类明确标注"AI 不代决、用户自担"
- [ ] 分工表与实际产物一一对应，无遗漏
