# 调试指南

> **注意**：本 Skill 为**纯文档型 Skill**，无运行时代码和调试器。本文档说明 Skill 使用过程中常见问题的排查方法。

---

## 常见问题排查

### 问题 1：Skill 没有触发

**现象**：说了"我想做一个 XX 项目"，但 AI 没有按七步流程执行。

**排查步骤**：
1. 确认请求中包含触发词（"我想做""帮我规划""从零开始""帮我生成"等）
2. 确认请求描述了"需要多步骤、多产物才能完成的目标"
3. 如果是简单任务（如"帮我翻译这句话"），Skill 不会触发，这是正常行为

**解决方法**：在请求中明确说"我想做一个 XX 项目"或"帮我从零开始做 XX"。

---

### 问题 2：生成的项目缺少周边功能

**现象**：社交平台只有发图和点赞，没有收藏、搜索、通知等功能。

**排查步骤**：
1. 检查第二步是否生成了"功能完整性矩阵"
2. 检查第三步是否遵守了"周边标配功能同步生成"约束
3. 检查第六步第 11 维"内容完整性检查"是否执行

**可能原因**：
- AI 没有读取 `references/content-completeness.md`
- 项目类型判断错误（如把社交类判断为工具类）
- 周边功能被错误标注为 P2（后续扩展）

**解决方法**：
1. 明确提醒 AI"对照功能完整性清单，确保 P1 功能全部实现"
2. 明确项目类型（如"这是一个社交类项目"）
3. 要求 AI 列出功能完整性矩阵后再开始生成

---

### 问题 3：生成的代码跑不通

**现象**：后端启动报错、前端编译失败、页面空白。

**排查步骤**：
1. 检查第六步第 10 维"运行时验证"是否执行
2. 检查后端：`python -c "from app.main import app"` 是否有导入错误
3. 检查前端：`npm run build` 或小程序编译是否有错误
4. 检查数据库：所有模型是否都被 ORM 识别

**常见原因**：
- 依赖缺失（requirements.txt 未声明某个包）
- 静态资源缺失（代码引用了不存在的图片/图标）
- 框架语法错误（如 WXML 中调用了 JS 函数）
- 前后端字段名不一致
- 旧数据库缺少新字段（SQLite 不支持 ALTER TABLE ADD COLUMN）

**解决方法**：
1. 运行 `pip install -r requirements.txt` 安装依赖
2. 检查代码中引用的静态资源文件是否存在
3. 删除旧数据库（`*.db`），让 init_db 重建表
4. 对照第六步各维度自检清单逐项排查

---

### 问题 4：指导文档与实际代码不一致

**现象**：README 写 9 个页面，但实际有 12 个；文档说"需手动实现"，但 AI 已经完成。

**排查步骤**：
1. 检查第三步是否遵守了"新增功能必须同步更新文档"约束
2. 检查第六步第 10 维"文档与代码一致性"是否执行
3. 检查第七步交付清单是否验证了 README 和指导文档一致性

**解决方法**：
1. 要求 AI"同步更新 README 和指导文档"
2. 交付前手动核对：页面数、模型数、功能列表、AI 已完成 vs 你需要做
3. 用 `git diff` 检查新增功能是否同步修改了文档

---

### 问题 5：人机分工不合理

**现象**：AI 把需要用户物理操作的任务（如安装环境、部署上线）标为 A 类（AI 已完成），或者把 AI 能完成的任务标为 C 类。

**排查步骤**：
1. 检查第四步是否使用了"通用判断三问"
2. 检查 C 类任务是否给出了验证方法
3. 检查 B 类任务是否给出了填空指引

**解决方法**：
1. 要求 AI 重新审视分工，使用"通用判断三问"
2. C 类任务必须说明"为什么 AI 不能替你做、你需要做什么、怎么验证"
3. B 类任务必须说明"AI 已做好的框架、你需要填什么、填写标准"

---

### 问题 6：Markdown 渲染异常

**现象**：表格显示错乱、代码块不闭合、标题层级混乱。

**排查步骤**：
1. 检查表格列数是否一致（表头和每行列数必须相同）
2. 检查代码块是否正确闭合（``` 必须成对出现）
3. 检查标题是否跳级（H1 后直接 H3，跳过 H2）
4. 检查 Frontmatter 是否严格 YAML（不能在其中放代码块标记）

**解决方法**：
1. 用 Markdown 编辑器的预览功能检查渲染效果
2. 表格列数不一致时，补齐缺失的列
3. 嵌套代码块使用 4 反引号（````）
