# 项目类型详解（Project Types）

> 7 大项目类型的特征、产物清单、资源选型、章节适配、验收标准。多数项目是混合型，应组合使用。

---

## 类型速查表

| 类型 | 核心问题 | 成功标志 |
|---|---|---|
| 软件/技术 | 要构建一个可运行的系统 | 系统能跑、功能可用、能部署 |
| 学习/成长 | 要掌握一项能力/知识 | 能独立运用、通过考核/测试 |
| 内容/创作 | 要产出并发布作品 | 作品完成、按计划发布、有反馈 |
| 商业/创业 | 要创造商业价值/收入 | 模式跑通、有客户/收入 |
| 研究/调研 | 要得出可靠结论/方案 | 结论有证据、可支撑决策 |
| 活动/组织 | 要办成一件事/建好一个组织 | 活动顺利举办、组织运转起来 |
| 个人/生活 | 要改善生活状态/完成生活大事 | 目标达成、生活改善 |

## 一、软件/技术项目

### 典型项目
Web 应用、移动 App、小程序、爬虫、数据平台、AI 应用、API 服务、开发者工具、游戏。

### 产物清单

| 产物 | 格式 | 阶段 | 分类 |
|---|---|---|---|
| 需求文档 | MD | 入门 | A |
| 架构设计 | MD + 架构图 | 入门 | A |
| 后端代码 | 代码文件 | 进阶 | A |
| 前端代码 | 代码文件 | 进阶 | A |
| 数据库设计 | 模型文件 + SQL | 进阶 | A |
| 依赖清单 | requirements.txt/package.json/pom.xml | 入门 | A |
| 配置模板 | .env.example | 入门 | A |
| 自动化测试 | 测试文件 | 实战 | A |
| 部署方案 | Dockerfile/CI脚本 | 实战 | A |
| API 文档 | 自动生成/MD | 进阶 | A |
| API Key 配置 | .env（用户填） | 入门 | B |
| 环境搭建 | 用户本机操作 | 入门 | C |
| 跑通验证 | 用户操作 | 入门 | C |
| 部署上线 | 用户操作 | 实战 | C |

### 资源选型
- 后端：FastAPI / Spring Boot / Express / Django / Gin
- 前端：Vue3 / React / Next.js
- 数据库：PostgreSQL / MySQL / SQLite
- 向量库：Qdrant / Chroma / Milvus
- 缓存/队列：Redis / Celery
- 部署：Docker / Vercel / 云服务器

### 章节适配
- 入门篇：项目全景 → 环境搭建 → 后端启动 → 前端启动 → 业务闭环
- 进阶篇：每个核心模块/技术能力一章
- 实战篇：生产化部署 → 测试质量 → 性能优化 → 求职/交付

### 验收清单
- [ ] 开发环境能启动
- [ ] 核心业务流程跑通
- [ ] 测试全部通过
- [ ] 能部署到目标环境
- [ ] 能讲清架构和原理

## 混合型项目的处理

多数真实项目跨多个类型，应组合处理：

| 混合场景 | 涉及类型 | 处理方式 |
|---|---|---|
| 做 SaaS 创业 | 软件 + 商业 | 两条线并行，商业验证优先于技术完善 |
| 做付费课程 | 内容 + 商业 + 学习 | 先内容框架，再商业设计，最后交付 |
| 技术博主 | 学习 + 内容 | 学习沉淀直接转化为内容 |
| 考研并做项目 | 学习 + 软件 | 时间分配，项目服务于学习目标 |
| 办技术沙龙 | 活动 + 内容 + 组织 | 以活动为主线，内容和组织为支撑 |

**混合项目原则**：
1. 识别主线类型（决定项目成败的那个）
2. 产物清单合并去重
3. 依赖关系跨类型梳理
4. 指导文档按主线组织，其他类型作为模块嵌入
5. 避免摊子铺太大，优先保证主线闭环
