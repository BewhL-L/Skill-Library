# Obsidian 标准化输出规范

> 人生指导手册默认交付为本地 Markdown（Obsidian 知识库友好）+ 可选在线文档（如飞书）。以下为最低标准；各部件"写什么内容"见 `12-document-anatomy.md`，完整知识库规范可配合 obsidian-knowledge-base-creator skill 使用。

> 目录
> 1. Frontmatter（12 字段）
> 2. 标题层级
> 3. 双向链接 [[]]
> 4. Mermaid 流程图（优先于图片）
> 5. 表格与排版
> 6. 文档尾部：三段式导航 + 文档信息块
> 7. 双交付物与验证

---

## 1. Frontmatter（12 字段）

````yaml
---
title: 文档标题（与一级标题一致）
category: 职业规划/【方向】/人生指导
tags:
  - 标签1
  - 标签2            # 8-20 个，覆盖主要章节主题，便于知识库检索
date: 2026-09-08     # 创建/定稿日期
difficulty: ⭐⭐⭐
status: ✅ 内容已完善
priority: 核心
version: v4.1
pre:
  - "[[前置笔记1]]"
next:
  - "[[后续笔记1]]"
aliases:
  - 别名1
  - 别名2
summary: 版本说明书（写给谁 + 本版新增/深化了什么 + 几篇几章 + 本版变更点），每次改版重写
---
````

字段要点：
- `difficulty` 用 ⭐~⭐⭐⭐⭐⭐ 星级，不用 emoji 色块
- `status` 标准值：✅ 内容已完善 / 📝 草稿 / 🔄 更新中
- `priority`：核心 / 重要 / 一般 / 可选
- `version` 与正文文档信息块、迭代协议（11）保持三处一致；每次改版必须同步更新 `date` 与 `summary`
- `summary` 是**版本说明书**而非内容摘要，写法见 `12-document-anatomy.md` 第 2 节
- `pre/next` 用双链数组串相邻笔记；`aliases` 覆盖用户可能搜索的口语化叫法
- tags 不用一次性标签，不与 category 重复；YAML 中含 `[[]]` 的值必须加引号

## 2. 标题层级

- 仅 1 个一级标题 `#`（文档标题）
- `##` 篇、`###` 章、`####` 节，最多到四级
- 篇 → 章 → 节四层结构，编号连续（第 N 篇 / 第 N 章 / N.1 节），新增/删除章节后全书重新编号
- 章标题带优先级：`### 第九章：学习路线总览（🔴P0，……）`
- 标题后不加标点，标题与正文间空一行

## 3. 双向链接 [[]]

- 关键概念首次出现、跨篇相关内容用 `[[]]` 双链，如 `[[项目实战篇]]`、`[[RAG检索增强生成]]`
- 可用别名 `[[文档名|显示文字]]`、锚点 `[[文档#章节]]`
- 保证无孤立章节：每篇至少与上下篇有导航链接；尾部导航（见第 6 节）集中铺 20+ 条主题双链
- 同一主题一处详述、他处概述并双链过去，避免重复和不一致
- 交付前搜索全书，确认双链指向的笔记名真实存在或已在"待建笔记"计划中，无明显死链

## 4. Mermaid 流程图（优先于图片）

Obsidian 原生支持 Mermaid，人生指导手册的流程/架构/路径一律用 Mermaid，便于后续编辑：

````
```mermaid
graph LR
  A[决定方向] --> B[系统学习] --> C[项目实战] --> D[求职冲刺]
```
````

规范：
- 节点文字用动宾短语、简洁；一张图只讲一件事
- 图前有引导句、图后有文字解读，不甩一张无说明的图
- 方向：流程顺序用 LR/TB，层级用 TB，状态机用 stateDiagram，时间线可用 timeline
- 全书必备图：五阶段能力地图、9 步开发流程（含迭代回环）、四阶段进阶图、每个实战项目的系统架构图、方向专项数据流图、部署架构图（完整版 20+ 张）
- 不依赖外部图片链接（防止失效）；Mermaid 节点文字含特殊字符时用引号包裹，避免渲染失败

## 5. 表格与排版

- 对比、清单、时间线、优先级一律用表格，表头加粗；表格前有一句引导语说明"下表是什么"
- 引用外部事实的表格，下一行写来源：`资料来源：【机构】[n]，本研究测算/整理`
- 单元格简洁，超长内容拆行或拆表
- 列表用 `-`，步骤用 `1.`，检查清单用 `- [ ]`
- 代码块标注语言；配置/代码给完整可复制内容，不给残缺片段
- 引用块用于 💡提示 / ⚠️风险 / ✅推荐 / ❌禁止 / 🔴红线 / 📌本章小结

## 6. 文档尾部：三段式导航 + 文档信息块

### 6.1 风险提示与结语在前

六篇正文结束后，顺序固定为：风险提示（8 条）→ 结语（掏心窝子 N 句 + 金句）→ 参考文献（[n] 与正文一一对应），内容模板见 `12-document-anatomy.md` 第 7 节。

### 6.2 尾部导航（三段式双链，替代单一"相关笔记"）

````markdown
### 尾部导航

**相关笔记链接（Obsidian双链）：**
- [[笔记1]] — 一句话说明
- [[笔记2]] — 一句话说明      # 20+ 条，按主题排列

**前置知识（建议先读）：**
- [[入门笔记1]] — 一句话说明   # 5-8 条，零基础补课前置

**延伸阅读（进阶）：**
- [[进阶笔记1]] — 一句话说明   # 6-10 条，入职后/进阶方向
````

### 6.3 免责声明

四段固定：定位与非专业意见声明、时效与生成性误差说明、用户独立判断与专业咨询建议、公司/产品中性引用声明。

### 6.4 文档信息块（全书最后一块，版本对账用）

````markdown
**（全文完）**

**文档信息：**
- 标题：【与 title 一致】
- 版本：vX.X（【版本代号】）
- 完成日期：【YYYY年M月D日】
- 字数：约【N】万字（中文字符【精确值】，总字符【精确值】）
- 结构：【X篇X章 + 风险提示 + 结语 + 参考文献 + 尾部导航】
- vX.X变更：【变更清单，与 Frontmatter summary 一致】
- 适用人群：【一句话画像】
- 核心判断：【全书最核心的一条结论】
````

## 7. 双交付物与验证

1. **本地 Markdown**：写入用户指定路径并覆盖同名文件；写入后回读开头 Frontmatter 与结尾文档信息块，确认编码正常（Windows 注意 UTF-8 无 BOM，控制台乱码不代表文件乱码，以 Read 工具为准）
2. **在线文档（如需要）**：同步到飞书/在线文档，返回可访问链接；Mermaid 若目标平台不渲染，需转为等价图片或文字结构
3. **字数实测**：中文字符数与总字符数分别统计后填入文档信息块，禁止凭感觉估算；统计时排除代码块或注明口径
4. 交付前核对：字数/行数、篇章节齐全、Frontmatter 12 字段完整、version/date/summary/文档信息块四处一致、双链无明显死链、Mermaid 可渲染、参考文献 [n] 与正文对应无缺号
5. 大文件（>256KB）分段读取验证，不要凭字数假设内容完整；每次迭代后按 references/11 做去重、消歧、理序、对账
