# 《项目全景总结与行动指南》通用模板

> 生成项目指导文档时使用本模板。包含：完整结构、七要素写法、三篇组织、类型适配、验收清单、规模适配。
>
> 使用方式：复制模板结构 → 按项目类型填充内容 → 删减不适用部分 → 自检。

---

## 一、文档整体结构

```
Frontmatter
# 项目标题
> 导语
## 学习路线总览（含图 + 表）
## 🤝 AI 已完成 vs 你需要做（全章总览表）
# 入门篇
  ## 第1章 ...
  ## 第2章 ...
# 进阶篇
  ## 第N章 ...
# 实战篇
  ## 第M章 ...
## 附录（速查表/配置/面试题/排查/资源）
## 结语
```

---

## 二、Frontmatter 模板

```yaml
---
title: 项目名称全景总结与行动指南
category: 项目实战/项目类型
tags:
  - 项目实战
  - 关键词1
  - 关键词2
difficulty: ⭐⭐⭐
status: ✅ 内容已完善
priority: 核心
pre: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

**YAML 铁律**：
- Frontmatter 内不放代码块标记（```）
- 含 `[[双链]]` 时用双引号包裹
- 不出现畸形括号

## 四、三篇结构

### 4.1 入门篇：准备与启动

**目标**：跑通/启动，建立体感。

**通用章节**（按项目类型替换名称）：

| 通用章 | 软件项目 | 学习项目 | 内容项目 | 商业项目 | 活动项目 |
|---|---|---|---|---|---|
| 项目全景 | 同 | 目标分析 | 定位目标 | 机会分析 | 目标定位 |
| 准备阶段 | 环境搭建 | 资料准备 | 账号工具准备 | 资源资质准备 | 方案策划 |
| 基础搭建 | 后端启动 | 学习计划 | 内容规划 | 模式设计 | 分工预订 |
| 核心流程 | 前端启动+业务闭环 | 启动第一次学习 | 完成第一个作品 | 最小验证MVP | 资源到位 |

**入门篇验收清单**：
```markdown
- [ ] （逐项可打勾的具体成果）
```

### 4.2 进阶篇：核心模块构建

**目标**：理解原理/掌握核心能力。

**章节组织**：
- 每个核心模块/能力/环节一章
- 按"是什么→怎么用→为什么→怎么用好"递进
- 前置知识在前，相关模块聚集

**章节数**：
- 小项目 3-5 章
- 中项目 5-10 章
- 大项目 8-15 章

**进阶篇验收清单**：
```markdown
- [ ] 能独立完成 [核心动作]
- [ ] 能讲清 [核心原理]
- [ ] 完成 [模块验证]
```

### 4.3 实战篇：落地与优化

**目标**：真实可用、求职、交付。

**通用章节**：

| 通用章 | 软件项目 | 学习项目 | 内容项目 | 商业项目 | 求职导向 |
|---|---|---|---|---|---|
| 规模化/落地 | 生产化部署 | 综合复习 | 批量生产 | 规模运营 | 完整成品 |
| 质量保障 | 测试质量 | 模拟考试 | 数据复盘 | 财务法务 | 测试通过 |
| 优化迭代 | 性能优化 | 查漏补缺 | 迭代涨粉 | 优化盈利 | 优化完善 |
| 交付/展示 | 上线交付 | 参加考试 | 发布运营 | 扩张 | 求职冲刺 |

**实战篇验收清单**：
```markdown
- [ ] 项目真实可用/达成目标
- [ ] 质量/数据达标
- [ ] 完成交付/发布/求职准备
```

## 五、每章七要素（必须完整）

### 要素 1：概念解释

```markdown
### N.1 什么是 XX

**概念解释**：[1 句正式定义]。

> 生活化比喻：[1 个生活化类比]。

**核心价值**：
- [为什么需要它]
```

**写法要点**：
- 先定义后解释，不堆术语
- 比喻要贴切、面向零基础
- 说清"解决什么问题"

### 要素 2：原理说明

````markdown
### N.2 原理

**核心机制**：[怎么运作的]。

**为什么这样设计**：[设计原因]。

**方案对比**：

| 方案 | 特点 | 适用 |
|---|---|---|

```mermaid
（流程图/架构图/关系图/时间线）
```
````

**写法要点**：
- 讲机制，不只列参数
- 配可视化（按内容选类型）
- 有对比、有取舍说明

### 要素 3：操作指引

```markdown
### N.3 怎么做

**操作步骤**：

1. [具体步骤]
   - 命令/动作：[可复制]
   - 预期结果：[会看到什么]
2. ...

**新手常见坑**：
- 现象：[会遇到什么]
- 原因：[为什么]
- 正确做法：[怎么办]
```

**写法要点**：
- 步骤具体、可执行、可复制
- 标注预期输出
- 关键步骤用 ⚠️ 提醒
- 坑点：现象+原因+做法

### 要素 4：🤝 本章分工

```markdown
### 🤝 本章分工

**🤖 AI 已完成**：
- [具体产物/文件/功能]

**👤 你需要做**：
- 【必须】[具体任务]
- 【可选】[具体任务]
- B 类：[填空指引]
- C 类：[验证方法]
```

**写法要点**：
- AI 列具体文件，不写笼统的"已完成"
- 用户列具体动作，可执行
- 标注必须/可选
- B 类给填写指引，C 类给验证标准

### 要素 5：💡 本章深度讲解

```markdown
### 💡 本章深度讲解

[3-5 句话：本章最重要的概念是什么、为什么重要、
与前后章关系、在实际项目/面试中的价值]
```

### 要素 6：📝 本章精简总结

```markdown
### 📝 本章精简总结

- 核心概念：...
- 关键原理：...
- 常用操作：...
- 最佳实践：...
- 常见坑点：...
```

### 要素 7：🎯 梯度验证任务

```markdown
### 🎯 梯度验证任务

- **基础任务⭐**：[考察基本概念/简单操作]
  - 答案/标准：...
- **进阶任务⭐⭐**：[考察原理理解/综合运用]
  - 思考方向：...
- **实战任务⭐⭐⭐**：[真实场景]
  - 背景：...
  - 要求：...
  - 验收标准：...
  - 提示：...
```

**写法要点**：
- 叫"验证任务"不叫"练习题"（适配所有项目）
- 三级梯度，难度递进
- 基础题给答案，进阶题给方向，实战题给完整任务包

## 七、规模适配

| 规模 | 周期 | 结构 | 章节数 | 七要素 |
|---|---|---|---|---|
| 小型 | 1-3 天 | 1 篇 | 3-6 章 | 保留核心（概念/操作/分工/验证） |
| 中型 | 1-4 周 | 三篇 | 每篇 3-8 章 | 完整七要素 |
| 大型 | 1 个月以上 | 三篇+分阶段 | 每阶段独立文档 | 完整七要素+阶段衔接 |

**小型项目精简策略**：
- 合并原理到概念中
- 保留分工（核心价值）
- 每章至少 1 个验证任务
- 可视化按需要，不凑数

- [ ] 每章有 🤝 分工

- [ ] 每章有 🎯 验证任务三级梯度

### 分工
- [ ] 开头有全章分工总览表
- [ ] AI 已完成列具体产物
- [ ] 用户任务具体可执行
- [ ] B 类有填空指引，C 类有验证方法

### 渲染
- [ ] Frontmatter YAML 可解析
- [ ] 代码块全部闭合
- [ ] 代码内容不暴露为标题
- [ ] Mermaid 图语法正确

- [ ] 用户能按文档从启动走到完成
- [ ] 无跳步、无悬空指引
- [ ] 面试题答案要点准确
