# 笔记质量评估维度详解与报告模板

> 供 note-quality-evaluator 评估笔记质量时参考，包含 5 个评估维度的详细说明和两种评估模式的完整报告模板。

---

## 5 个评估维度详解

### 维度1：内容深度（权重 30%）

**检查要点**：
- 是否深入到原理层面，还是停留在表层描述
- 「原理」模块是否有机制解释、架构设计、工作流程
- 是否有源码片段或核心逻辑分析（L3+ 笔记要求）
- 是否有设计决策和 trade-off 分析

**评分标准**：
| 评分 | 等级 | 描述 |
|------|------|------|
| 9-10 | 极深 | 有源码级分析、设计决策推导、对比方案 |
| 7-8 | 较深 | 有架构设计、核心机制、工作流程 |
| 5-6 | 一般 | 有基本原理，但不够深入 |
| 3-4 | 较浅 | 主要是概念定义和用法，原理部分薄弱 |
| 1-2 | 极浅 | 只有概念定义，无原理分析 |

**常见问题**：
- 「原理」模块只有一两句话，没有机制解释
- 只有"是什么"，没有"为什么"
- 缺少架构图/流程图的文字描述
- 没有源码片段或核心逻辑分析（L3+ 笔记要求）

---

### 维度2：内容准确性（权重 25%）

**检查要点**：
- 技术内容是否准确，有无错误或过时信息
- API 名称/参数是否正确
- 版本信息是否过时
- 概念定义是否准确或有歧义
- 代码示例是否有错误（无法运行或逻辑错误）
- 对比分析是否有误

**评分标准**：
| 评分 | 等级 | 描述 |
|------|------|------|
| 9-10 | 极准 | 无任何错误，所有技术细节准确 |
| 7-8 | 较准 | 个别小错误，不影响整体理解 |
| 5-6 | 一般 | 有几处错误，需要修正 |
| 3-4 | 较差 | 多处错误，影响理解 |
| 1-2 | 极差 | 大量错误，内容不可信 |

**常见问题**：
- API 名称/参数错误
- 版本信息过时（如还在讲 Vue2 的 API）
- 概念定义不准确或有歧义
- 代码示例有错误（无法运行或逻辑错误）
- 对比分析有误（A 和 B 的区别说反了）

---

### 维度3：内容完整性（权重 20%）

**检查要点**：
- 五段式结构中各模块是否有实质内容
- 「概述」是否有一句话定义、适用场景、解决的问题
- 「原理」是否有核心机制、架构设计、工作流程
- 「实操」是否有可运行代码示例、最佳实践
- 「问题」是否有常见坑表格（问题→原因→方案）
- 「拓展」是否有相关概念、进阶学习资源
- 是否缺少前置知识说明（pre 字段）

**评分标准**：
| 评分 | 等级 | 描述 |
|------|------|------|
| 9-10 | 极完整 | 五段式全部充实，无缺失 |
| 7-8 | 较完整 | 个别模块略薄，整体完整 |
| 5-6 | 一般 | 有 1-2 个模块缺失或薄弱 |
| 3-4 | 较差 | 多个模块缺失，结构不完整 |
| 1-2 | 极差 | 只有概念，无实质内容 |

**常见问题**：
- 「问题」模块缺失或只有1个问题
- 「实操」模块的代码片段不完整（缺少导入/配置）
- 「拓展」模块只有链接，没有内容
- 缺少前置知识说明（pre 字段为空）

---

### 维度4：知识关联性（权重 15%）

**检查要点**：
- 是否与其他笔记建立了充分的双链关联
- 有无 pre 前置概念
- 正文中高频概念是否添加了 [[]] 双链
- 有无相关概念推荐
- 是否为孤立文档（无入链也无出链）

**评分标准**：
| 评分 | 等级 | 描述 |
|------|------|------|
| 9-10 | 极丰富 | 5+ 双链，前置/相关/拓展全覆盖 |
| 7-8 | 较丰富 | 3-4 个双链，关联合理 |
| 5-6 | 一般 | 1-2 个双链，关联不足 |
| 3-4 | 较差 | 无双链，孤立文档 |
| 1-2 | 极差 | 完全孤立，无任何关联 |

**常见问题**：
- 无 pre 前置概念
- 正文中缺少 [[]] 双链（高频概念未链接）
- 无相关概念推荐
- 孤立文档（无入链也无出链）

---

### 维度5：可读性与表达（权重 10%）

**检查要点**：
- 内容是否清晰易读，表达是否准确
- 段落是否过长，缺少结构化（应使用列表/表格）
- 术语使用是否一致（同一概念多种叫法）
- 缺少示例，纯理论描述
- 逻辑是否跳跃，缺少过渡

**评分标准**：
| 评分 | 等级 | 描述 |
|------|------|------|
| 9-10 | 极佳 | 结构清晰，表达准确，示例丰富 |
| 7-8 | 较好 | 整体清晰，个别地方可优化 |
| 5-6 | 一般 | 有些段落过长或逻辑跳跃 |
| 3-4 | 较差 | 表达混乱，难以理解 |
| 1-2 | 极差 | 完全无法阅读 |

**常见问题**：
- 段落过长，缺少结构化（应使用列表/表格）
- 术语使用不一致（同一概念多种叫法）
- 缺少示例，纯理论描述
- 逻辑跳跃，缺少过渡

## 批量笔记快速评估报告模板

```markdown
## 📊 知识库质量评估报告

**评估范围**：分类名称（共 N 篇笔记）
**评估时间**：YYYY-MM-DD

### 总体质量分布
| 质量等级 | 笔记数 | 占比 | 代表笔记 |
|---------|--------|------|---------|
| 优秀（8-10分） | N | XX% | [[笔记1]], [[笔记2]] |
| 良好（6-7.9分） | N | XX% | ... |
| 中等（4-5.9分） | N | XX% | ... |
| 较差（<4分） | N | XX% | ... |

### 最需改进的笔记 TOP 10
| 排名 | 笔记 | 评分 | 主要问题 | 改进优先级 |
|------|------|------|---------|-----------|
| 1 | [[笔记]] | X.X | XXX | 🔴 高 |
| ... | ... | ... | ... | ... |

### 共性问题统计
| 问题类型 | 出现次数 | 涉及笔记占比 |
|---------|---------|------------|
| 「问题」模块缺失或不足 | N | XX% |
| 缺少前置知识链接 | N | XX% |
| 原理部分深度不足 | N | XX% |
| 代码示例不完整 | N | XX% |
| 正文缺少双链 | N | XX% |

### 改进建议
1. 优先改进评分 <4 分的 N 篇笔记（预计 X-X 小时）
2. 批量补充所有笔记的「问题」模块（可用 tech-concept-deep-dive 辅助）
3. 批量添加前置知识和正文双链（可用 obsidian-knowledge-base-creator 的 fix-link）
4. 建议每月执行一次质量评估，跟踪改进进度
```

## 按难度分级的质量标准

| 难度 | 深度要求 | 原理要求 | 源码要求 | 问题数量 |
|------|---------|---------|---------|---------|
| ⭐ 入门 | 概念+用法 | 基本原理 | 不要求 | ≥2个 |
| ⭐⭐ 进阶 | 核心用法+场景 | 机制说明 | 不要求 | ≥3个 |
| ⭐⭐⭐ 高级 | 原理+架构+实践 | 架构设计+工作流程 | 核心片段 | ≥4个 |
| ⭐⭐⭐⭐ 专家 | 源码+性能+复杂方案 | 完整机制+设计决策 | 关键模块源码 | ≥5个 |
| ⭐⭐⭐⭐⭐ 资深 | 前沿研究+跨领域+体系 | 深度源码+对比方案 | 多模块源码 | ≥6个 |
