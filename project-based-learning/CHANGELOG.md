## [v1.1.0] - 2026-11-03

### 新增

- **核心原则 +2**：`分工显式`（每阶段标 AI 可代劳 / 你必须亲手）、`零基础可读`（术语解释、命令预期输出、阶段动手卡片）。
- **8 部分横切要求**：分工、验收（命令 + 期望输出）、估计值、动手卡片——不新增第 9 部分，避免结构膨胀。
- **选型三问**：练技术点还是完整交付、每周投入、练习还是简历项目；并注明周期按每周 15-20 小时估算。
- **场景一步骤补全**：分步教程含"命令 + 期望输出 + 本阶段卡片"；新增"标注人机分工"一步；双链无笔记时链接到主题并标「待建」，不臆造笔记名。
- **输出规范 +5 条**：估计值标注、命令工作目录与安全、阶段卡片、人机分工、双链不臆造。
- **质量清单 +6 项** 与 **四轮自检**（结构 / 事实 / 一致性 / 可用性）。
- **交接包**：技术栈 / P0-P1 范围 / 阶段划分 / 验收命令 / 双链清单，交给 `project-scaffolder` 时不重新规划。
- `references/project-templates.md`：阶段 1 增加"人机分工 + 本阶段动手卡片 + 卡住了"；第六部分增加"命令 + 期望输出"三行示例；第一部分注明周期为估计值。

### 变更

- `README.md` 同步 7 条核心原则、SKILL 文档结构说明与版本号。
- `TESTING.md` 抽查从 5 条扩到 7 条：新增"分工与卡片""估计值与命令安全"；`QUICKSTART.md` 同步。
- `API.md` 输出契约补"人机分工 / 阶段卡片 / 估计值"；交接改为"8 大部分 + 交接包"。
- `ARCHITECTURE.md` 文档树补「工程实践基线 / 四轮自检」；`DEBUGGING.md` 新增"没有分工""没有卡片"两类症状，并更新抽查编号；`CONTRIBUTING.md` 抽查 5→7、版本校验补 frontmatter。
- `examples/bad-vs-good.md` 从 6 组扩到 8 组：新增"人机分工""阶段动手卡片"对照。
- `FAQ.md`：Q1 补人机分工与阶段卡片；Q2 补"按每周 15-20 小时估"的假设。
- `examples/plan-skeleton-rag.md`：阶段 2 补"人机分工"与"动手卡片"两行；周期标注估计值。

### 修正（多轮自检）

- 「输出规范」第 5 条与质量清单对应项：原写"代码示例必须可运行"，易被读成"交付完整项目代码"，与定位卡"不生成代码"冲突。改为"代码片段可运行、只给关键片段，要完整工程用 `project-scaffolder`"。
- 本 Skill 为纯文档型，无脚本，`TESTING.md` 的"测试"指对**生成物**的抽查，不是单元测试。

## [v1.0.2] - 2026-11-03

### 新增

- 「工程实践基线」：验收写成"命令 + 期望输出"，数字取自机器可读产物（junit xml），不抄终端摘要行；四类静默失败（配置旁路 / 绝对阈值 / 校验未同步 / 取消异常）各配一条验收。
- 提交纪律：`commit` 是批准、`push` 是传输；按模块提交、按路径 `git add`、装 `secret-gate` 的 pre-commit 闸门。
- 环境一致性验收：改一行 → 重启 → 确认生效，防"跑的是旧副本"。
- 质量检查清单新增 4 项对应上述要求。

### 背景

- 2026-11-02/03 实战沉淀：一轮"测试全绿但依然可能错"的代码审查（24 文件 / +908 −123）里，问题几乎都是"看起来正常"的静默失败；同期的 Git 自动化又踩了"改了源码、加载的是旧副本"与 `git add -A` 带出私密文件两次事故。方案层不写进去，学习者必然重踩。
