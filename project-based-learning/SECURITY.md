# SECURITY

本 Skill 不执行代码、不访问网络，但它**产出的是可直接落地的项目设计**，其中可能包含不该外流的上下文。风险集中在"写进方案里的东西"，而不是"Skill 本身"。

## 1. 三类需要脱敏的输入

| 输入 | 为什么敏感 | 处理 |
|---|---|---|
| 真实业务/公司信息 | "给某某客户做的对账系统"会随方案进入笔记库、简历甚至公开仓库 | 用行业化代称（"某零售企业中台"），保留技术结构即可 |
| 内网地址与拓扑 | `10.x.x.x`、内部域名、VPN 网关出现在方案里，等于泄露边界 | 一律写 `localhost` 或占位域名 `example.internal` |
| 账号、密钥、连接串 | 方案里常出现"配置示例" | 只写键名与占位值（`OPENAI_API_KEY=<your-key>`），**绝不写真实值** |

## 2. 生成物的分级

参照 `project-processization` 的做法，方案建议分两份：

| 文档 | 可见性 | 内容 |
|---|---|---|
| 公开版 | 可进公开仓库 / 简历附件 | 架构、技术选型、验收标准（脱敏后） |
| 私密版 | 仅本地知识库 | 含真实业务背景、内部地址、踩坑记录 |

判断标准很朴素：**这段内容出现在 GitHub 上，我会不会后悔。**

## 3. 不要把密钥写进学习项目

学习项目的"配置示例"是最常见的泄漏入口：

```dotenv
# 正确：占位
OPENAI_API_KEY=sk-your-key-here

# 错误：真实 key（一旦提交，等于公开）
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxx
```

配套措施（若已安装 `secret-gate`）：装 pre-commit 钩子，`.env`、私钥块、内嵌凭据在 `git commit` 那一刻被拒。

## 4. 方案里应写入的安全验收

好的学习项目方案会**把安全做成验收项**，而不是口号：

- [ ] 密码/令牌不以明文入库（`grep -r "password" migrations/` 无明文）
- [ ] 接口鉴权覆盖：无 token 访问受保护路由返回 401
- [ ] 上传文件校验类型与大小，且有上限
- [ ] 依赖无高危漏洞（`pip-audit` / `npm audit` 零 high）

## 5. 数据与隐私

- 方案中如涉及真实数据集，注明"用脱敏样本或公开数据集替代"；
- 用户上传的截图/文档若含个人信息，提示先打码再写入笔记；
- 本 Skill 不收集任何遥测数据。

## 6. 报告问题

这是个人使用的技能。发现方案生成会诱导写入敏感信息（例如模板中要求填真实连接串），直接修改 `references/project-templates.md` 中对应段落，并在 `CHANGELOG.md` 记录。
