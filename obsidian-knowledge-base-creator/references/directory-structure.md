# 12 分类目录结构规范

> 知识库采用 12 个顶级分类，编号前缀，层级清晰，覆盖从基础到进阶、从全栈到 AI 的完整知识体系。

├── 05-云原生与运维/      # Docker/K8s/DevOps/监控/Linux
├── 06-计算机基础/        # 网络/操作系统/数据结构/算法
├── 07-通用工具/          # Git/IDE/效率工具/终端

## 各分类详解

### 00-综合导航
**定位**：知识库的入口和枢纽，不存放具体技术笔记。

**包含内容**：
- `Home.md` — 知识库首页，总入口
- `MOC-综合导航.md` — 全库内容地图，链接所有分类 MOC
- `学习路线总览.md` — 从新手到老手的完整学习路径
- `知识体系框架.md` — 知识体系的整体架构说明
- `标签索引.md` — 全库标签的分类索引
- `术语表.md` — 核心术语的统一解释

**命名规范**：
- MOC 文件：`MOC-{分类名}.md`
- 导航文件：`{名称}.md`（如 `学习路线总览.md`）

- 核心概念笔记（五段式）

## 命名规范

### 文件夹命名
- 格式：`{编号}-{分类名}`（如 `01-前端开发`）
- 编号：00-99，00 为导航，99 为实战
- 分类名：简洁明确，2-6 个字

### 文档命名
- 核心笔记：`{主题} 知识点系统梳理_优化版.md`（如 `Vue3 知识点系统梳理_优化版`）
- 实战笔记：`{主题}实战.md`（如 `Kafka深度实战`）
- 指南笔记：`{主题}指南.md`（如 `RabbitMQ实战指南`）
- MOC：`MOC-{分类名}.md`（如 `MOC-前端开发`）
- 模板：`{名称}-template.md`（如 `note-template`）

### 命名原则
1. **见名知意**：文件名能直接反映内容主题
2. **统一格式**：同类文档使用相同的命名模式
3. **避免缩写**：除非是广为人知的缩写（如 API、CSS）
4. **中文为主**：技术术语可用英文，描述用中文
5. **版本标记**：优化版用 `_优化版` 后缀，避免覆盖原版

## 层级规范

### 最大层级
- 顶级分类：12 个
- 二级子分类：每个顶级分类下 3-8 个
- 三级文件夹：按需创建，不超过 3 层
- 文档：直接放在对应分类或子分类下

### 层级示例
```
01-前端开发/
├── MOC-前端开发.md
├── 基础/
│   ├── JavaScript 知识点系统梳理_优化版.md
│   ├── TypeScript 知识点系统梳理_优化版.md
│   └── CSS 布局实战.md
├── 框架/
│   ├── Vue3 知识点系统梳理_优化版.md
│   └── React 核心原理与实战.md
└── 工程化/
    ├── Vite 核心原理与实战.md
    └── 前端工程化最佳实践.md
```

## 新增分类原则

当现有 12 个分类无法覆盖新领域时，按以下原则新增：

1. **优先归入现有分类**：先判断是否能归入已有分类的子分类
2. **编号选择**：在相邻分类之间插入，使用小数编号（如 `04.5-新分类`）
3. **批量调整**：分类数量超过 15 个时，考虑重新编号
4. **同步更新**：新增分类后，必须同步更新 `MOC-综合导航.md` 和 `学习路线总览.md`
