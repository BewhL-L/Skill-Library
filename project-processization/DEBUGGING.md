# 调试指南

## 脚本不识别中文路径 / 中文乱码

- **现象**：Windows PowerShell 输出中文为乱码。
- **原因**：控制台默认 GBK 编码，脚本写出的文件是 UTF-8，二者不冲突。
- **解决**：`chcp 65001` 切换到 UTF-8；或用 `--json --output result.json` 输出到文件，
  再用编辑器 / Python 读取。

## validate_md 报"多个 H1"

- 检查是否在代码围栏（```bash）里写了 `# 注释`。脚本用围栏状态机已能跳过；
  若仍报错，检查围栏是否成对、语言标注是否完整（围栏总数必须为偶数）。
- 指南是**独立文档**：必须有且仅有 1 个 H1；不要沿用 README 的 H1 造成重复。

## verify_zero_cut 报"疑似删减"

- 这是有意为之的严格保护。逐行查看 `missing_details`：
  - 若为有意的事实修正（如用例数 47→79），加 `--allow-note` 说明，仍需人工复核。
  - 若确为误删，回到指南把原文补回。
- 目录树、命令块等带缩进的行属于实质行，也会被纳入比对。

## make_toc 锚点点击不跳转

- 不要手算锚点，统一用脚本生成。
- 检查标题是否含特殊符号导致 GitHub 与 Obsidian 规则差异；以 GitHub 规则为准。
- 注意 `a + b` 这类含加号的标题会产生双连字符，属正常现象。

## 扫描结果与预期不符

- 组件数偏多：多半是把 `__init__.py` 算进去了；工具已排除，确认用的是业务文件数。
- 行数对不上：确认口径（物理行、是否排除缓存/依赖目录）；同一文档只用同一次扫描。
- 前端/后端目录识别不到：用 `--components` 显式指定相对路径，或检查目录层级并用
  `--group-depth 2`。

## 想看脚本内部如何计算

1. 先用 `--json --output debug.json` 拿到完整结构化结果。
2. 直接读对应函数源码（每个函数都有 docstring），或在 Python 中导入单步执行：
   ```python
   import scan_project_facts as s
   print(s.scan(r"./项目", [])["code"])
   ```
3. 对照 `tests/unit/` 中同名测试，看输入输出约定。

## 运行报错"ModuleNotFoundError"

- 直接运行脚本一般无此问题（同目录导入）。
- 若在测试外以模块方式导入，把 `scripts/` 加入 `PYTHONPATH`；pytest 已由 `conftest.py`
  自动处理路径。
