# 使用案例

## 案例 1：视觉升级后的交付前自检（本次方法论来源场景）

**输入**：一个约 1700 行的单文件打卡面板（深浅双主题、玻璃拟态、呼吸灯动效），历经 7 轮视觉/动效改造。

**执行**：
- 第 1 轮（一致性/美学）：grep 发现 6 处硬编码绿描边 + 死代码选择器 + 失效的 theme-color meta → 全部修复
- 第 2 轮（排版/响应式）：多视口截图 + 360/390 探针 → 零发现
- 第 3 轮（功能交互）：jsdom 32 条断言 → 1 条"失败"甄别为 jsdom 伪影（点击不聚焦），显式 focus 后全绿
- 第 4 轮（动效/性能）：keyframes 属性白名单核对、will-change/transition:all 零残留 → 零发现
- 第 5 轮（收敛复检）：发现真实回归——手动主题块令牌泄漏（系统浅色+手动深色时勾选框串色）→ 补全两个主题块 → diff 归零 + 冒烟 32/32 → 收敛

**输出**：每轮「通过项/已修复项」清单 + 终轮"无需进一步优化"结论（依据：令牌 diff 为空、冒烟 0 失败、探针 ISW==ICW、截图无回归）。

## 案例 2：接手他人页面做质量摸底

**输入**：无文档的存量页面，用户只说"帮我看看有没有问题"。

**执行**：同样五维轮次，但第 1 轮先补建基线——跑一次 jsdom 冒烟记录现有行为（防修坏无断言可查），溢出探针跑三个视口（360/768/1200），再按清单逐维检查。只报告 + 征询，不直接修交互语义类问题（见 SKILL.md 决策依据）。

**输出**：分级问题清单（样式类直接修 / 语义类列清单征询）+ 基线断言集（供后续改造防回归）。
