# 速查表类型与模板详解

> 供 cheatsheet-generator 生成各类速查表时参考，确保格式统一、信息密度高、适合打印。

## 一、速查表通用规范

### 排版规范
- 总字数控制在 1500-2500 字（1-2 页 A4）
- 使用三级标题（`###`）分组，不使用二级以上大标题
- 表格为主，每个表格不超过 8 行，超过则拆分
- 代码块使用短代码（单行或 2-3 行），不使用长代码
- 重要提示使用 `>` 引用块
- 列数控制在 3-4 列，超过则信息过密

### 内容规范
- 只收录高频、常用、易忘的知识点
- 每个条目简洁明了，不展开解释
- 命令/API 必须准确，参数完整
- 对比表格必须有明确的对比维度
- 底部添加"深入学习"链接，指向知识库对应笔记

### Frontmatter（保存到知识库时）
```yaml
---
title: XXX 速查表
tags: [速查表, 技术栈, 复习]
category: 对应分类
created: 2026-08-31
updated: 2026-08-31
difficulty: ⭐⭐
status: ✅ 内容已完善
priority: 重要
type: 速查表
---
```

## 二、命令速查表模板

### 适用场景
Git、Docker、Linux、Vim、npm、kubectl、kubectl 等命令行工具。

### 模板结构
```markdown
### XXX 命令速查表

#### 分组1（如：基础操作）
| 命令 | 说明 | 示例 |
|------|------|------|
| `command arg` | 一句话说明 | `command --option` |

#### 分组2（如：高级操作）
| 命令 | 说明 | 示例 |
|------|------|------|

#### 常用组合
```bash
# 场景1描述
command1 | command2

# 场景2描述
command3 && command4
```

#### 注意事项
> XXX

> 深入学习：[[笔记1]]、[[笔记2]]
```

### 分组建议
- 按操作类型分组（基础/进阶/高级）
- 按使用频率排序（常用的在前）
- 每个分组 5-8 条命令
- 常用组合单独列出（实际工作中高频使用的命令组合）

## 三、API / 方法速查表模板

### 适用场景
Vue3 组合式 API、Array 方法、Python 内置函数、Spring 注解、React Hooks 等。

### 模板结构
```markdown
### XXX API 速查表

#### 分类1（如：响应式 API）
| API | 说明 | 示例 | 返回值 |
|-----|------|------|--------|
| `api(arg)` | 一句话说明 | `api(value)` | 类型 |

#### 分类2（如：生命周期）
| 选项式 | 组合式 | 调用时机 |
|--------|--------|---------|

#### 注意事项
> 1. XXX
> 2. XXX

> 深入学习：[[笔记1]]、[[笔记2]]
```

### 关键要求
- API 签名完整（包含参数和返回值）
- 示例简洁（一行能说明白的不用两行）
- 注意事项必须有（API 使用中最容易踩的坑）
- 如果有新旧版本对比，单独列出（如 Vue2 Options API vs Vue3 Composition API）

## 四、概念对比速查表模板

### 适用场景
容易混淆的概念对比（var/let/const、== / ===、深拷贝/浅拷贝、Spring Bean 作用域、缓存策略等）。

### 模板结构
```markdown
### XXX 对比速查表

#### 对比1：A vs B vs C
| 特性 | A | B | C |
|------|---|---|---|
| 特性1 | 值 | 值 | 值 |
| 特性2 | 值 | 值 | 值 |
| 特性3 | 值 | 值 | 值 |

**选择建议**：
- 场景1 → 选 A，因为 XXX
- 场景2 → 选 B，因为 XXX

#### 对比2：D vs E
| 特性 | D | E |
|------|---|---|

> 深入学习：[[笔记1]]、[[笔记2]]
```

### 对比维度建议
- 定义/本质
- 语法/用法
- 性能/效率
- 适用场景
- 局限性/坑
- 选择建议（必须有，告诉用户什么时候用哪个）

## 五、架构/流程速查表模板

### 适用场景
系统架构要点、请求处理流程、部署流程、算法流程等。

### 模板结构
```markdown
### XXX 流程速查表

#### 完整流程
```
1. 步骤1 → 组件A
2. 组件A → 组件B（说明：XXX）
3. 组件B → 输出
```

#### 核心组件职责
| 组件 | 职责 | 关键接口/方法 |
|------|------|-------------|
| 组件A | 一句话 | `method()` |

#### 关键配置/注解
| 配置/注解 | 作用 | 默认值 |
|-----------|------|--------|

#### 常见问题
| 问题 | 原因 | 解决方案 |
|------|------|---------|

> 深入学习：[[笔记1]]、[[笔记2]]
```

### 流程描述要求
- 使用编号列表，每步明确
- 箭头表示数据/控制流向
- 关键步骤添加说明（括号内）
- 组件职责表必须有（帮助理解每个部分的作用）

## 六、面试高频题速查表模板

### 适用场景
面试前快速复习高频考点（Java 面试题、前端面试题、AI 面试题等）。

### 模板结构
```markdown
### XXX 面试高频题速查表（TOP 20）

#### 模块1（如：JVM）
1. **题目1**：一句话问题
   - 核心要点：要点1、要点2、要点3
   - 关键词：关键词1、关键词2

2. **题目2**：一句话问题
   - 核心要点：XXX
   - 关键词：XXX

#### 模块2（如：并发）
...

> 详细答案见对应笔记：[[笔记1]]、[[笔记2]]
```

### 面试题设计要求
- 每个模块 3-5 题，总计 15-20 题
- 题目用一句话描述（不展开）
- 核心要点 3-5 个（答题时的得分点）
- 关键词 2-3 个（面试官听到这些词就给分）
- 底部链接到详细答案笔记
