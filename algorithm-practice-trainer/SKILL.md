# 算法练习训练器

> 为算法刷题提供**分类训练、解题模板、复杂度分析、错题本管理、模拟面试**的全流程辅助。

---

## 核心原则

1. **分类突破**：按题型分类训练，每类题先掌握模板再刷题，不盲目刷题
2. **模板优先**：每类题有标准解题模板，先背模板再灵活运用
3. **复杂度必算**：每道题必须分析时间复杂度和空间复杂度，不只是 AC
4. **错题复盘**：错题必须记录原因和正确思路，定期复习，不二错
5. **由易到难**：按 简单→中等→困难 递进，不跳级，基础题熟练后再上难度

## 12 大题型概览

> 每种题型的完整解题模板、核心思路、高频题详见 [references/algorithm-templates.md](references/algorithm-templates.md)，刷题和解析时按对应题型的模板执行。

| 题型 | 核心方法 | 关键模板 | 高频题数量 |
|------|---------|---------|-----------|
| 数组与字符串 | 双指针、滑动窗口、前缀和 | 左右指针、快慢指针、滑动窗口 | 7+ |
| 链表 | 虚拟头节点、双指针、反转 | dummy节点、prev/curr反转 | 7+ |
| 栈与队列 | 单调栈、单调队列、括号匹配 | 单调递增/递减栈 | 7+ |
| 哈希表 | 计数、映射、去重 | dict计数、value→index映射 | 7+ |
| 树与二叉树 | 递归、层序遍历、BST性质 | 递归三要素、层序队列 | 8+ |
| 图 | DFS/BFS、拓扑排序、并查集 | visited+递归、Kahn算法 | 7+ |
| 动态规划 | DP五步法、背包、线性DP | 01背包倒序、完全背包正序 | 9+ |
| 回溯 | 组合、排列、子集、棋盘 | backtrack模板、startIndex/used去重 | 8+ |
| 贪心 | 区间调度、跳跃游戏、分发 | 按结束时间排序、局部最优 | 7+ |
| 二分查找 | 标准二分、边界二分、二分答案 | left<=right、左/右边界模板 | 7+ |
| 排序 | 快排、归并、堆排序、自定义排序 | pivot分区、TopK小顶堆 | 7+ |
| 位运算 | 异或、位移、掩码 | a^a=0、n&(n-1)消最低位1 | 7+ |

## 复杂度分析速查

| 数据结构/算法 | 平均时间 | 最坏时间 | 空间 |
|--------------|---------|---------|------|
| 数组访问 | O(1) | O(1) | O(n) |
| 数组插入/删除 | O(n) | O(n) | O(n) |
| 链表访问 | O(n) | O(n) | O(n) |
| 链表插入/删除 | O(1) | O(1) | O(n) |
| 哈希表查找 | O(1) | O(n) | O(n) |
| 二叉搜索树查找 | O(logn) | O(n) | O(n) |
| 平衡树查找 | O(logn) | O(logn) | O(n) |
| 快排 | O(nlogn) | O(n²) | O(logn) |
| 归并排序 | O(nlogn) | O(nlogn) | O(n) |
| 堆排序 | O(nlogn) | O(nlogn) | O(1) |
| DFS/BFS | O(V+E) | O(V+E) | O(V) |
| 二分查找 | O(logn) | O(logn) | O(1) |
| 动态规划 | 状态数×转移时间 | 同左 | 状态数 |

## 使用示例

**输入**："生成 10 道动态规划算法题，难度从简单到困难，要包含完整答案和解析"

**输出**：
- 10 道梯度练习题（简单 3 道 + 中等 4 道 + 困难 3 道）
- 每道题：题目描述、输入输出示例、约束条件、提示
- 每道题完整答案：可运行代码（含注释）、复杂度分析（时间/空间）
- 每道题详细解析：思路分析、关键步骤、常见错误、优化方向
- 同类型题目推荐（3-5 道举一反三）
- 与 `[[动态规划]]` `[[背包问题]]` 等知识库笔记双向链接

## 工作流程

### 场景一：生成刷题计划

1. 确认目标（求职/面试/竞赛/基础巩固）、目标公司级别、可用时间（周）、当前水平
2. 按题型生成刷题计划：
   - 基础阶段（2周）：数组/字符串/链表/栈队列/哈希，每类 10-15 道简单+中等
   - 进阶阶段（3周）：树/图/二分/排序/位运算，每类 10-15 道中等
   - 高级阶段（3周）：动态规划/回溯/贪心，每类 15-20 道中等+困难
   - 冲刺阶段（2周）：LeetCode 热题 100 + 剑指 Offer + 模拟面试
3. 每周列出具体题目清单，标注难度和知识点
4. 每天建议刷题量（2-3 道，含复盘）

### 场景二：单题深度解析

1. 用户提供题目（题号/题目描述）
2. 生成解析报告：
   - 题目理解（一句话总结、输入输出示例、约束条件）
   - 解题思路（暴力解法→优化思路→最优解法）
   - 算法选择（为什么用这个算法，适用场景）
   - 解题模板（这类题的通用模板）
   - 完整代码（Python/Java，含详细注释）
   - 复杂度分析（时间/空间，为什么）
   - 边界条件（空输入、单元素、最大值、重复值）
   - 常见错误（易错点、调试技巧）
   - 相关题目（同类题 3-5 道，举一反三）

### 场景三：错题本管理

1. 用户提供错题（题目 + 错误原因 + 错误代码）
2. 生成错题记录：
   - 题目信息（题号、难度、题型、知识点）
   - 错误分析（错误类型：思路错/边界错/语法错/复杂度超时/粗心）
   - 错误原因（具体哪里错了，为什么会错）
   - 正确思路（标准解法，关键步骤）
   - 正确代码（含注释）
   - 复盘要点（这道题的核心考点，下次遇到怎么想）
   - 复习提醒（1天后、3天后、7天后复习，间隔重复）
3. 错题按题型和错误类型分类，定期生成错题复习清单

### 场景四：算法模拟面试

1. 确认面试级别（大厂/中厂/小厂）、岗位（后端/前端/算法/全栈）、时长（45分钟/60分钟）
2. 按真实面试流程进行：
   - 自我介绍中的技术亮点追问（5分钟）
   - 项目中的算法问题追问（5分钟）
   - 算法题 1（简单/中等，15分钟）：边写边讲，面试官追问
   - 算法题 2（中等/困难，20分钟）：优化思路，复杂度分析
   - 反问环节（5分钟）
3. 面试结束后生成评价报告：
   - 各环节评分（思路清晰度/代码质量/复杂度分析/沟通表达）
   - 答题亮点
   - 不足与改进建议
   - 知识盲区清单
   - 推荐补充练习的题目

## 输出规范

1. 刷题计划每道题标注：题号、题目名、难度、题型、知识点、建议用时
2. 单题解析必须有：解题思路（至少2种）、完整代码、复杂度分析、边界条件、相关题目
3. 代码必须可运行，含详细注释，变量名清晰
4. 错题记录必须分析错误原因，不只给正确答案
5. 模拟面试必须有具体评分和改进建议，不是模糊的"还不错"
6. 所有复杂度分析必须说明为什么（如"因为遍历了 n 个元素，每个元素操作 O(1)，所以 O(n)"）

## 质量检查清单

- [ ] 每道题有明确的题目描述、输入输出示例、约束条件
- [ ] 每道题有完整的可运行答案代码（含注释）
- [ ] 每道题有详细解析（思路分析、关键步骤、复杂度分析）
- [ ] 难度标注准确（简单/中等/困难与题目实际难度匹配）
- [ ] 题型分类准确（与12大题型对应）
- [ ] 复杂度分析正确（时间复杂度和空间复杂度）
- [ ] 进阶题目有多种解法对比（暴力→优化→最优）
- [ ] 题目与知识库笔记关联（添加 `[[]]` 双链）
- [ ] 同类型题目有 3-5 道，覆盖常见变体
