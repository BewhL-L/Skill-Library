# 间隔复习算法详细说明（权威版）

> 供 knowledge-review-spaced 计算复习间隔时参考。本文件是复习算法的**唯一权威口径**：`SKILL.md` 的「复习间隔算法概览」与 `review-templates.md` 的字段/模板都以本文件为准，三处必须一致，出现冲突时以本文件为准。

---

## 〇、一套模型，三个输入

每次复习只采集三个输入，算出下一次间隔：

| 输入 | 字段 | 取值 | 来源 |
|------|------|------|------|
| 已通过次数 | `review_count` | 整数，从 0 开始 | Frontmatter |
| 难度系数 | `ease_factor`（简称 EF） | 1.3–3.0，默认 2.5 | 难度初始化 + 每次复习微调 |
| 本次复习质量 | `quality`（q） | 1–5 整数 | 用户复习后评分 |

> 不再并行使用"固定间隔表 × 难度系数 × ✅🟡❌三级"那套旧口径，避免同一笔记算出两个不同的下次日期。难度只影响**初始 EF**，质量评分统一用 **1–5 分**（想用粗粒度的，见第六节的 ✅🟡❌→分数映射）。

## 一、艾宾浩斯遗忘曲线（为什么要在临界点复习）

### 遗忘规律（无干预时的自然遗忘率）
- 学习后 20 分钟：遗忘约 42%
- 学习后 1 小时：遗忘约 56%
- 学习后 9 小时：遗忘约 64%
- 学习后 1 天：遗忘约 67%
- 学习后 2 天：遗忘约 72%
- 学习后 6 天：遗忘约 75%
- 学习后 31 天：遗忘约 79%

### 对算法的指导
- 在遗忘率约 30–40%（"快要忘但还没全忘"）时复习，记忆保持时间延长最明显，这正是间隔逐次拉长的依据。
- 每复习一次且质量达标，记忆痕迹增强，下一次间隔按 EF 倍数拉长；多次达标后进入长期记忆，频率大幅降低。
- 遗忘曲线是"为什么"，SM-2 是"具体怎么排期"，二者不冲突。

## 二、标准 SM-2 间隔算法（本 Skill 采用的简化版）

### 2.1 间隔主公式

设本次为第 n 次"通过"（q≥3 算通过），当前间隔 `I(n)`：

```
若 q < 3（没记住，q=1或2）：
    review_count 归零，I = 1 天（明天重新学）

若 q ≥ 3（通过）：
    n = 1（第 1 次通过）：I(1) = 1 天
    n = 2（第 2 次通过）：I(2) = 6 天
    n ≥ 3             ：I(n) = round( I(n-1) × EF )   // 四舍五入，最小 1 天
```

- 第 1、2 次是固定锚点（1 天、6 天），用于先把短期记忆夯实；
- 第 3 次起进入"上次间隔 × 难度系数 EF"的指数拉长阶段；
- EF 默认 2.5，因此标准序列大致为：**1 → 6 → 15 → 38 → 94 → 235 …天**（随每次质量微调而浮动，不是写死的固定表）。

### 2.2 EF（ease_factor）更新规则

每次复习（无论通过与否）都先更新 EF，再算间隔：

| 本次质量 q | EF 调整 | 说明 |
|-----------|---------|------|
| 5（完全记住、能迁移） | EF + 0.10 | 记得越牢，后续间隔拉得越疏 |
| 4（基本记住、少量遗忘） | EF + 0.05 | 轻微奖励 |
| 3（有点印象、细节遗忘多） | EF 不变 | 临界，维持节奏 |
| 2（比较模糊、需重学） | EF − 0.15 | 缩短后续间隔 |
| 1（完全忘了） | EF − 0.30 | 明显缩短，并重置通过次数 |

约束：调整后 **EF 一律裁剪到 [1.3, 3.0]**——再简单也不超过 3.0（防止间隔爆炸），再难也不低于 1.3（防止间隔永远是 1 天）。

```
EF_new = clamp( EF_old + delta(q), 1.3, 3.0 )
delta(5)=+0.10  delta(4)=+0.05  delta(3)=0  delta(2)=-0.15  delta(1)=-0.30
```

### 2.3 完整计算步骤（伪代码）

```
function schedule(note, q):
    # 1. 更新难度系数
    note.EF = clamp(note.EF + delta(q), 1.3, 3.0)

    # 2. 根据质量决定间隔与通过次数
    if q < 3:                         # 没记住
        note.review_count = 0
        note.interval = 1
    else:                             # 通过
        note.review_count += 1
        n = note.review_count
        if n == 1:   note.interval = 1
        elif n == 2: note.interval = 6
        else:        note.interval = max(1, round(prev_interval * note.EF))

    # 3. 推进日期与状态
    note.last_review = today
    note.next_review = today + note.interval 天
    note.review_status = next_status(note.review_status, q)   # 见第四节
```

### 2.4 计算示例

**例 1（一路顺利，标准 EF=2.5）**
- 第 1 次 q=4：EF 2.5→2.55，n=1，I=1，明天复习
- 第 2 次 q=5：EF 2.55→2.65，n=2，I=6
- 第 3 次 q=5：EF 2.65→2.75，n=3，I=round(6×2.75)=round(16.5)=17 天
- 第 4 次 q=4：EF 2.75→2.80，n=4，I=round(17×2.80)=48 天

**例 2（中途卡壳，回退）**
- 已到 n=3、I=15，本次 q=2：EF 2.5→2.35，通过次数归零，I 重置为 1 天，状态回退（见第四节），明天重学。

**例 3（临界维持）**
- n=2、EF=2.5，本次 q=3：EF 维持 2.5，n=3，I=round(6×2.5)=15 天。

## 三、难度如何进入模型：难度 → 初始 EF

难度不再用一套独立的"固定间隔 × 系数"，而是在**笔记首次纳入复习时决定初始 EF**：越难的笔记初始 EF 越低，间隔天然更密；越简单初始 EF 越高，间隔更疏。之后都走同一套 SM-2 主公式。

| 难度 | 初始 EF₀ | 含义 | 第 3 次间隔（I=6 后，质量恒为 4 时的近似） |
|------|---------|------|------------------------------------------|
| ⭐ 入门 | 2.7 | 简单、忘得慢，间隔更疏 | 约 16–17 天 |
| ⭐⭐ 进阶 | 2.6 | 略放宽 | 约 16 天 |
| ⭐⭐⭐ 高级 | 2.5 | 标准（默认） | 15 天 |
| ⭐⭐⭐⭐ 专家 | 2.3 | 偏难、忘得快，间隔更密 | 约 14 天 |
| ⭐⭐⭐⭐⭐ 资深 | 2.1 | 最难、高频复习 | 约 13 天 |

> 这样"难度影响复习密度"的诉求被保留，但全程只有 EF 一套系数，不会再出现"难度系数"和"ease_factor"两个并行数字。难度后续可被真实复习质量修正：如果一篇⭐⭐⭐⭐⭐的笔记连续 q=5，EF 会自动涨上来，间隔自然放宽，无需手动改难度。

## 四、复习状态机（与 SKILL.md / 模板完全一致）

### 4.1 四个状态
- `new`：刚纳入，尚未完成第一次复习
- `learning`：正在建立记忆
- `reviewing`：基本成型，进入拉长间隔阶段
- `mastered`：连续高质量，进入长期记忆（复习清单默认不再每天催，但保留低频巩固）

### 4.2 流转规则（用"连续达标计数 streak"判断）
```
new        → learning   ：完成任意一次评分后
learning   → reviewing  ：连续 2 次 q ≥ 3
reviewing  → mastered   ：连续 3 次 q ≥ 4
回退（出现 q ≤ 2）：
    mastered  → reviewing （掉一档，streak 清零）
    reviewing → learning  （掉一档，streak 清零）
    learning  → 保持 learning，I 重置为 1 天
任意状态 q ≤ 2：连续达标计数 streak 清零、review_count 归零、I=1
```

> 说明：`review_count` 表示"连续通过的次数"，一旦 q≤2 即归零，这与 2.1 的间隔重置严格对应；不要另设一个只增不减的计数器，否则状态机和间隔会打架。

## 五、每日复习清单的优先级排序

当天待复习笔记可能多于可投入时间，按下面的**单一排序分**从高到低取，默认每日 10–15 篇（约 2–3 小时），超出的顺延。

```
排序分 = 逾期天数 × 5
       + (6 - 难度星级) 取反 → 难度越高越优先：难度星级 × 3
       + 优先级数值（核心=3 / 重要=2 / 一般=1）× 2
       + (10 - review_count) × 1     // 通过次数越少越优先
分越高越靠前。
```

四个因子与权重：
1. **逾期天数（权重最高）**：逾期 >7 天 🔴紧急；3–7 天 🟠重要；1–2 天 🟡普通；今日到期 🟢正常。
2. **难度（星级越高越优先）**：难的内容更容易忘。
3. **笔记优先级**：P0/核心知识点优先。
4. **通过次数**：还没记牢（次数少）的优先，已多次通过的可延后。

## 六、粗粒度评分映射（想用 ✅🟡❌ 时）

如果用户不想打 1–5 分，允许用三档快速自评，但内部必须换算成统一分数再走算法：

| 粗粒度 | 换算 q | 判定 | 对应间隔动作 |
|--------|-------|------|-------------|
| ✅ 完全记住（不看答案能完整回忆、能迁移） | 5 | 通过 | 走 2.1 通过分支，EF+0.10 |
| 🟡 模糊记得（有印象、看提示能回忆） | 3 | 临界通过 | 走通过分支但 streak 不增长为"高质量"，EF 不变 |
| ❌ 忘记了（没印象、需重学） | 1 | 未通过 | 重置次数、I=1、状态回退、EF−0.30 |

> 即：✅/🟡/❌只是 5/3/1 的快捷输入，**不是另一套算法**。换算后仍按第二~四节计算，保证结果唯一。

## 七、复习历史记录格式（Frontmatter）

### 7.1 标准字段（与 review-templates.md 一致）
```yaml
review_status: reviewing      # new / learning / reviewing / mastered
review_count: 3               # 连续通过次数，q≤2 归零
last_review: 2026-09-04
next_review: 2026-09-19
ease_factor: 2.55             # 范围 1.3-3.0
interval: 15                  # 当前间隔（天）
streak: 2                     # 连续高质量(q≥4)次数，用于状态流转
```

### 7.2 可选：最近复习流水（只保留最近 5 条，倒序）
```yaml
review_history:
  - date: 2026-09-04
    quality: 4
    interval_before: 6
    interval_after: 15
    ef_before: 2.50
    ef_after: 2.55
```
规则：只留最近 5 条避免 Frontmatter 膨胀；每条记日期、质量、调整前后间隔与 EF；最新的在最前。

## 八、特殊情况处理

### 新笔记初始化
- `review_status=new`、`review_count=0`、`streak=0`
- `ease_factor` 按难度取初始值（第三节，默认 2.5）
- `last_review` 留空，`next_review=创建日期`（建议当天先复习一次夯实短期记忆）

### 长期未复习（"接近遗忘"）
- 逾期 >30 天：不直接沿用旧间隔，本次最高按 🟡(q=3) 处理，`review_count` 退回到不超过 2，间隔重新从 6 天档起步。
- 若直接评 ❌(q=1)，按未通过重置。

### 内容发生更新的笔记
- **重大更新**（改了原理/核心结论）：`review_count=1`、`streak=0`，状态回到 learning，1 天后重新复习（内容变了，旧记忆需覆盖）。
- **小修改**（错别字、排版、补链接）：不影响复习计划，保持原间隔。

### 批量复习的量控
- 每日 10–15 篇、每篇 10–15 分钟；超过 15 篇只取排序分最高的 15 篇，其余顺延。
- 每周至少留 1 天不安排新内容，专门清逾期笔记。

## 九、与 Obsidian Dataview 集成（速览）

可直接复用的查询（今日待复习、逾期、状态分布、分类掌握率、本周记录、薄弱笔记）**完整 6 条见 [review-templates.md](review-templates.md) 的「与 Obsidian Dataview 联动」**，此处只给最常用的今日清单：

```dataview
TABLE WITHOUT ID
  file.link AS "笔记",
  difficulty AS "难度",
  next_review AS "下次复习",
  review_count AS "连续通过",
  review_status AS "状态"
WHERE next_review <= date(today) AND review_status != "mastered"
SORT (date(today) - next_review).days DESC, difficulty DESC
LIMIT 15
```

> 算法口径以本文件为准；字段名、模板与查询以 review-templates.md 为准；两者字段一一对应，不得各写一套。
