# 变更记录（Changelog）

本文件记录 `career-life-guidance` Skill 的所有显著变更。

版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)：主版本.次版本.修订号（破坏性结构调整升主版本；新增能力且向后兼容升次版本；勘误与小修升修订号）。
日期采用用户本地时区（Asia/Shanghai）。

---

## [2.0.0] - 2026-09-12

### 变更背景

以标杆成品《普通一本零基础转行 AI 全栈：从决定到站稳中产的完整人生路线图》（六篇四十七章、约 19 万字）为基准，对本 Skill 做一次成品级对齐：补齐"书籍级手册"的固定部件、密度标准与前辈语气配方，使方法论从"章节清单"升级为"照着就能产出同等量级与质感成品"的操作规范。

### Added（新增）

- **`references/12-document-anatomy.md`（新增文件）**：成品手册解剖与固定部件模板，覆盖
  - 全书部件全景与篇幅配比（第三篇项目实战占 25%-35% 等）
  - Frontmatter 12 字段与 `summary` 版本说明书写法
  - "写在前面"四段结构（状态白描 / 掏心窝子三句话 / 版本说明 / 难度预告与召唤）
  - 能力体系总览四件套（阶段总表 / 维度优先级矩阵 / 核心增量表 / 按状态阅读导航图）
  - 篇级结构（篇首导言三口气、篇小结四段式）
  - 章级八零件（标题带优先级 / 开场大白话 / 表格+来源行 / 加粗定锚 / 红线引用块 / 误区真相对 / 📌本章小结 / 📋行动清单）
  - 收尾套件（风险提示 8 条 / 结语五句话+金句 / 参考文献规范 / 三段式尾部导航 / 免责声明四段 / 文档信息块）
- **`CHANGELOG.md`（本文件，首次建立版本变更记录）**。
- **SKILL.md 新增"二、先认标杆：一份合格成品长什么样"**：v1-v4 量级标准、成品固定十件套、密度指标下限（每章 1-3 张表、全书 20+ Mermaid、每章小结与 5-8 条行动清单等）。
- **`references/09-writing-style.md` 新增第 8、9 节**：前辈语气句式配方库（开场/三句话/定锚句/误区真相/数字说服/现实托底/行动召唤/8 类禁止句式）与本章小结、篇小结、行动清单的具体写法。
- **`references/03-six-phase-structure.md` 新增第 3 节"篇与章的固定外观"**：篇三件套、章八零件、篇前部件不可省的硬性要求。

### Changed（变更）

- **SKILL.md 整体重构**：
  - 工作流 8 步全面嵌入成品套件动作（第 3 步先立写在前面与总览、第 5 步明确项目篇篇幅占比、第 7 步统一收尾套件、第 8 步大文件分段验证）。
  - 写作风格章升级为"风格与前辈语气配方"，给出语气四件套。
  - 交付前校验清单重组为身份边界 / 结构完整 / 内容质量 / 格式密度 / 交付验证五组，新增固定套件齐全度、密度指标、四处版本一致性等检查项。
  - 参考文件导航表新增 12 号文件与 CHANGELOG 入口。
- **`references/10-obsidian-output.md`**：
  - Frontmatter 由 10 字段对齐为标杆实际的 12 字段（补 `date / version / pre / next / summary`，明确 `summary` 为版本说明书）。
  - 尾部导航由单一"相关笔记"升级为相关笔记 / 前置知识 / 延伸阅读三段式；新增免责声明与文档信息块规范。
  - 新增字数实测要求（中文字符与总字符分别统计、注明口径）与 Mermaid 全书必备清单。
- **`references/09-writing-style.md`**：篇幅与密度节补量化下限；自检清单从 8 条扩到 11 条；统一全书图标语义（🔴📌📋 等）。
- **`references/03-six-phase-structure.md`**：完整目录示例补齐 Frontmatter、写在前面、总览四件套、篇首导言/篇小结与全部收尾部件；后续章节顺延重新编号。
- **`assets/document-template.md`**：可填充骨架全面对齐成品——补写在前面、总览四件套、每章八零件占位（📌小结/📋行动清单）、每篇小结、风险提示/结语/参考文献/三段式导航/免责声明/文档信息；填充顺序与裁剪提示同步更新。

### 一致性约定（本次确立，后续迭代必须遵守）

- 版本号在 **Frontmatter `version`、文末文档信息块、CHANGELOG、对用户的交付回复** 四处保持一致。
- 同一数字跨章节必须能对账；表格引用外部事实必须带来源行；预测必须给三情景。
- 任何裁剪都不得整组删除收尾套件；用户排除项在后续迭代中不得加回。
