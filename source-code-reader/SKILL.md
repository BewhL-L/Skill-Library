# 源码阅读助手

> 为技术框架生成**系统化源码阅读方案**，包含阅读路线、核心流程、设计模式、数据结构、性能优化，解决"源码不知道从哪读、读了就忘、看不懂设计"的问题。

---

## 核心原则

1. **目标驱动**：先明确阅读目标（学习什么、解决什么问题），不盲目通读
2. **宏观到微观**：先理解整体架构，再深入核心流程，最后看细节实现
3. **运行验证**：搭建可运行环境，通过断点/日志验证理解，不只是静态阅读
4. **设计优先**：关注设计模式、架构思想、关键决策，不纠结每一行代码
5. **输出笔记**：每读完一个模块输出阅读笔记，整理架构图和时序图，形成知识积累

---

## 源码阅读五步法

| 步骤 | 内容 | 时间 | 产出 |
|------|------|------|------|
| 1. 准备阶段 | 明确目标、搭建环境、了解背景、找到入口 | 30分钟 | 阅读环境和入口点 |
| 2. 宏观架构 | 画架构图、理解模块划分、梳理数据流、识别核心接口 | 1-2小时 | 整体架构图 |
| 3. 核心流程 | 选1-2个核心流程、画时序图、理解每步实现、关注设计模式 | 2-4小时 | 核心流程时序图 |
| 4. 细节深入 | 深入核心类、理解算法、关注异常和边界、对比实现优劣 | 4-8小时 | 核心类分析笔记 |
| 5. 总结输出 | 整理图表、撰写笔记、提炼设计思想、关联知识库 | 1-2小时 | 源码阅读笔记 |

> 五步法的详细执行要点和源码阅读笔记模板详见 [references/source-code-reference.md](references/source-code-reference.md)

## 使用示例

**输入**："帮我生成 Vue3 响应式系统的源码阅读路线，要深入到 Proxy 和依赖收集的实现细节"

**输出**：
- 阅读路线（5 个阶段，预计 8 小时）：
  - 阶段1：准备（30分钟）- 克隆 vuejs/core 仓库，导入 IDE，找到入口
  - 阶段2：宏观架构（1小时）- @vue/reactivity 模块结构，核心类关系图
  - 阶段3：核心流程（3小时）- reactive() 创建响应式对象 → effect() 副作用 → track() 依赖收集 → trigger() 触发更新，完整时序图
  - 阶段4：细节深入（3小时）- Proxy handler 实现、WeakMap 依赖存储结构、ref/reactive/computed 区别、调度器实现
  - 阶段5：总结输出（30分钟）- 整理架构图和时序图，撰写源码阅读笔记
- 核心类清单（ReactiveEffect、TrackOpTypes、TriggerOpTypes、Scheduler）
- 关键数据结构（targetMap: WeakMap<target, Map<key, Set<effect>>>）
- 设计模式分析（观察者模式、代理模式、策略模式）
- 关键代码片段（带详细注释）
- 性能优化点（批量更新、调度器、依赖清理）
- 与 `[[Vue3响应式原理]]` `[[Proxy]]` `[[依赖收集]]` 等知识库笔记双向链接

## 工作流程

### 场景一：生成完整源码阅读方案

1. **确认需求**：
   - 目标框架和版本
   - 阅读目标（学习什么、解决什么问题）
   - 时间预算（每天能读多久、总共多久）
   - 当前水平（对框架的熟悉程度）

2. **生成阅读路线**：
   - 按阶段划分（准备→宏观→核心流程→细节→总结）
   - 每个阶段列出阅读内容、核心类、预计时间
   - 标注优先级（必读/选读/深入）

3. **生成核心流程梳理**：
   - 选择 2-3 个最核心的流程
   - 每个流程画出时序图/调用链
   - 标注每个步骤的核心类和方法
   - 说明设计模式和关键决策

4. **生成设计模式分析**：
   - 框架中使用的主要设计模式
   - 每个模式的应用位置和作用
   - 为什么用这个模式（解决了什么问题）

5. **生成关键数据结构分析**：
   - 核心数据结构（如 BeanDefinition、VNode、Dependant）
   - 每个结构的字段和作用
   - 数据在流程中的流转

6. **生成性能优化点分析**：
   - 框架中的性能优化技巧
   - 每个优化的原理和效果
   - 可以借鉴到自己项目中的点

7. **生成阅读笔记模板**：按模板为每个模块生成阅读笔记框架

### 场景二：单个核心流程深度解析

1. 确认要解析的流程（如"Spring Bean 的创建流程"、"Vue3 的响应式更新流程"）
2. 生成深度解析：
   - 流程概述（一句话说清楚）
   - 完整时序图（每步的类和方法）
   - 每步的详细说明（做了什么、为什么这样做）
   - 关键代码片段（带注释）
   - 设计模式分析
   - 常见问题和陷阱
   - 与知识库笔记的关联 `[[]]`

### 场景三：设计模式分析

1. 确认框架和关注的设计模式（如"Spring 中用了哪些设计模式"）
2. 生成设计模式分析：
   - 模式列表（每个模式的应用位置）
   - 每个模式的详细分析：
     - 模式定义
     - 在框架中的应用（具体类和方法）
     - 解决了什么问题
     - 优缺点
     - 可以借鉴到自己项目中的点
   - 模式之间的协作关系
   - 框架的整体设计哲学

### 场景四：源码阅读笔记生成

1. 确认已阅读的模块和理解程度
2. 按源码阅读笔记模板生成完整笔记：
   - 阅读目标
   - 整体架构图
   - 核心模块表
   - 核心流程时序图
   - 关键代码片段
   - 设计模式表
   - 关键数据结构表
   - 性能优化点
   - 关键 Takeaway
   - 与知识库关联 `[[]]`
   - 实践启发
3. 存入知识库对应分类

## 输出规范

1. 阅读路线必须分阶段，每阶段有明确的阅读内容和时间估算
2. 核心流程必须有时序图（文字描述或 Mermaid），不能只有文字
3. 设计模式分析必须说明"为什么用这个模式"，不是只列模式名
4. 关键代码片段必须有详细注释，说明每步做什么
5. 性能优化点必须有原理说明和效果数据
6. 所有核心概念添加 `[[]]` 双链，与知识库关联
7. 阅读笔记必须包含架构图和时序图，图文结合
8. 实践启发必须具体可执行，不是"这个设计很好"

## 与其他 Skill 的协作

- **与 `tech-concept-deep-dive` 协作**：源码阅读中发现的核心技术概念用深度拆解器生成详细笔记，源码阅读引用这些笔记
- **与 `project-based-learning` 协作**：源码中学到的设计思想和最佳实践应用到项目中，用项目驱动学习生成器生成实践项目
- **与 `code-practice-generator` 协作**：源码中的核心算法用代码实践生成器生成可运行的简化实现
- **与 `knowledge-review-spaced` 协作**：源码阅读笔记纳入复习计划，间隔重复巩固
- **与 `learning-path-planner` 协作**：源码阅读纳入学习路线的高级/专家阶段
- **与 `cheatsheet-generator` 协作**：源码核心流程、设计模式整理成速查表
- **与 `ai-assisted-coding` 协作**：让 AI 先梳理调用链与候选入口做广度扫描，人再按本 skill 方法精读关键路径做深度判断
- **与 `english-for-developers` 协作**：源码注释、标识符、RFC/设计文档的英文阅读由技术英语技能支撑
