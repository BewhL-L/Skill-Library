# AI 辅助编程实战手册（Prompt 库 · 工作流 · 红线 · 验证）

> 供 ai-assisted-coding 在实际协作中参考。包含 Prompt 五要素、分场景可复制模板、AI 编辑器工作流、五条红线、反模式、Debug 黄金模板、验证清单与项目规则文件模板。

---

## 一、Prompt 五要素（缺一不可）

| 要素 | 作用 | 写不好的后果 | 示例片段 |
|------|------|-------------|---------|
| ① 角色/身份 | 设定专业视角与回答深度 | 答案过浅或跑偏 | "你是有 8 年经验的 Java 后端工程师" |
| ② 上下文背景 | 让答案贴合你的项目 | 给出版本不符/跑不通的代码 | "Spring Boot 3.2 + JDK17 + MyBatis-Plus，模块是订单服务" |
| ③ 具体任务 | 明确要产出什么 | 答非所问、范围失控 | "只写 Service 层的下单方法，含幂等与事务" |
| ④ 输出格式 | 减少二次整理 | 大段散文、无法直接用 | "按文件分块给代码，每块前标注文件路径，最后给 3 个风险点" |
| ⑤ 约束与红线 | 圈定边界 | 引入禁用库/不安全写法 | "不用 JPA、不写原生 SQL 拼接、参数全部预编译" |

> 一个判断标准：把你的 Prompt 发给一个**不了解你项目的资深同事**，他若还需要反问 3 个以上问题，说明上下文不足。

### 1.1 通用骨架（可直接套）

```
你是【角色】。
背景：我在做【项目/功能】，技术栈是【语言+框架+版本】，相关代码/结构是【贴关键代码或目录】，现在要解决【问题】。
任务：请【具体、单一、可验证的任务】。
要求：
- 输出格式：【分文件代码 / 步骤列表 / 对比表 / 先计划后代码】
- 约束：【不许用 X、必须处理 Y、兼容 Z】
- 先不要直接给全部代码，先列出你的实现计划和 2 个备选方案让我确认。
```

## 二、分场景 Prompt 模板库（可复制）

### 2.1 解释概念（学习模式，引导式优先）

```
你是我的编程私教。我目前【水平，如"会 Java 语法但没接触过并发"】。
请讲解【概念】，要求：
1. 先用一个生活类比让我建立直觉，再给严谨定义；
2. 说明"没有它会怎样、它解决什么问题"；
3. 给一个 20 行内的最小可运行示例并逐行注释；
4. 不要一次讲完，先讲第一部分，然后出 1 道小题考我，我答对再继续。
```

### 2.2 代码生成（生成模式，垂直切片）

```
你是资深【栈】工程师。基于以下上下文写【某功能】：
- 技术栈与版本：【…】
- 已有代码：【贴实体/接口/相关类】
- 目录与命名约定：【…】
请：
1. 先给实现计划（拆成 ≤4 步）与涉及文件清单，等我确认；
2. 确认后按文件分块给完整可运行代码，每块标注文件路径；
3. 每块末尾用 3 行说明关键设计决策；
4. 最后列出这段代码最可能出问题的 3 个点及自测方法。
约束：【…】
```

### 2.3 AI Debug 黄金模板（调试模式）

```
请帮我定位一个 Bug，先不要急着给补丁。
【问题标题】
- 期望结果：
- 实际结果：
- 完整报错堆栈（从下往上读，含 Caused by）：
- 复现步骤（稳定/偶发）：
- 运行环境（OS / 语言版本 / 框架版本）：
- 相关代码（最小可复现片段，标注文件）：
- 最近改动（改了什么代码/配置/依赖后出现）：
- 已尝试：试过什么、结果如何。
请输出：按可能性排序的 3 个根因，每个给"为什么是它 + 如何验证（命令/断点/日志）"，我验证后把结果回喂给你。
```

### 2.4 重构（质量模式，先分析后改）

```
先不要改代码。请审查下面这段代码：
【贴代码】
1. 列出所有代码坏味道（命名/重复/长函数/耦合/魔法数/异常吞没…）并标注位置；
2. 给出小步重构计划，每步可独立运行、测试不中断；
3. 我确认后，一次只给一步的 diff（改前→改后）与理由；
4. 指出哪些地方行为可能变化、需要补什么测试。
```

### 2.5 生成测试

```
为下面的【函数/类】生成测试：
- 测试框架：【JUnit5+Mockito / Vitest / pytest】
- 按"正常路径 / 边界（空、单元素、最大值、null）/ 异常（非法输入、依赖失败）"三类组织；
- 每个用例给： Given-When-Then 注释、明确断言（不要只断言不抛异常）；
- 标注哪些分支还没覆盖、建议补的用例。
代码：【…】
```

### 2.6 代码审查（让 AI 挑刺）

```
以挑剔的资深 Reviewer 视角审查这段代码，按四个维度各列问题，按严重度 P0/P1/P2 标注：
- 正确性与 Bug（边界、并发、空指针、资源泄漏）
- 安全（注入、鉴权、敏感信息、越权）
- 性能（N+1、循环 IO、不必要对象、锁粒度）
- 可维护性（命名、职责、重复、可读性、测试）
每条给：问题、为什么是问题、最小修复建议。最后给总体评价与是否可合入的结论。
代码：【…】
```

### 2.7 让 AI 自我质疑 / 多方案对比

```
针对【问题】给我 3 个不同方案（保守/平衡/激进），用表格对比：实现复杂度、时间/空间复杂度、可维护性、扩展性、风险。给出你的推荐和理由，再扮演反对者列出推荐方案最可能失败的 2 个场景。
```

## 三、AI 编辑器 / 工具工作流

### 3.1 通用协作节奏（与工具无关）
1. **搭骨架**：让 AI 生成目录、配置、空类/接口、依赖清单
2. **垂直切片**：一个功能从前端→接口→服务→数据库端到端打通，再做下一个（不要先让 AI 写完全部前端）
3. **Diff 审查**：AI 的每处改动逐块看 Diff，看懂一块接受一块，不做"全部接受"
4. **@ 引用上下文**：用编辑器的文件/符号引用把相关代码喂给 AI，优于整段粘贴
5. **会话收敛**：一个会话围绕一个主题；主题切换就新开会话，避免上下文污染

### 3.2 常见工具能力地图（以官方文档为准，能力会快速演进）

| 工具形态 | 代表 | 最适合 | 注意 |
|---------|------|-------|------|
| 对话式大模型 | ChatGPT/Claude/Gemini/豆包 | 解释、方案、评审、生成片段 | 无项目上下文，需手动喂 |
| IDE 内补全 | GitHub Copilot 等 | 行内/函数级补全、样板代码 | 补全不等于正确，仍需验证 |
| AI 编辑器/Agent | Cursor、Windsurf 等 | 多文件改动、Composer/Agent 流 | 控制改动范围，逐处接受 Diff |
| 终端 AI CLI | 各类 AI shell/coding CLI | 命令生成、脚本、批量改造 | 涉及删除/部署的命令先人工确认 |

> 选型原则：学习阶段优先"解释强、可追问"的对话式；真实项目用能读项目上下文的编辑器/Agent；不要同时依赖多个自动改代码的 Agent，避免互相覆盖。

## 四、五条红线（任何时候不可破）

1. **AI 代码必须逐行看懂**：讲不清的不许 commit；先让 AI 讲到你懂
2. **安全与资金相关代码重点自审**：鉴权、支付、加密、权限、SQL、外部回调——AI 生成后必须人工逐行核对，不接受"看起来对"
3. **不看就不许合入**：禁止整段"全部接受"后直接提交；每处 Diff 都要过目
4. **要能独立讲清每个模块**：面试/答辩/交接时脱离 AI 也能讲架构与关键决策，否则说明能力没长在你身上
5. **AI 是结对伙伴不是替代品**：最终架构判断、技术选型、上线决策在你；AI 给候选，你担责任

> 配套习惯：密钥/Token/个人数据、内部源码不要随意贴到不合规的外部服务；遵守你所在公司对代码外发与 AI 工具的规定。

## 五、常见反模式（对照自查）

| 反模式 | 表现 | 正确做法 |
|--------|------|---------|
| 一句话甩锅式提问 | "帮我做个 XX 系统" | 拆任务、给上下文、垂直切片逐步来 |
| 盲抄盲跑 | 复制就运行，报错再问 | 先读懂，再运行，带着预期验证 |
| 补丁叠加 | 报错→贴 AI→改→又报错→再贴，不找根因 | 用 Debug 模板做假设-验证，找根因 |
| 全部接受 Diff | Agent 改了 20 个文件一键接受 | 逐块审查，控制改动范围 |
| 幻觉信任 | 把 AI 说的 API/参数/数字当事实 | 关键处查官方文档/源码/实际运行 |
| 学习被替代 | 练习全让 AI 写，自己只敲回车 | 先自己做，卡住再让 AI 给提示而非答案 |
| 上下文污染 | 一个会话从前端聊到部署再聊算法 | 按主题新开会话，保持上下文聚焦 |
| 无沉淀 | 同样问题反复问 | 沉淀 Prompt 库、规则文件、踩坑笔记 |

## 六、AI 产出的四步验证闭环

1. **看懂**：能脱稿讲清每段在做什么、为什么这么写、关键参数含义
2. **运行**：在本地/测试环境真实跑通主路径与边界，不凭"应该能跑"
3. **测试**：核心逻辑有单测，覆盖正常/边界/异常；让 AI 生成的测试要检查断言是否有效
4. **静态检查**：过 lint / 类型检查 / 格式化；处理掉 warning，不带着告警合入

> 学习场景再加第 5 步**默写**：关掉 AI，把核心逻辑自己重写一遍；写不出说明还没会。

### 6.1 识别 AI 幻觉的信号
- 引用了**不存在的**函数/参数/配置项/依赖版本
- 给出的 API 用法与你所用**版本不符**（框架大版本升级后尤其常见）
- 数字、性能结论、"官方推荐"说得很确定却给不出来源
- 代码"自洽但跑不通"：命名一致、逻辑好看，但调用了项目里不存在的方法
- 应对：让 AI 给出处 → 查官方文档/源码 → 最小例子实测，三者对不上以官方与实测为准。

## 七、项目级 AI 规则文件模板

把团队/项目约定固化下来，让每次 AI 输出默认合规（文件名按工具不同，如 `.cursorrules`、`AI-CONVENTIONS.md`、Copilot Instructions）：

```markdown
# 项目 AI 协作约定
## 技术栈（锁定版本）
- 后端：Java 17 + Spring Boot 3.2 + MyBatis-Plus；前端：Vue3 + TS + Vite
## 目录与命名
- 后端分层 controller/service/mapper/entity，类名 UpperCamelCase，方法 lowerCamelCase
## 强制
- 所有外部输入做校验；SQL 一律参数化/预编译，禁止字符串拼接
- 接口返回统一 Result<T>；异常走全局 @RestControllerAdvice
- 每个新 Service 方法必须配单元测试
## 禁止
- 不引入未在 pom/package 中声明的依赖；不硬编码密钥与连接串
- 不自动删除/重命名既有文件；不改与当前任务无关的代码
## 输出
- 按文件分块并标注路径；先给计划，确认后再写实现
```

## 八、把 AI 协作沉淀进知识库

- **Prompt 库笔记**：按"解释/生成/调试/重构/测试/评审"六类存验证过的模板，用 `[[]]` 关联具体技术点
- **踩坑笔记**：每个被 AI 一起解决的难题记录"现象→根因→验证→修复→同类预防"，进入 `knowledge-review-spaced`
- **概念笔记**：AI 讲通的概念按 `tech-concept-deep-dive` 三位一体结构落库，关键结论补官方出处
- **复盘指标**：每周统计"一次命中率、AI 代码返工率、哪类问题 AI 最易错"，持续优化你的提问与规则文件

> 目标不是"更会用 AI"，而是"借 AI 更快地成为能独立交付、且能判断 AI 对错的工程师"。
