# 功能完整性检查清单（Content Completeness Checklist）

> 本文件按项目类型列出"标配功能清单"。Skill 在第二步规划时必须对照本清单确认产物覆盖度，在第三步生成时必须同步生成周边功能，在第六步自检时必须逐项验证。
>
> **核心理念**：一个完整的产品 = 核心功能 + 周边标配功能。只做核心功能（如社交平台只做"发图+点赞"）是不完整的，必须自动补充收藏、搜索、通知、互动等周边功能。

---

## 一、软件/技术类项目

### 1.1 社交/内容平台（如宠物社交、小红书、微博类）

**核心功能（必须有）**：
- 用户体系：注册/登录/个人资料编辑
- 内容发布：图文/视频发布、多图上传
- 信息流：时间线/推荐流、分页加载
- 互动：点赞、评论

**周边标配功能（必须同步生成，不能遗漏）**：
- **收藏/书签**：内容收藏、我的收藏列表、收藏状态显示
- **搜索**：内容搜索（按关键词）、用户搜索、搜索历史/热门搜索
- **通知**：点赞通知、评论通知、关注通知、通知列表页、未读角标
- **评论增强**：评论点赞、评论回复（楼中楼）、评论删除
- **个人主页**：我的发布、我的收藏、统计信息（获赞数/粉丝数/关注数）、宠物/标签管理入口
- **关注体系**：关注/取消关注、粉丝列表、关注列表、关注状态显示
- **下拉刷新/加载更多**：所有列表页必须支持
- **图片预览**：点击图片放大查看、左右滑动切换

**进阶功能（可选，按项目规模决定）**：
- 私信/实时聊天（WebSocket）
- 推荐算法（个性化推荐/热门内容）
- 话题/标签体系
- 举报/屏蔽
- 内容审核

### 1.2 电商/购物平台

**核心功能**：商品展示、商品详情、购物车、下单

**周边标配功能**：
- 搜索：商品搜索、筛选、排序
- 用户中心：订单列表、收货地址管理、收藏商品
- 评价：商品评价、评分、晒图
- 通知：订单状态通知、促销通知
- 分类：商品分类导航
- 购物车：数量修改、删除、选中结算

### 1.3 工具/效率类应用

**核心功能**：核心工具功能（如笔记、待办、计算器）

**周边标配功能**：
- 数据管理：列表、详情、编辑、删除
- 搜索/筛选：内容搜索、分类筛选
- 分类/标签：内容分类、标签管理
- 导出/分享：数据导出、分享功能
- 本地存储/云同步：数据持久化
- 设置：偏好设置、主题切换

### 1.4 管理后台/数据系统

**核心功能**：数据展示、核心业务操作

**周边标配功能**：
- 登录/权限：角色权限、操作日志
- 列表页：搜索、筛选、排序、分页、批量操作
- 表单页：新增/编辑表单、表单验证
- 详情页：数据详情、关联数据展示
- 数据导出：Excel/CSV 导出
- 仪表盘：数据统计、图表展示

## 八、完整性检查执行规则

### 8.1 第二步（规划阶段）执行规则

1. 确定项目类型后，立即查阅本文件对应类型的"标配功能清单"
2. 在 WBS（工作分解结构）中列出所有核心功能和周边标配功能
3. 标注每个功能的优先级（P0=必须有 / P1=应该有 / P2=可以有）
4. 对于不适用的功能，明确说明"本项目不包含 XX，因为 XX"
5. **禁止**：只列核心功能，忽略周边标配功能

### 8.2 第三步（生成阶段）执行规则

1. 生成核心功能代码时，**同步生成**周边标配功能
2. 周边功能不是"后续迭代"，而是"首次交付就包含"
3. 每个周边功能必须完整实现（后端 API + 前端页面 + 数据模型），不允许"留空"或"TODO"
4. 新增功能必须同步更新 README 和指导文档

### 8.3 第六步（自检阶段）执行规则

1. 对照本文件的标配功能清单，逐项检查是否已实现
2. 未实现的功能必须说明原因（不适用 / 超出范围 / 用户明确排除）
3. **功能完整性反向检查**：列出所有已实现的 API 端点，确认每个都有前端入口或文档说明
4. 检查"核心功能有但周边功能缺失"的情况（如社交平台有发图但没收藏/搜索/通知）

### 8.4 优先级判定标准

- **P0（必须有）**：没有这个功能，产品无法正常使用或核心体验严重缺失
  - 例：社交平台的注册/登录、发布、信息流
- **P1（应该有）**：没有这个功能，产品能用但不完整，用户体验明显下降
  - 例：社交平台的收藏、搜索、通知、评论点赞
- **P2（可以有）**：有更好，没有也不影响基本使用
  - 例：社交平台的私信、推荐算法、话题体系

**默认规则**：P0 和 P1 必须在首次交付中实现；P2 可标注为"后续扩展方向"。
