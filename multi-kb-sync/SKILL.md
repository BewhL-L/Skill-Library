# 多知识库同步与联动

> 管理多个 Obsidian 知识库之间的**标签、模板、样式、配置**同步，确保跨知识库一致性，解决"多个知识库风格不统一、标签混乱、无法联动"的问题。

---

## 核心原则

1. **全局标准优先**：全局标签集、模板、样式为权威标准，各知识库必须对齐
2. **增量同步**：只同步变更的部分，不覆盖各知识库的本地自定义内容
3. **冲突可追溯**：同步前检测冲突，冲突处理有记录，可回滚
4. **本地扩展允许**：各知识库可在全局标准基础上扩展，但不得修改核心字段和全局标签
5. **自动化优先**：同步操作尽量自动化，减少人工操作，降低出错概率

---

## 同步范围

| 同步项 | 说明 | 同步方式 | 冲突处理 |
|--------|------|---------|---------|
| 全局标签集 | 一级/二级/三级标签定义 | 全量覆盖（以全局为准） | 同名不同义以全局为准 |
| 笔记模板 | Frontmatter、五段式结构 | 全量覆盖 | 以全局模板为准 |
| CSS 样式 | callout、代码块、表格样式 | 全量覆盖 | 以全局样式为准 |
| Dataview 查询 | 常用查询脚本 | 增量同步 | 同名查询以全局为准 |
| Templater 脚本 | 模板脚本 | 增量同步 | 同名脚本以全局为准 |
| 快捷键配置 | 核心快捷键 | 全量覆盖 | 以全局配置为准 |
| 本地配置 | 各库特有配置 | 不同步 | 保留本地自定义 |

---

## 全局标签集标准概览

> 完整的全局标签集（一级/二级/三级标签定义）、同步操作规范、标签冲突处理规则详见 [references/sync-reference.md](references/sync-reference.md)，执行同步时按标签集标准和冲突规则执行。

**一级标签（技术领域）**：`#java`、`#frontend`、`#python`、`#ai-engineering`、`#database`、`#devops`、`#algorithm`、`#system-design`、`#soft-skills`

**二级标签（技术细分）**：如 `#java/jvm`、`#frontend/vue3`、`#ai/rag`、`#database/mysql` 等

**三级标签（状态/类型）**：如 `#status/learning`、`#type/concept`、`#priority/high` 等

---

## 使用示例

**输入**："我有 3 个 Obsidian 知识库（Java后端、前端、AI工程），标签体系不统一，帮我同步全局标签集并生成同步报告"

**输出**：
- 全局标签集标准（一级 9 个技术领域 + 二级技术细分 + 三级状态/类型）
- 扫描结果：3 个知识库的当前标签统计（每个库有多少标签、重复/冲突标签）
- 同步计划：新增标签 N 个、更新标签 N 个、删除废弃标签 N 个、冲突标签 N 个
- 冲突处理表（冲突项、各库值、处理方式、结果）
- 执行同步（备份→标签同步→模板同步→样式同步→配置同步）
- 同步报告（同步内容概览、各库同步详情、未同步项、质量检查结果）
- 跨库引用修复（断链检测和修复）
- 下次同步建议（时间、重点内容、遗留问题）
- 与 `[[Obsidian多库管理]]` `[[标签体系]]` 等知识库笔记双向链接

## 工作流程

### 场景一：全量同步

1. **扫描**：扫描所有知识库的当前状态（标签、模板、样式、配置）
2. **对比**：与全局标准对比，识别差异（新增、修改、删除、冲突）
3. **冲突检测**：
   - 同名不同义的标签
   - 模板字段不一致
   - 样式冲突
   - 配置差异
4. **生成同步计划**：
   - 列出所有变更项
   - 标注冲突项和处理方式
   - 预估同步时间
5. **执行同步**：
   - 先备份各知识库当前状态
   - 按计划执行同步（标签→模板→样式→配置）
   - 每步同步后验证
6. **生成同步报告**：同步内容、变更数、冲突处理、未同步项、质量检查结果

### 场景二：增量同步（单项同步）

1. 确认要同步的项（如"只同步标签"、"只同步 CSS 样式"）
2. 扫描该项在各知识库的状态
3. 与全局标准对比，识别差异
4. 检测冲突
5. 执行同步（备份→同步→验证）
6. 生成简要同步报告

### 场景三：新增全局标签

1. 确认新标签的名称、层级、定义、适用范围
2. 在全局标签集中登记
3. 同步到所有知识库
4. 检查是否有笔记需要添加新标签
5. 生成标签新增报告

### 场景四：跨知识库引用修复

1. 扫描所有知识库中的 `[[]]` 双链
2. 识别指向其他知识库的引用（跨库引用）
3. 检查目标笔记是否存在
4. 修复断链（目标不存在的引用）
5. 统一跨库引用格式
6. 生成引用修复报告

## 同步报告模板概览

> 完整的同步报告模板（含同步内容概览、各知识库详情、冲突处理、未同步项、质量检查、下次建议）详见 [references/sync-reference.md](references/sync-reference.md)。

报告包含：同步时间、同步范围、同步类型、同步内容概览表、各知识库同步详情、冲突处理表、未同步项（需人工确认）、同步质量检查清单、下次同步建议。

---

## 输出规范

1. 同步报告包含同步时间、范围、类型、内容概览、各库详情、冲突处理、未同步项、质量检查
2. 全局标签集有明确的层级（一级/二级/三级）和定义，无重复或冲突标签
3. 冲突处理有记录（冲突项、各库值、处理方式、结果），可追溯
4. 同步操作有备份（同步前备份各库当前状态），可回滚
5. 未同步项标注原因（需人工确认/不支持/冲突未解决）
6. 跨库引用格式统一，无断链（目标笔记不存在的引用已修复）
7. 同步后各知识库可正常打开（无配置错误、无样式冲突）
8. 标签命名规范统一（小写字母、连字符分隔、不超过 3 级）
9. 同步计划有明确的执行步骤和验证点
10. 下次同步建议具体（时间、重点内容、遗留问题）

## 质量检查清单

- [ ] 所有知识库标签集与全局标准一致
- [ ] 所有知识库模板与全局标准一致
- [ ] 所有知识库核心样式与全局标准一致
- [ ] 所有知识库核心配置与全局标准一致
- [ ] 无未处理的冲突
- [ ] 同步前已备份各知识库
- [ ] 同步后各知识库可正常打开
- [ ] 跨库引用无断链
- [ ] 同步报告已生成并保存

## 与其他 Skill 的协作

- **与 `obsidian-knowledge-base-creator` 协作**：新建知识库时，用本 skill 同步全局标准到新知识库
- **与 `note-quality-evaluator` 协作**：同步后对所有知识库执行批量质量评估
- **与 `knowledge-review-spaced` 协作**：同步标签后，复习计划可跨知识库统一管理
- **与 `learning-path-planner` 协作**：学习路线中的笔记可跨知识库引用和联动
- **与 `cheatsheet-generator` 协作**：全局标签集、同步操作整理成速查表
