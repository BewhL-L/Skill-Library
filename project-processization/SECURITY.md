# 安全策略

## 敏感信息处理

- `scan_project_facts.py` 扫描 `.env*` 时**只提取键名，不读取键值**，从工具层面避免
  API Key、密码、token 进入报告。
- 产出的学习指南中，示例密钥必须使用占位符（如 `sk-xxxx`），禁止粘贴真实凭据。
- 不要把含生产数据、真实用户信息的内容直接提交或贴给外部模型。

## 报告安全问题

若发现可能泄露凭据、执行非预期文件操作或其它安全问题，请**不要**在公开 issue 中披露细节，
通过私有方式联系维护者，并在报告中包含：

- 问题描述与影响范围；
- 复现步骤与最小样例；
- 建议的修复方式。

## 脚本行为边界

- 扫描与校验脚本默认**只读**项目文件。
- 仅 `make_toc.py --write` 会写回，且会在同目录生成 `.bak` 备份。
- 脚本不发起网络请求、不执行项目代码，仅做静态解析。

## 依赖安全

- 运行时零第三方依赖，攻击面最小。
- 开发依赖（pytest/ruff）建议定期升级：`pip install -U -e ".[dev]"`。
