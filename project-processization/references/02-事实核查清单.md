## 1. 代码规模与分层行数

- 命令：`scan_project_facts.py --path 项目根 --group-depth 2`
- 读取：`code.python` / `code.frontend`、`python_by_topdir`（app 与 tests 分行）。
- 口径：物理行数（空行计入）；排除 `venv/.venv/node_modules/__pycache__/dist/build/.git`。
- 坑：不要用"大概多少行"；不要混用 `Get-Content` 与其它脚本的结果，同一文档只用一把尺子。

## 2. 测试文件与用例数

- 扫描器自动统计：`tests.files`（测试文件数）、`tests.functions`（用例总数）、
  `per_file`（每个测试文件的用例数，Python 用 `def test_`，JS/TS 用 `test(`/`it(`）。
- 人工核对：`grep -rn "def test_" backend/tests` 或编辑器全局搜索 `def test_`。
- 坑：README 常写"47 个"但实际更多；务必逐文件数并让总数 = 各文件之和。
- **口径必须写清**：扫描器数的是 `def test_`（或 `test(`/`it(`）**定义数**。若项目用了
  `@pytest.mark.parametrize`，pytest 实际收集（`pytest --collect-only -q`）会按参数组合展开，
  数量大于定义数。指南里写"XX 个用例"时要标明是"测试函数数"还是"收集用例数"，二者别混用；
  同一文档统一用一种口径并注明。

## 3. 组件目录与业务文件数

- 命令：`--components "backend/app/routers,backend/app/models,backend/app/schemas,..."`
- 扫描器已自动排除 `__init__.py`，`file_count` 即业务组件数；`init_files` 是包标记数。
- 坑：路由数 = 业务 router 文件数（不含 `__init__.py`）；引用时名称与文件名对应。

## 4. 前端页面与组件

- 页面：统计 `src/views/`（或 `pages/`）下 `.vue` 文件数，区分"业务页 + Layout/NotFound"。
- 组件：统计 `src/components/`；路由：看 `src/router`；状态：`src/stores`。
- 坑：`.vue` 与 `.ts` 都要算；入口 `main.ts`、`App.vue` 不要误算为业务页面。

## 5. Docker 服务与端口

- 扫描器用轻量正则从 `docker-compose*.yml` 提取顶层服务名。
- 人工核对：读 `docker-compose.yml` 的 `services:`，记录每个服务的**容器名**（有 `container_name`
  就用它；没有则由 Compose 生成 `<项目名>-<服务名>-<序号>`）、端口映射**连同绑定地址**、依赖、健康检查；
  区分"数据库等基础服务"与"应用服务"。
- 坑 1：有的服务（如 celery-worker）不映射端口，别漏；`depends_on` 不等于"就绪"——
  `condition: service_healthy` 要求被依赖服务**确实配了 healthcheck**，否则启动即报
  `container xxx has no healthcheck configured`。
- 坑 2：端口写 `"127.0.0.1:5432:5432"` 表示仅宿主可访问，写 `"5432:5432"` 是对全网卡暴露。
  文档里只写"端口 5432"会误导成"局域网能连"，必须带访问范围。
- 坑 3：bind mount 的源路径不存在时 Docker 会**静默建空目录**——`backend/.env` 会变成目录
  （`env_file` 报 `is a directory`），uploads 会变成空目录（表现为"上传的文件消失"且无报错）。
  核查启动方式时要检查路径**类型**，不能只看"容器起来了"。

## 6. 环境变量与密钥脱敏

- 扫描器只列 `.env*` 的**键名**，不输出值。
- 人工核对：列出 `config.py`/`settings.py` 实际读取的键、默认值；区分"必填/可选"。
- 铁律：文档中**绝不**出现真实 API Key、密码、token；示例用 `sk-xxxx` 或占位。

## 7. 依赖清单

- 后端：`requirements*.txt`（扫描器去版本号给包名）；前端：`package.json` 的 dependencies/devDependencies。
- 核对：依赖要能在代码里找到对应 import；写"用了什么技术栈"时按真实依赖归类。
- 坑：`requirements.txt` 里被注释/可选的依赖不要当作生产必需。

## 8. 评测数据（golden QA）

扫描器不解析业务数据，必须人工核对：

- 打开评测数据文件（如 `evaluation/data/golden_qa.json`）：
  - 顶层结构（`version/description/fields_guide/cases`）。
  - 用例条数：数 `cases` 数组长度。
  - 每条字段：如 `id/kb_id/category/question/reference_answer/must_contain_keywords/expected_document_names`。
  - 分类数：对 `category` 去重计数。
- 坑：文档里"条数/字段名/分类数"三处都要与 JSON 一致；`kb_id` 可能写死，要说明。

## 9. 配置常量与开关

- 打开 `config.py`/`settings.py`，记录：检索模式、`CHUNK_SIZE`、`CHUNK_OVERLAP`、
  父子切片大小、`TOP_K`、`RRF_K`、`RERANK_TOP_N`、各功能开关（Rerank/HyDE/缓存/LLM 裁判…）。
- 文档里写"第 X 个开关"时，开关名必须与代码字段名逐字一致。
- 坑：`.env` 与 `config.py` 默认值可能不同，以"实际生效链路"为准（Docker 走环境变量）。

## 10. 脚本 / CLI 真实参数

- 看 argparse/click：搜索 `add_argument`、`@click.option`，或直接跑 `python xxx.py --help`。
- 记录：位置参数、可选参数、默认值、报告输出位置（如 `eval_reports/` 带时间戳）。
- 坑：文档最常漏写 `--kb-id`、`--no-judge` 这类真实存在且很实用的参数。

## 11. 接口（路由）清单

- 数每个 router 文件里的 `@router.get/post/...` 装饰器，得到接口规模。
- 记录鉴权方式（如 JWT Bearer）、SSE 流式接口、后台任务接口。
- 坑：Swagger `/docs` 是核对接口最快的方式；在线测需先登录拿 token 再 Authorize。

## 12. 文档与素材资产

- 列出 `docs/`、开发指导目录、架构图（.svg/.png）、博客/面试素材等，文件名与路径写准确。
- 指南"文档导航"一章引用的每个文件都必须真实存在。
